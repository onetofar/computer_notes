大模型部署与推理引擎方向的笔记。当前两条线:**vLLM(原理与并发吞吐)** 和 **Windows 原生单卡部署(实际在跑的那套)**。

这一系列解决的是同一个问题：**模型权重已经加载好了，GPU 也够快，怎么让这一张卡在单位时间内在给定帧率与吞吐之间取得最好的平衡**。

vLLM 是这条线上最经典的一套工程方案——它的四个核心机制（PagedAttention / 连续批处理 / 前缀缓存 / 量化）几乎都能在操作系统里找到同构的原型：分页内存管理、时间片轮转、缓存复用、数值精度。这不是巧合——推理引擎要解决的问题，本质上就是**资源分配问题**，而操作系统是这个问题二十年来最好的答案集。

> 后续 4-1 / 4-2 记录的是**方向反转**:vLLM 优化的是多请求并发,而单人本机场景的正确解是"让更大的模型全上卡"。同一个 12G 卡,3-1 判了 14B 死刑,4-1 把它救回来了——差别全在桌面显存、KV 精度、并发假设三个旋钮。
