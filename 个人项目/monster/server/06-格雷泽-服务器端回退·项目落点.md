## 本项目落点

| 教材结论 | 落到哪 | 怎么落 |
|---|---|---|
| 单快照回退 | **协议 `C2S_HitReport` 增补 `snapshot_tick:u32 + interp_t:u16`** | 7B → 13B。事件量级，带宽影响可忽略 |
| 只回退远端实体 | `Boss` 结构加 `pose_history` | Boss 每 tick 一份，保留最近 200ms |
| 超出窗口降级 | §11.2 校验表第一行 | 超出保留窗口 → 按当前位姿算 |
| 不做完整回滚重放 | 列在升级路线 | PvE 共斗不需要精确复现，完整回滚成本高收益低 |

**为什么放在 M5 而不是 M6**：不做**不是崩溃**，是"打偏时服务器不认"，
玩家体感是**手感变差且极难定位**。越晚做，积累的"这游戏手感不好"的印象越难归因。

**决策依据的四问**（写决策记录 D12 时用）：

1. 选了什么：**命中包带插值进度，服务器单快照回退**。
2. 放弃了什么：**用服务器当前状态校验**（最省事）、**完整时间回滚重放**（最贵）。
3. 为什么不选前者：客户端看到的是插值画面，差 ½RTT，转向时必丢合法命中。
4. 什么时候失效：PVP 或需要精确命中复现时 → 升级到完整回滚重放。

#### 服务器要保存什么（§8.3 增补节的最小实现）

只有 **"最近 N tick 的 Boss 位姿"**——每 tick 一份 `BossNet`(33B) × 4 = 132 B。
**不是整个世界的历史。** 因为需要回退的只有"我看见的 Boss 长什么样"，
而那画面本来就是两个快照插值出来的。

窗口取 **8 tick**（`技术参考.md` 只说"200ms"）。这个数字有来历，写在 `game_config.h` 里是**算式**
（4 + 2 + 2：保留窗口 + 上/下限各 2），不是拍的。

#### ★ 怎么证明它真的用了回退，而不是当前位姿（K7 交付里最硬的一条验证）

```
探针：上报旧 tick=244（当时 Boss 朝 Down），当前 Boss 朝 Up，打 Leg
      （Leg 只在 Down 暴露）→ hp 掉了
```
**按当前位姿判这条必然被丢，而且丢得完全正确。** 它落地了 ⇒ 判定用的是回退位姿。

单测另有正反对照：同腿同伤 120，**只改 `snapshot_tick`** →
(a) 旧帧收下、(b) 当前帧丢弃、(c) 同帧 `interp_t=0` 取旧端点收下。

**变异测试揪出的真 bug**：把保留窗口从 8 改成 1 tick，**代码在、结构在、测试全过**，
而延迟补偿**恒定走超窗分支**、实际一点没生效。
这正是 §8.3 描述的症状——所以"窗口 8"必须被**变异测试**守着，靠断言守不住。

#### ★ 一次被自证逼出来的"绿灯骗人"（K8）

`lo | (hi << 8)` 改成 `(hi << 8) | lo` 冒充大端 → **全套测试全绿**。
**位或可交换，这两个表达式完全一样**——我的"变异"是个空操作。
更要命的是：小数值（`msg=1`）和回文值（`0x0102`）对字节序**天然全盲**，
所以"用小值做往返测试"根本测不出端序。
**修法**：补**金标准字节测试**（直接钉死线上字节，不依赖任何往返）。

⇒ 这条值得单独立规矩：**往返测试测不出编码错误，两端都错时它照样绿。**
**凡是要上线的字节格式，必须有一个对着规格写的金标准向量。**
