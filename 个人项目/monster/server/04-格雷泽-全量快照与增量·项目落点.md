### 为什么第 1 条要钉"组成部分"而不是钉 98

`tests/test_smoke.cpp:97-98` 记着原因：**单钉 98 一个数，
"BossNet 从 33 长到 40、忘了回头改 98"会完全隐形**。

所以现在钉的是三个组成部分（`BossNet` / `PlayerNet` / 帧头）的宽度，98 是它们的和。
任何一段变宽，总和断言当场红。

### 断线重连：第 2 条推导的直接结果

`src/session/session_mgr.cpp:381-390`，`TickWorld` 的**第一步**：

```cpp
for (const net::ConnId conn : needs_snapshot_) SendFullSnapshot(conn, tick);
```

**顺序是硬要求**：必须在常规快照广播**之前**。重连的人不该等下一个 10Hz 节拍
（最多 100ms 黑屏），而 `技术参考.md` §10.3 的原话是"立刻有真相"。
放到后面就是"这局刚好卡了一下"，而这种 bug 只在弱网下偶发，极难复现。

`SendFullSnapshot` 里 `if (bytes.empty()) return;`（`:377`）——
房间已销毁时**没有真相可发**，发一份空的比不发更糟（客户端会把它当合法空快照）。
