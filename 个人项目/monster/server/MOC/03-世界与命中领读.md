# 03 · 世界与命中领读（`src/world/` `src/sim/`）

> **怎么读**:[[00-项目领读]] L5.4/L5.6 是地图。本篇讲三个跨文件的因果链——
> **结算顺序为什么写死**、**回退为什么只需要 8 tick 的 Boss 位姿**、
> **四道校验的处置为什么分三档**。
> 📖 教材结合方向与 [[01-网络层领读|01]]/[[02-会话与房间领读|02]] 相同:项目 → 解读 → 教材,单向。

## 0 · 模块形状:纯逻辑与它的唯一消费者

```
sim/    纯逻辑:boss_brain(AI)· boss_aggro(仇恨)· boss_anatomy(部位)· boss_rewind(回退)
        ——无 IO、无时钟、无全局随机;include 只有 proto 类型定义(实测 0 违规)
world/  结算编排:把 sim 装进 tick 顺序,产出「这一拍发生了什么」与「快照长什么样」
```

**分层**:world 认识 sim,不认识 session/net。它只**产出**事实,谁来广播、何时广播由 session 层决定(`world.h:9-11`)。滥用闸的判定在世界里做,但**读它、据此断连的是 session**——世界不认识连接(`world.h:162-164`)。

> 📖 [[第6章 网络拓扑和游戏案例|格雷泽第6章 §6.2.1]]:代码三层分叉(共享/Server/Client)的**服务器内部版**——「结算」与「投递」的分离是同一条纪律的纵深。

## 1 · 承重设计一:结算顺序写死,「别把 5 提到 2 前面」

`World::Tick` 六步(`world.h:166-172`,顺序**不给调用方选**):

```
1 采集输入(无输入沿用上帧 move_dir) → 2 玩家积分+clamp → 3/4 仇恨+Boss AI
→ 5 清算 HitReport 队列 → 6 胜负判定 → 记一帧位姿(最后)
```

**为什么写死**(§12 原话):「别把 5 提到 2 前面——**会出现用上 tick 位置裁决本 tick 命中**」。反过来读:5 放在 2/3/4 之后,保证校验用的 Boss 位姿是**本 tick 结算完的**;而回退键 `(snapshot_tick, interp_t)` 指向的是**过去**——「本 tick 的现在」与「客户端看见的过去」互不污染(`world.cpp:296-300`)。

**位姿采样也锁顺序**:`RecordPose(tick_)` 放在 Tick 的**最后**(`world.cpp:347-351`)——「这一 tick **结算完**的权威位姿」才是回退样本的语义;提前一帧记,回退就会查到还没走完这一帧的 Boss。

> 📖 [[第6章 网络拓扑和游戏案例|格雷泽第6章 §6.3.2]]:锁步的「命令第 x 轮产生第 x+2 轮执行」与本节的「结算顺序写死」是同一个思想的两面——**时序即语义,时序不许参数化**。

**改动地图**:把第 5 步提到第 2 步前 = 用过时位姿裁决;RecordPose 挪进第 3 步 = 回退查到半帧 Boss;把 Tick 拆成可自由组合的几个函数 = 顺序写死失效(那才是真正的回归)。

## 2 · 承重设计二:单快照回退——为什么 8 tick 位姿就够了

`boss_rewind.h:4-10` 是全模块最重要的一段推理:

> 需要回退的只有「**我看见的 Boss 长什么样**」——那个画面本来就是两个快照**插值**出来的,所以客户端报出 `(snapshot_tick, interp_t)`,服务器就能**精确复现**;玩家自己**不回退**(位置由服务器按输入积分,服务器说了算)。
> 于是服务器要保存的只有「最近 N tick 的 Boss 位姿」,**不是整个世界的历史**。

对照教材的四要件([[第8章 改进的延迟处理|第8章 §8.4]]):「服务器存最近几帧位姿」这一条,在本项目里因为**快照插值的确定性**而进一步收缩——格雷泽要存「所有相关对象」的位姿,本项目只存 Boss(玩家位置不参与命中校验的回退),8 tick × 132 B 就是全部状态。

**回退的实现是纯函数**(约束 2 的 C++ 侧对偶):输入「位姿样本 + 两个客户端字段」→ 输出「开火那一刻的位姿」;不读时钟、不碰网络、不持状态——**「回退算得对不对」可以在单测里逐字段验,不必先起一个服务器**(test_hit_report.cpp 就是这么做的)。

> 📖 [[第8章 改进的延迟处理|第8章 §8.4]] 的最小实现判据在此逐条对位:`snapshot_tick_A/B + interp_t` → 本项目的 `snapshot_tick + interp_t`(插值跨度由配置给出,省一个字段);服务器环形缓冲 → `pose_history_`(deque,升序,尾部最新)。

**改动地图**:让回退也覆盖玩家位置 = 状态量爆炸且与「服务器说了算」冲突;把纯函数改成读成员 = 单测必须起服务器;窗口从 deque 换 vector「为了接口好看」= 改规格里的类型(模板因此对容器无感,`boss_rewind.h:54-59`)。

## 3 · 承重设计三:朝向最近邻插值(`boss_rewind.h:68-77`)

位置线性插值,**朝向用最近邻**(`t < 0.5` 取旧端点,否则取新端点)。

**为什么**:四向朝向没有中间态——线性插出一个「介于上和下之间」的朝向是**查表越界的发明创造**;最近邻还让「哪一半算旧」成为一个**可以写进断言的具体数**,而不是「差不多」。

**改动地图**:把 facing 也线性插值 = 枚举越界 UB 或静默错值;改成「按角度插再量化」= 引入浮点,破坏纯逻辑的可复现性。

## 4 · 承重设计四:超窗不丢命中(`boss_rewind.h:39-45`)

`RewindStatus::kOutOfWindow` 时**按当前位姿算,不丢弃这条命中**——§11.2 表格第一行的失败处理。

**为什么**:超窗是正常网络行为(极端延迟下客户端报的 tick 早被窗口淘汰),丢掉它 = 「明明砍中了,服务器说没打中」,大部分时候对、偶发丢命中,极难定位。**回退是尽力而为的补偿,不是判决的前置条件**——这与 8 tick 窗口(400ms)覆盖 ½RTT+IP 的设计互为表里:窗口够大,超窗才是真的异常。

> 📖 [[第8章 改进的延迟处理|第8章 §8.4]] 的代价侧:回退把公平给射击者、代价记在被击中者账上;超窗兜底则是把「延迟大到回退不了」的情形也收进同一套裁决,不产生第二种语义。

**改动地图**:超窗改丢弃 = 偶发丢命中且无规律;窗口调小 = 超窗率上升(但语义不变——这是该设计的好处)。

## 5 · 承重设计五:具名裁决 HitVerdict(`world.h:52-81`)

§11.2 的「静默丢弃」在协议层**看不见**(不回包、不扣血就是「没发生」)——对端到端验收是灾难:「是服务器没实现,还是这条命中真的不合法?」两者在终端里一模一样。

解法:每一道校验产出一个**具名结果**(`kAccepted / kAcceptedNoRewind / kDroppedBadPart / kDroppedBroken / kDroppedDefeated / kDroppedNotExposed / kDroppedNoDamage / kDroppedDamageCap / kDroppedRate / kDroppedIgnored / kDroppedRunOver`),`last_hit_results_` 每 tick 清空重建。**丢弃仍然丢弃**(客户端行为零变化),变的只是**服务器自己看得见**——日志、单测逐条断言都有观测口。

> 📖 [[第10章 安全性|格雷泽第10章 §10.2]]:输入验证的「拒绝但不踢」需要一个前提——**拒绝这件事本身可观测**。无名丢弃让「正常预测落空」与「攻击探测」在服务器眼里同形,滥用闸就无从谈起。

**改动地图**:合并裁决枚举 = 验收退回「终端里一模一样」;把 results 改成累计统计 = 「这一拍发生了什么」的痕迹语义丢失。

## 6 · 承重设计六:四道校验,处置分三档（`world.cpp:354-414`)

| 道 | 校验 | 处置 | 计滥用? |
|---|---|---|---|
| ① | 回退还原(超窗按当前位姿) | 继续 | — |
| ② | part 越界 / Boss 已死 / 部位已破 / IsExposed(那时的 facing) | **静默丢弃** | ❌ |
| ③ | `damage <= 0` / `damage > cap(200)` | 丢弃 / 丢弃 | ❌ / **✅** |
| ④ | 频率(令牌桶 >4/s) | 丢弃 | **✅** |

**分档的判据是错误性质,不是错误位置**:

- **② 与 damage==0 是「正常网络行为」**——客户端预测落空、动画与判定差一帧、伤害没算出来,都会走到这里;把它当错误处理 = **正常玩家被踢**(原注:一个自己算漏了伤害的正常客户端会被自己的 bug 踢下线);
- **③ 超限与 ④ 超频是「只有攻击者才会持续产生」**——单次可能是误报,窗口内反复超限才是滥用(60s 内 10 次 → latch 断连,由 session 层执行)。

> 📖 [[第10章 安全性|格雷泽第10章 §10.2]]:验证的两类失败(无辜的乱序 vs 恶意的越界)处置必须分流——「拒绝但不踢」只适用于前者;[[第6章 网络拓扑和游戏案例|第6章 §6.3.2]] 的「StaticCreate 创建时验一次、ProcessCommand 执行时再验一次」在这里变成「解码时粗验、结算时细验」两段。

**改动地图**:把 ② 也计滥用 = 预测落空的正常玩家进断连名单;damage==0 并入超限 = 自伤 bug 的客户端被踢;滥用闸不 latch = 攻击者探到阈值边缘永久悬空。

## 7 · 承重设计七:令牌桶一拍一补(`world.cpp:302-310`)

频率闸的令牌补充**每 tick 一次**(按 `hit_rate_per_sec × dt`),不是每条报告一次。

**为什么**:「4/s」是**速率**口径——按报告补,一包里塞 64 条(帧队列深度上限)会全部通过,速率闸被单包击穿。一拍一补让「一拍内能用多少」有硬上界,与帧队列深度共同构成「无界增长的路不给」的双保险(输入缓冲同款:定长、满则丢最旧,`world.h:104-109`)。

> 📖 [[第7章 延迟、抖动和可靠性|格雷泽第7章 §7.3]]:包数经济学的防御侧——攻击者把字节拆小、把报告塞密,服务器用「每 tick 预算」把它压平。

**改动地图**:补充点挪到 HandleHitReport = 单包击穿;删 burst 上限 = 攒桶后爆发绕过速率。

## 8 · 承重设计八:latch 与清空副作用的耦合(`world.cpp:316-334`)

`BossDied` 只发一次的实现是 `death_event_sent_` latch——但它正确工作的前提是「**事件队列每 tick 被 `TakePendingEvents` 清空**」这个副作用。原注的警觉:

> 「不发第二次」依赖那个副作用——有人把清空删掉时,它会变成每 tick 一次 BossDied,症状只是「客户端反复播死亡演出」,**很难联想到这一行**。

**解读**:这是一个被明知的脆弱耦合,不是疏忽——真正的修复方向(事件带 id 去重)在「不新增协议」的红线下不划算,所以用注释把「炸点与症状的距离」写死,让排查的人能跳到这一行。

**改动地图**:删 TakePendingEvents 的清空 = BossDied 风暴;在 brain 的早退分支只改输出不改成员的约定被破坏 = 快照里的 Boss 状态与事件不一致。

## 9 · 承重设计九:present 与 online 是两个字段(`world.h:83-99`)

座位(`present`)与连接(`online`)**不是一回事**:§10.3 重连窗口里座位还在( present=true)但人走了(online=false)。**断线的人不许继续走**——事故记录:

> 一个残留的 `last_move` 会让幽灵玩家一路走进 aggro 圈把 Boss 拽走,症状是「新客户端一进来 Boss 已经在半路上了,而房里的玩家都站着没动」。

**解读**:这是 [[02-会话与房间领读|02]] §「座位保留」在世界层的镜像——保留的是**席位状态**,收走的是**活动权**。两个字段合成一个 bool,这两条规格就没有各自的承载。

> 📖 [[第6章 网络拓扑和游戏案例|格雷泽第6章 §6.2.3]]:ClientProxy 三重身份里「输入缓冲」在断线时的处置——本项目用 online 门控输入消费,等价物。

**改动地图**:断线只置 present=false = 座位丢失(重连回不来);只置 online=false 但允许 SampleInput = 幽灵玩家。

## 10 · 承重设计十:不可表达的错误状态(`world.h:127-135`)

`World()` 默认构造**即用 GameConfig 真值初始化**——「忘了 Setup 于是拿一个半初始化的世界跑」这种故障在本层**不可表达**。`Setup` 单独留着一个口子,只为单测注入参数(单测要的是「某组输入下的行为」,不是 GameConfig 的值)。

同款思路遍布:输入环形缓冲定长、HitReport 队列定长(满了丢最旧)、令牌桶上限 clamp——**让错误状态在类型与构造上无法成立**,而不是靠运行时检查兜。

> 📖 彭放《网络多人在线游戏开发实战教程》第5章「性能优化与对象池」的「FrameDecoder explicit 构造」与 [[02-会话与房间领读|02]] §2 是同一哲学的两处落地:**构造函数是最后一条防线,类型系统比纪律可靠**。
> （⚠️ 该章的教材笔记**尚未入库**,所以此处只作文字引用、不建 wikilink —— 免得留一条永远红的链。）

**改动地图**:把 GameConfig 真值改成留空等 Setup = 半初始化世界复活;给队列改动态增长 = 无界增长路重新打开。
