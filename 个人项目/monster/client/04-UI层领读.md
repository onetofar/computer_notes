# 04 · UI 层领读（`otf-game/scripts/ui/` + `scripts/audio/`）

> **怎么读**：这一层的承重墙**不是布局，是「同源纪律」**。
> 13 个文件里有 9 个的文件头都在讲同一件事：**显示的值不许自己算**。
> 布局代码反而是最容易出 bug 的地方，但它已经被收敛得比较干净了。

## 0 · 覆盖边界

| | |
|---|---|
| **本文覆盖** | `scripts/ui/` 全部 13 个 .gd（**3560 行**，`hud.gd` 一家 1138 行）+ `scripts/audio/sfx.gd` 全文 · 测试覆盖度逐文件核对 |
| **本文不覆盖** | view 层（[[03-view层领读]]）· 存档写入逻辑（在 autoload `Game` 里，见 [[05-联机与编排领读]]）· 各 UI 的 `.tscn`（**它们基本是空壳**，见 §2.1）· 实际渲染效果 |
| **一个重要的方法论警告** | 本项目测试用自定义 `check()` / `_check()`，**不出现 `assert` 关键字**。按 `assert` 计数会误判为「零断言」。UI 层恰恰是覆盖最厚的部分（`test_hud_status.gd` 单文件 **164 条**）。 |

## 1 · 三条文件头口径（`hud.gd:4-14`）

```
① HUD 只读不写：一个玩法数都不算
② 全程序化画：StyleBoxFlat + Label，.tscn 只是空壳
③ 鸭子类型：has_method 探测，实体没接上就退化成不显示
```

这三条不是风格偏好，是**阶段二的接口契约**：

| 口径 | 阶段二成立吗 |
|---|---|
| ① 只读 | ✅ 成立 —— 这些方法变成「读服务器广播」，**`hud.gd` 零改动**（**但有两处例外，见 §3**） |
| ② 程序化 | ✅ 与网络无关 |
| ③ 鸭子类型 | ✅ —— 也让 `test_hud.gd` 能用假实体直接单测 |

## 2 · 五条承重设计

### 2.1 全程序化建 UI，`.tscn` 只是空壳

`hud.gd:8-9`、`:138`；`ui_kit.gd:4-5`。

**为什么**：手写 `.tscn` 里的锚点/容器嵌套/主题覆盖要逐行核对，错了**只在运行时静默**（控件错位、底板压字）。代码搭则一眼看得完。

**改动地图**：新增 UI 组件 → 加 `.gd` + 在 `ui_kit.gd` 补共用件；**不要去改 `.tscn`**。

### 2.2 左下角「一摞面板」的位置**一次算完**

`hud.gd:174-202` `_layout_stack()` —— HP / TTK / 状态条 / Boss 状态条全部由它算，间距按 `2 × GameConfig.hud_panel_border` 留。

**上一轮的病**：三处各写一遍 `-MARGIN - 38 - ttk_gap - h` 的算式，而九宫格木框比声明矩形四边各外扩 15px —— 间距 2/8px、框 15px，于是**每一层的框横穿进下面一层**。

> 注释里写明「极难定位」：症状落在两个面板上（状态图标被切、HP 标题被划一道），**根因是同一个数**。

### 2.3 ★ 判据必须读「布局实际用的那个矩形」，不许测试自己重算

`hud.gd:1015-1045` `stack_rects()` · `status_icon_strip.gd:159-161` `plate_rects()` / `:223-228` `plate_pitch()`。

**都是只读出口，测试与摆层共用同一个数。**

**挡住什么**：测试自己拿 GameConfig 重算一遍 → 两处各算各的 → **判据成了摆设**，方向还是"测试说没压、屏幕上压了"这种最难查的。

> **通用判据：新增可数判据时，先加只读出口，再写测试。**

### 2.4 反馈必须上屏；**失败也上屏，理由原话照搬**

`inventory_panel.gd:11-14`、`:455-463`；`forge_panel.gd:366-368`；`storage_panel.gd:260-262`。

**做法**：`show_result(res)` 把提示与格子刷新绑在**同一份**返回值上。

**它挡住的第一版 bug**：写了 `refresh(Game.inventory())`，抓帧拍到同一屏"提示说满了"而"24 格全空、写着 0/24"。

> 项目口径：**判定可以滞后，表现不能撒谎。**（这条同时出现在 [[03-view层领读|03 view 层]] 的 §2.4）

### 2.5 时间必须是入参，不是引擎时钟

`hud.gd:591-595` `set_float_clock()` · `:641-654` `pump_floats(now_ms)` · `:1132-1137`。

**为什么**：合并窗口类断言在 headless 下钉不住，只能靠真的等 0.4 秒。

## 3 · HUD 显示的每一个关键值从哪来（阶段二风险评估表）

| 显示项 | 位置 | 来源 | 阶段二风险 |
|---|---|---|---|
| Boss 核心血量 | `hud.gd:735,740` | **实体只读口** | 低 |
| Boss 核心上限 | `hud.gd:736-739` | 实体口；**缺失时回落 `maxf(target,1.0)`** | ⚠️ 回落是本地兜底 |
| 部位当前血量（**分子**） | `hud.gd:748` | 实体 `part_hp(part)` | 低 |
| **部位血量上限（分母）** | `hud.gd:749` | ⚠️ **本地 `GameConfig.boss_part_hp`** | **高 —— 同一行两个数不同源** |
| 部位破坏 / 永久变红 | `hud.gd:745,755-759` | 实体口 + 一次性状态迁移 | 低 |
| 玩家血量 / 血条颜色 | `hud.gd:768,770,844-848` | 实体 `hp()/max_hp()` + **本地插值** | 中（插值纯显示） |
| 伤害/秒 | `hud.gd:803,819` | `player.melee_damage()` → `TtkLib.dps_of()` | 中 |
| **TTK 行** | `hud.gd:811-821`（`predict` 在 `:816`） | ⚠️ **整套击杀预测在本机跑** | **高** |
| 技能 CD / 状态图标 | `skill_bar.gd:106-172` / `status_icon_strip.gd:92-152` | `SkillComponent.state()` / `HealthComponent.active_statuses()`（**同源**） | 低 |
| Boss 状态条 | `hud.gd:521-527` | **恒为空**（Boss 无状态容器） | — |
| 飘字 | `hud.gd:579-611` | `status_ticked` → `FloatThrottle` 合并 | 低 |

> **结论：切服务器权威时只有两处必须重写** —— TTK/DPS 三行（`hud.gd:789-827`）与部位血量分母（`:749`）。其余全是「读实体 → 显示」。

### 3.1 `hud.gd:749` 是本文最该记住的一行

```gdscript
hp = int(_boss.part_hp(part))                    # 分子：来自实体（阶段二 = 服务器广播）
var mx := maxi(int(GameConfig.boss_part_hp.get(part, 1)), 1)   # 分母：来自本地配置
```

**同屏显示的两个数，一个走权威、一个走本地。** 阶段二若服务器改了部位血量上限，这里会显示成 `8000/3000` 而**不报任何错**。

## 4 · 三个「同源」纪律的实战

### 4.1 飘字节流有闸门，普攻没有

只对 DoT/回复做时间窗合并（`FloatThrottle`，`hud.gd:115-118`、`:575-588`、`:694-697`），普攻与技能伤害走 `spawn_damage_number`（`:667-676`，只有 6 行）。

- **为什么 DoT 要合并**：每 0.5s 一跳，逐 tick 飘字 = 糊屏
- **为什么普攻不能合并**：一次一击，合并掉反而读不出自己打了多少
- ⚠️ **闸门走帧而不是 0.1s 轮询**，否则同一秒内该合并的几跳会落在轮询点两侧漏合并

### 4.2 伤害数字是世界空间节点

`hud.gd:13-14`、`:667-676` → `damage_number.gd`（Node2D）。

**为什么不用 CanvasLayer 控件**：CanvasLayer 上的控件不属于世界，钉住得每帧自己换算，且相机一缩放就糊。

### 4.3 语义通道分离：红底 = 装不下，格数满**不算**

`inventory_panel.gd:221-224`、`:243-247`、`:268-276`。

| 语义 | 判据 | 表现 |
|---|---|---|
| 这批**装不装得下** | `is_hard_full()` | **红底** |
| 格数满 | `is_full()` | 不算 |
| 选中 | — | **边框加粗**，不占底色 |

**用错判据的后果**："红底却捡得到 / 冷蓝黑却被拒"—— 玩家无法预判下一次拾取，**规则等于不存在**。

### 4.4 空档必须显式可读

`boss_status_missing()`（`hud.gd:112-114`、`:516-520`、`:1062-1066`）返回 true，因为 Boss **还没有**状态容器（T9b 有意留的空档）。

> **挡住的是**："看起来是没状态" 与 "是没接上数据" 在画面上不可区分。将来容器建好，只要它提供 `active_statuses()`，本文件**零改动**可用。

## 5 · 像素字体与音频

### 5.1 字体两条铁律 + 中文回退链

`ui_fonts.gd:13-18`（关 AA / 关 hinting / 关亚像素 · 字号只用原生尺寸整数倍）· `:51-58`（CJK 走 `SystemFont` 按序回退）。

**为什么不把中文字体拷进仓库**：这批 opengameart 像素字体**零 CJK 字形**（逐个 TTF 渲染"龙"零出墨），而内置第三方中文字体是**开源授权坑**。

⚠️ **回退链的实际渲染效果是零自动验证的** —— 它只有在装了对应系统字体的机器上才有效果。

### 5.2 音频 = autoload + 8 路轮转池

`sfx.gd:4-8`（全局单点）· `:25-26`（8 路轮转）· `:44-46`：

```gdscript
p.volume_db = _linear_to_db(_sfx_volume) + volume_db
```

> **「台面值 + 本次偏移」**：直接赋 `volume_db` 会让该 player **永久停在 0dB**，滑块从此失效。单 player 则会互相打断。

**唯一与"退出"相关的资源纪律**：`sfx.gd:89-95` `_exit_tree()` 主动交还音频流 —— 避免退出时 `resources still in use at exit` 在回归日志里长得像真错误。

## 7 · `hud.gd` 该不该拆（评估结论）

先看构成：

| 段 | 行数 | 性质 |
|---|---|---|
| 布局与注释 | 174–371 + 410–461 ≈ **250 行** | 决策密集，大量「为什么这样写」 |
| **只读查询口** | 873–1137 ≈ **265 行（23%）** | **为测试与抓帧验收存在的 API，不属于任何功能模块** |
| 真值逻辑 | 731–827 ≈ 97 行（伤害数字只 6 行） | 少 |

**结论：拆 `_layout_stack()` 那一段收益更大，但 `:174-202` 必须留在主体。** 反过来，把 `873-1137` 拆出去**不会减少"上帝文件"的实际复杂度** —— 那部分本来就只是出口。

> 顺带一个事实：**HUD 里没有队伍/队友信息面板**。整个 HUD 只有玩家自己的血条、TTK、技能栏、状态条，加 Boss 血量与部位。

## 8 · 待拍板

1. **`hud.gd:749` 同屏不同源** —— 阶段二高风险项。要么现在就让 Boss 实体提供 `part_max_hp(part)`，要么在计划表里明写它是第 5 层的返工点。
2. **`forge_panel.gd` 列宽一半走配置一半写字面量**（12 处）—— 要么补进 GameConfig，要么明确声明这些列宽是本面板专属布局。
3. **默认音量三个文件各一份** —— 谁是家？
4. **`guild_hall.gd` 的断言缺口** —— 它做了最多排版取舍，却是覆盖最薄的。
5. **`ui_kit.gd` 的字面量** —— 共享层，影响全部面板，优先级应高于各面板。
