# 02 · 配置与数据层领读（`otf-game/scripts/config/` + `scripts/data/`）

> **怎么读**：这两层回答两个问题——**"这个数是多少"** 与 **"这个东西有什么"**。
> 它们的边界判据是一句话：**换一只怪要改的** → data/；**所有怪共调一次** → config/。
> 上一篇 [[01-sim层领读|01 sim 层]] 拿的是 GameConfig 的读法，这里补「这些值从哪来、哪些不能手改」。

## 1 · 三条承重设计

### 1.1 约束的载体必须「三件事齐做」——文件自己把这条钉在第 1 行

`game_config.gd:1-11` 开门第一句不是配置，是**自检**：

```
① 文件存在  ② 在 project.godot [autoload] 注册  ③ 业务代码真的在引用
```

**三件事缺一件，约束就是一张纸。** 这个项目已经付过一次学费：`_legacy/scripts_old/config/game_config.gd` 自称 autoload 却从未注册，四个原型脚本全在硬编码 —— 约束写了等于没写。

所以本文第一条判据：**改任何玩法数值只动 `game_config.gd`；新增参数也在这个文件加，别去 JSON 里开第二个门。**

### 1.2 config/ 与 data/ 的分界是一句话，不是「重要的参数放 config」

判据写在 `data/monster_def.gd:18-26`：

> **换一只怪要改的** → `<id>.json`；**所有怪共调一次** → GameConfig。

它挡住的具体失败是：把「受击闪白时长」「顿帧档」「bob 幅度」塞进每只怪的 JSON，于是「同调一次手感」要改 N 个文件，且**必然漏**。

同一条归属纪律在 `data/boss_catalog.gd:541-546`、`game_config.gd:670-675`、`:709-715` 又复述了三遍 —— 重复三次说明它被违反过。

### 1.3 data/ 的失败语义统一：**读不到一律报错，绝不静默兜底**

| 脚本 | 位置 | 具体 |
|---|---|---|
| `boss_catalog.gd` | `:19-24` | 未登记的 `boss_id` 一律 `ok:false`，**绝不退回龙** |
| `boss_catalog.gd` | `:58-77` | 面板记录/立绘/掉落预览逐条校验 |
| `skill_catalog.gd` | `:12-17` | 对 InputMap、对协议编号、对 status 引用各有一道校验 |
| `skill_catalog.gd` | `:224-295` | 非法条目**剔除并把原因留在 `errors()`**，不是丢弃 |

**为什么这么严**：症状是「面板写着『火种飞龙』进去发现是龙」「按了 Q 没反应」「图标挂在那儿血不掉」—— 而这些**一句日志都不打**。兜底比报错贵得多，因为兜底要等到玩家发现。

## 3 · 三个最容易踩的坑（都不是「忘了写」，是「写的时候没想到」）

### 3.1 受击区是**逐朝向实测生成物**，不是规则表

`game_config.gd:32-51` + 生成物头 `boss_zone_metrics.gd:1-17`。

哪个部位打不打得到，由 `boss_zone_metrics` 的**几何**决定；旧的 `exposed_parts` 规则表已被完全取代。

**为什么不能规则化**：这套是「一组固定形状整体旋转 90°」的思路 —— 但侧视图只画得出一只翅膀，正视图两只都摊开，**旋转出来的判定与画面对不上**。

> ⚠️ **换素材必须重跑生成器，这条没有任何自动提示。** 素材一换、生成物不重跑，受击区会整体压在别的地方。详见 CLAUDE.md 铁律 3。

**更危险的一点**：`zones_from_refs.py`（现役，读手勾场景）和 `measure_hurt_zones.py`（旧法，alpha 轮廓 Voronoi）**写同一个 OUT_GD**。我已经把 `game_config.gd:45` 从指向旧脚本改成了指向现役脚本（commit `7df3463`）—— 照旧注释跑会**静默覆盖手勾受击区**，无任何报错。

### 3.2 本体碰撞体是「四朝向轮廓掩膜的交集」，三种错法各对应一个已踩过的坑

`game_config.gd:52-61`。约束：**固定、无空气墙、一次算好永不换**。

| 错法 | 症状 |
|---|---|
| 手填宽了 | 玩家进不了攻击距离，**Boss 永远在走、行走动画无限循环** |
| 改回矩形 | 323 格里 114 格空气墙 |
| 改逐朝向轮廓 | 转身时把贴站的玩家包进去 |

### 3.3 停步/攻击距离是**方向性**的

`game_config.gd:112` 的 `boss_attack_gap` 是**沿目标方向的「体表伸出距离」之外的增量**，伸出距离由 `boss_ai` 沿本体轮廓投影算出。

固定半径对这条龙的后果：要么从背后永远够不着（推人永不攻击），要么正面隔空咬。

## 4 · 装备加成与跨语言参数（阶段二的关键接缝）

### 4.1 装备加成**另存**而不改写基础值

`game_config.gd:403-441`。`apply_server_config()`(`:420`) **覆盖式**写入 `equipment_bonus`，战斗与 HUD 必须读 `effective_melee_damage()`(`:433`) / `effective_max_hp()`(`:438`)，**不要读裸值**。

**为什么不能改写基础值**：会让「基础值/最终值」共用一个字段，换两次装备就漂 —— 与 §5.1 的 `boss_total_hp` 血案是同一个坑。

**阶段二怎么变**（B8 已改，`29f4ecc`）：`game.gd:178-201 _broadcast_loadout()` 按 `_carries_local_loadout()` 决定谁吃加成，不再向全组广播 —— 见 [[05-联机与编排领读|05 联机与编排]]。

### 4.2 两端都需要的阈值必须收进 GameConfig，并用跨语言向量锁住

`game_config.gd:119` 的 `boss_hit_dot_threshold = 0.35`。

**血案**：它曾是 `boss_ai.gd` 两处硬编码 `0.35`，而服务端 `boss_brain.h` 却是配置字段 —— **两端一个可调一个不可调，改一边必然分叉**。

判据：**「两端是否必须一致才能通信」** —— 是 → 进 GameConfig + 进 `config_parity.json`。

| 角色 | 文件 | 作用 |
|---|---|---|
| 真值表 | `resource/otf-resource/data/test_vectors/config_parity.json` | 三段 anatomy/brain/aggro，25 键 |
| 客户端守卫 | `otf-game/test/test_config_parity.gd` | 52 项回归里的一项 |
| 服务端守卫 | `otf-server/tests/test_config_parity.cpp` | ctest #18，现有 33 条跨语言 + 45 条「默认值 == 真值」 |
| 掉落向量 | `data/test_vectors/loot_roll.json` | 种子→输出 171 条，生成物 |

### 6.2 过期注释（5 处）

1. **`:143` 推导式算错。** 原文：「90/s ≈ 一次完整翻滚（0.3s 位移 + 0.4s 无敌）能抹掉约 38 点被动仇恨」。

   **实测**：`_dodging` 在 `skill_component.gd:78-79` 是**随 `_dash_left` 归零而清**的，即窗口 = `dash_time = 0.3s`。**无敌的 0.4s 不在断仇恨窗口内**（那是 `invuln_time`，另一件事）。所以 90 × 0.3 = **27 点**，不是 38。

   > 这是「注释里的**推导式**比结论危险」的又一例（判据见 §6.5）。结论「90/s」是对的，式子错了 —— 而式子正是拿来验算的那个。

2. **`:584 / :591 / :596` 三处引用不存在的文件** `test/_tmp_guild_size.gd`（实测 `MISSING`）。

3. **`:592` 的加总与常量对不上。** 注释「header 65 / bosses 307（= 小标题 18 + 间距 4 + 卡片 275）」，但常量是 `guild_header_h: int = 56`(`:600`)，且 18+4+275 = **297** 而非 307。

4. **同一段落里余量有三个数**：`:583` 「余 4」、`:631` 「只剩 23px 余量」、`:688` 「只剩 4px 余量」。哪个是当前值需要抓帧才能定论（临时脚本已不存在）。

5. **`:73` 比例注释无出处**：`player_hitbox_radius 105.0 ##（Boss×5/3 后同步放大）`，但 `test/test_zone_geometry.gd:87` 是**除以** `boss_scale` 用的，注释里的推导无法从本文件复核。

### 6.3 同一参数在两个地方各有一份（6 组）

| # | 两处 | 有机器锁吗 |
|---|---|---|
| 1 | `game_config.gd:548-550` ↔ `strings.gd:16-18` | ❌ 无（且值逐字相同） |

| 4 | `skill_catalog.gd` `FALLBACK_ICON_SIZE := 32` ↔ `status_catalog.gd` 同名常量 | ❌ 注释 `:28-29` 自陈「逐字相同」 |

**#4 和 #1 是真问题**：注释承认重复、又没有守卫，说明写注释的人知道、但没改 —— 因为改不动（两个文件各有读者）。

### 6.4 「注释说会被 X 消费」但实际无人读

- **`:35` `exposed_parts`** —— 注释自称「代码里已无人读它做判定」，**这句准确**。但它并非零引用：`view/boss_entity.gd:73` 与 `test/test_forge.gd:578` 仍把它塞进调试载荷 `"exposed"`；`sim/boss_anatomy.gd:66` 另有自己的 `exposed_parts()` 函数（`test/test_boss_anatomy.gd:32-33` 测的是那个）。

  **注释成立，引用面比暗示的宽。** 这类「半死」值最难处理 —— 删了会断调试载荷，留着又占着「已死」的位置。

### 6.5 一个通用判据

> **注释里的推导式比结论危险。** 结论过时，读者能靠数字发现不对；推导式过时，读者会拿**错的式子**去验证一个**对的结论**，然后得出「果然不对」的假警报。

这个项目里已发作 6 次：§6.2（38 点）、`game_config.gd:215` boss_scale（已修 `9ad7974`）、`boss_anatomy.gd:23` 配平（已修 `7df3463`）、`forge_panel.gd:19-27`（已修 `90e1359`）、`session_mgr.cpp` 头注、`cli_client.cpp --help`。

**目前没有机器检查** —— 见 §7。
