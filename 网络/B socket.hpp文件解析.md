## 构造函数:文件名(Socket)
### 源码:
```c++
    // RAII: 构造时打开 fd
    Socket() : fd_(socket(AF_INET, SOCK_STREAM, 0)), test_1(7673) {
        std::cout << "test_1: " << test_1 << std::endl;
        if (fd_ < 0) {
            throw std::runtime_error("Failed to create socket");
        }
    }
```
- **`:` (冒号)**：标记初始化列表的开始。它告诉编译器，接下来要在大括号 `{}` 执行前，对类的成员变量进行初始化。
  后续fd_()调用了一个底层的socket函数获取文件描述符的int,test_1()自己传了个值进去
### 实现原理
该构造函数使用了 C++ 的**初始化列表**与**函数体**相结合的方式来完成对象的初始化：
- **`fd_(socket(AF_INET, SOCK_STREAM, 0))`**：
  - 调用系统级函数 `socket()` 来创建一个网络套接字。
  - `AF_INET`：指定协议族为 IPv4。
  - `SOCK_STREAM`：指定套接字类型为面向连接的流式套接字，即 **TCP 协议**。
  - `0`：指定协议，通常设为 0，系统会根据前面的类型自动选择对应的默认协议（这里即 TCP）。
  - 将 `socket()` 返回的文件描述符赋值给成员变量 `fd_`。
- **`test_1(7673)`**：
  - 将成员变量 `test_1` 初始化为 7673。这看起来像是一个用于测试或调试的变量。
- **`std::cout << "test_1: " << test_ << std::endl;`**：
  - 在标准输出中打印 `test_1` 的值，用于调试或确认初始化状态。
- **`if (fd_ < 0) { throw std::runtime_error("Failed to create socket"); }`**：
  - 判断套接字是否创建成功。在 Linux/Unix 系统中，`socket()` 函数成功时返回非负的文件描述符，失败时返回 `-1`。
  - 如果 `fd_` 小于 0，说明创建失败，立即抛出 `std::runtime_error` 异常，中断对象的构造。
###  用途
- **网络编程基础**：该构造函数用于封装底层 Socket API，作为自定义网络通信类的初始化入口。通过它，类的实例在创建时就自动完成了 TCP 套接字的创建。
- **资源获取即初始化 (RAII)**：结合该类的析构函数(通常会调用 `close(fd_)`），可以实现套接字生命周期的自动管理，防止资源泄露。
- **调试与状态追踪**：通过 `test_1` 变量的打印，开发者可以在对象构造时确认代码执行路径或初始状态。
## 析构函数:~+文件名(~Socket)
### 源码:
```c++
    ~Socket() {
        if (fd_ >= 0) {
            close(fd_);
        }
    }
```
### 解析:
加上类名（如 ~Socket()）定义的是。
#### 触发时机：
当对象离开其作用域（比如函数执行结束），或者被 delete 时，析构函数会自动被调用。
#### 作用：
用于打扫战场，释放对象占用的资源。
在代码中：Socket 对象在构造时向操作系统申请了一个文件描述符 fd_。当对象销毁时，~Socket() 自动调用 close(fd_) 把资源还给操作系统。你再也不用担心忘记调用 close() 导致资源泄漏了。
### 为什么还要加 if (fd_ >= 0)？
因为文件描述符是非负整数。如果构造 Socket 时系统资源耗尽，fd_ 会是 -1。此时如果强行 close(-1)，操作系统会报错。加上判断，让析构函数具备容错能力。
## `= delete`是什么意思
>如果别人尝试调用被 `delete` 的函数，编译器会直接报错拦截。
### 为什么要禁用拷贝？（防止 Double Close）
这是delete最核心的逻辑。我们通过一个**反面案例**来理解：
假设你没有禁用拷贝，C++ 编译器会为你自动生成默认的拷贝构造函数（浅拷贝）：
```
Socket s1;           // 假设 s1 的 fd_ = 3
Socket s2 = s1;      // 默认拷贝行为：s2.fd_ 也变成了 3
```
此时，`s1` 和 `s2` 指向了**同一个**系统资源。灾难发生了：
1. `s2` 先离开作用域，调用 `~Socket()`，执行 `close(3)`。
2. `s1` 后离开作用域，调用 `~Socket()`，再次执行 `close(3)`。
同一个文件描述符被关闭了两次，这就是 **Double Close**。这会导致程序崩溃，或者更严重地，导致其他正常的连接被意外关闭。
### 两个被禁用函数的区别
你禁用了两个函数，它们分别对应两种拷贝场景：
| 被禁用的语法                                 | 对应的操作场景                               | 举例              |
| :------------------------------------- | :------------------------------------------- | :---------------- |
| `Socket(const Socket&) = delete;`            | **拷贝构造**：用一个旧对象来初始化一个新对象 | `Socket s2 = s1;` |
| `Socket& operator=(const Socket&) = delete;` | **拷贝赋值**：两个都已存在的对象之间的赋值   | `s2 = s1;`        |
把这两者都禁用，就彻底封死了 `Socket` 对象被随意复制的大门，从根源上杜绝了 Double Close。
## 拷贝替换为移动拷贝
### 为什么要拷贝:
**拷贝 = 复制 fd** → 两个对象管同一个文件描述符 → **双重 close 崩溃**
**移动 = 转移 fd** → 一个对象接管、原对象置空 → **只 close 一次，完全安全**
### 函数1:移动构造函数：转移 fd 的所有权
#### 源码:
```c++
 Socket(Socket&& other) noexcept : fd_(other.fd_), test_1(other.test_1) {
        other.fd_ = -1;  // 关键！将原对象的 fd 置为无效，防止它析构时 close
        std::cout << "Move constructor called, fd transferred" << std::endl;
    }
```
#### 解析:
##### 实现原理: 这段代码的核心原理是**资源窃取与置空**，而不是传统的内存拷贝。
- **`Socket(Socket&& other)`**：参数是右值引用（`&&`），表示这是一个移动构造函数，用于接收一个即将被销毁或不再需要的临时对象（右值）。
- **`noexcept`**：声明此函数不会抛出异常。这对于移动构造函数非常重要，因为 C++ 标准库容器（如 `std::vector`）在扩容时，如果移动构造函数是 `noexcept` 的，就会优先使用移动操作而非拷贝操作，从而提升性能。
- **`: fd_(other.fd_), test_1(other.test_1)`**：在初始化列表中，直接将原对象 `other` 的文件描述符 `fd_` 和测试变量 `test_1` 赋值给新对象。这是浅拷贝。
- **`other.fd_ = -1;`**：这是**最关键的一步**。将原对象的 `fd_` 设置为 `-1`（在 Linux/Unix 系统中，`-1` 是无效的文件描述符）。这样做的目的是防止原对象在析构时调用 `close(fd_)` 关闭掉刚刚转移给新对象的套接字。
- **`std::cout << ...`**：打印日志，用于调试和追踪移动语义的调用。
## 删除被禁用的情况,如何优雅的切换_fd.
### 移动构造函数:文件名(Socket)
#### 源码:
```cpp
    // 移动构造函数：转移 fd 的所有权
    Socket(Socket&& other) noexcept : fd_(other.fd_), test_1(other.test_1) {
        other.fd_ = -1;  // 关键！将原对象的 fd 置为无效，防止它析构时 close
        std::cout << "Move constructor called, fd transferred" << std::endl;
    }
```
- **`Socket&&` (右值引用)**：标记参数为右值引用。它告诉编译器，传入的 `other` 是一个即将销毁的临时对象，或者被 `std::move` 标记的“不再使用的对象”，从而允许我们安全地“偷取”其内部资源，而不是进行昂贵的深拷贝。
  后续 `fd_(other.fd_)` 直接将对方的文件描述符值拿来，`test_1(other.test_1)` 将测试变量也一并转移。
#### 实现原理
该移动构造函数使用了 C++ 的**右值引用**与**资源窃取**机制来完成对象所有权的高效转移：
- **`Socket(Socket&& other) noexcept`**：
  - 声明这是一个移动构造函数。`noexcept` 关键字向标准库保证此操作不会抛出异常，这使得 `std::vector` 等容器在扩容时优先调用移动而非拷贝，极大提升性能。
- **`: fd_(other.fd_), test_1(other.test_1)`**：
  - 在初始化列表中，直接将 `other` 持有的文件描述符和测试值“偷”过来，赋给当前新构造的对象。此时，新对象和旧对象内部指向了同一个系统资源。
- **`other.fd_ = -1;`**：
  - **这是防止资源泄露的核心防线！** 既然新对象已经接管了真实的 `fd`，必须将原对象的 `fd_` 置为无效值（如 `-1`）。如果不置空，当 `other` 离开作用域触发析构函数 `~Socket()` 时，会执行 `close(fd_)`，导致新对象持有的资源被意外关闭，造成**双重释放**或**资源失效**。
- **`std::cout << "Move constructor called..."`**：
  - 在标准输出中打印移动轨迹，用于调试确认资源发生了转移，而非拷贝。
#### 用途
- **解决无 GC 环境下的资源泄露**：在没有垃圾回收的 C++ 中，通过 `other.fd_ = -1` 配合析构函数中的 `if (fd_ >= 0)` 判断，实现了资源从“旧主”到“新主”的绝对安全交接。旧主析构时发现是空壳（`-1`），什么都不会做；新主析构时才会真正释放资源。
- **避免昂贵的深拷贝**：对于持有系统资源（如 socket fd、文件句柄、大块内存）的对象，拷贝语义要么被禁用（如本类的 `= delete`），要么代价极高。移动语义通过转移所有权，实现了 O(1) 的极速资源转移。
- **完美契合 RAII**：移动构造函数不仅没有破坏 RAII 规则，反而强化了它。它确保了无论对象如何被传递、被放入容器，其绑定的系统资源始终有且只有一个明确的归属者，生命周期依然由析构函数自动、精准地管理。
### 移动赋值运算符:文件名(Socket)
#### 源码:
```cpp
    // 移动赋值运算符
    Socket& operator=(Socket&& other) noexcept {
        if (this != &other) {  // 防止自我赋值 (s1 = std::move(s1))
            // 1. 清理自身的旧资源
            if (fd_ >= 0) {
                close(fd_);
            }
            // 2. 偷取对方的资源
            fd_ = other.fd_;
            test_1 = other.test_1;
            // 3. 将对方置空
            other.fd_ = -1;
        }
        return *this;
    }
```
- **`operator=(Socket&& other)` (移动赋值)**：与移动构造（从无到有创建对象）不同，移动赋值是**两个已存在的对象**之间的资源交接。因为目标对象（`this`）可能已经持有资源，所以必须先妥善处理自己的旧资源。
  后续的三步走逻辑是移动赋值的黄金法则：先清自身，再偷对方，最后毁对方。
#### 实现原理
该移动赋值运算符严格遵循了移动语义下的资源交接规范：
- **`if (this != &other)`**：
  - **防止自我赋值**。如果强行执行 `s1 = std::move(s1)`，没有这个判断的话：程序会先 `close(s1.fd_)` 释放自己的资源，然后又把刚释放的（无效）资源赋给自己，最后把自己置空，导致对象彻底损坏。
- **1. 清理自身的旧资源 (`if (fd_ >= 0) close(fd_);`)**：
  - 这是移动赋值比移动构造多出的关键一步。目标对象在接管新资源前，必须先释放自己正在管理的旧资源，否则旧资源就泄露了。
- **2. 偷取对方的资源 (`fd_ = other.fd_; test_1 = other.test_1;`)**：
  - 将源对象的资源句柄和数据直接搬过来。
- **3. 将对方置空 (`other.fd_ = -1;`)**：
  - 与移动构造同理，剥夺源对象的资源所有权，防止它析构时 `close` 掉刚交接过去的资源。
- **`return *this;`**：
  - 返回对象自身的引用，以支持连续赋值操作（如 `a = b = c`）。
#### 用途
- **对象复用与状态重置**：当需要将一个已有对象替换为另一个临时对象的状态时使用。例如在网络连接池中，将一个闲置的连接对象替换为一个新建立的连接。
- **保障 RAII 在赋值场景下的闭环**：确保“一资源一归属”的铁律在赋值过程中不被打破。旧资源被安全释放，新资源被唯一接管，绝不泄露，绝不重释。

### 💡工程实现

你的逻辑已经完全正确了。但在 C++ 工程实践中，移动赋值运算符还有一种更高级、更推荐的标准写法，叫做 **Copy-and-Swap 惯用法** 的变体。

你可以把移动赋值运算符写得极简，且天然异常安全：

```cpp
    // 极简移动赋值：借助移动构造和 swap
    Socket& operator=(Socket&& other) noexcept {
        // 只要不是自我赋值，就与对方交换
        if (this != &other) {
            std::swap(fd_, other.fd_);
            std::swap(test_1, other.test_1);
        }
        return *this;
    } // other 离开作用域时，带着原来的旧 fd 析构，自动 close
```

**为什么这种写法更好？**
你不需要手动写 `if (fd_ >= 0) close(fd_);`。你只需要把你的 `fd_` 和对方的 `fd_` 互换。当函数结束时，参数 `other` 作为局部对象会被销毁，它的析构函数会自动帮你 `close` 你原本拥有的那个旧 `fd_`！这叫“借刀杀人”，代码更短，且绝对不会忘记清理旧资源。

```c++
  std::cout << "========== 场景 2：放入 vector ==========" << std::endl;
    std::vector<Socket> vec;

    std::cout << "========== 场景 3：移动赋值 ==========" << std::endl;

```



| 代码场景                       | 触发的函数         | 原因                                                         |
| :----------------------------- | :----------------- | :----------------------------------------------------------- |
| `vec.push_back(std::move(s1))` | **移动构造函数**   | `vector` 里原本没有对象，是在**构造**一个新元素放入容器。    |
| `s2 = std::move(vec[0])`       | **移动赋值运算符** | `s2` 已经是一个存在的对象，这是将资源**赋值/转移**给一个已有对象。 |

## 设置超时时间:内置函数->setsockopt()

### 源码:

```c++
    void set_recv_timeout(int timeout_ms) const {
        struct timeval tv;
        tv.tv_sec = timeout_ms / 1000;
        tv.tv_usec = (timeout_ms % 1000) * 1000;
        if (setsockopt(fd_, SOL_SOCKET, SO_RCVTIMEO, &tv, sizeof(tv)) < 0) {
            throw std::runtime_error("Failed to set SO_RCVTIMEO");
        }
    }
```

### 实现原理

该函数通过底层 Socket API `setsockopt` 来修改套接字的属性，具体步骤如下：

- **时间单位转换**：C++ 标准库和 POSIX 定义的超时结构体 `timeval` 要求将时间分为“秒”和“微秒”两部分。而函数输入参数 `timeout_ms` 是毫秒。
  - `tv.tv_sec = timeout_ms / 1000;`：通过整除计算得到秒数。
  - `tv.tv_usec = (timeout_ms % 1000) * 1000;`：通过取余得到剩余的毫秒数，再乘以 1000 转换为微秒。
- **设置套接字选项**：调用 `setsockopt` 函数。
  - `fd_`：类的成员变量，代表要设置的超时时间的套接字文件描述符。
  - `SOL_SOCKET`：表示操作的是套接字层级别的选项。
  - `SO_RCVTIMEO`：指定要设置的选项名称为“接收超时时间”。
  - `&tv` 和 `sizeof(tv)`：传入超时时间的结构体指针及其大小。
- **错误处理**：如果 `setsockopt` 返回值小于 0，说明设置失败，此时抛出 `std::runtime_error` 异常。

### 注意事项

- **平台兼容性差异**：
  - 在 **Linux** 系统中，`SO_RCVTIMEO` 选项设置的超时时间只在单次系统调用中有效。也就是说，一旦 `recv` 超时返回后，该选项会被系统自动重置，后续的 `recv` 将再次陷入无限期阻塞。因此，**在循环接收数据时，必须在每次调用前重新设置该选项**。
  - 在 **Windows** 系统中（使用 `setsockopt` 配合 `SO_RCVTIMEO`），超时设置是持久的，一次设置对所有后续的 `recv` 调用都有效。
- **异常安全**：该函数在失败时抛出异常，调用方必须使用 `try-catch` 进行捕获，否则可能导致程序因未捕获异常而崩溃（`std::terminate`）。
- **`const` 修饰符的语义**：函数被声明为 `const`，说明该函数意图不修改类的任何非 `mutable` 成员变量。虽然修改套接字的底层行为（超时时间）在逻辑上改变了对象的状态，但由于 `fd_` 只是一个文件描述符（通常为 `int`），`setsockopt` 修改的是操作系统内核中套接字的状态，而非类成员变量本身的值，因此在这里使用 `const` 是常见做法。
- **微秒溢出风险**：`(timeout_ms % 1000) * 1000` 计算结果不会超过 999,000，在 `tv_usec`（通常为 32 位或 64 位整数）中不会溢出，此处是安全的。
