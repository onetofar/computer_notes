> [!info] 核心结论
> 伯克利套接字 API 本身游双系列已逐函数讲透，本篇只收格雷泽 §3 的两块独有增量：**跨平台差异速查**（Windows Winsock2 vs POSIX，写双端代码的人直接照抄）和**类型安全封装模式**（`int` 裸句柄 → RAII 类 + `shared_ptr` typedef + 工厂）。外加一条游戏循环纪律：非阻塞轮询时**每帧读取设上限**——不限量读会把服务器让给恶意客户端的单字节洪泛。

## 机制

### 跨平台差异速查（§3.2）

| 维度 | Windows (Winsock2) | POSIX (Linux/Mac/PS) |
|---|---|---|
| socket 类型 | `SOCKET` = `UINT_PTR`（指针向内核资源） | **`int`**（打开文件表的下标，可直接当 fd 用） |
| 头文件 | `WinSock2.h`；地址转换另含 `Ws2tcpip.h` | `sys/socket.h` + `netinet/in.h` + `arpa/inet.h` + `netdb.h` |
| 库初始化 | **必须** `WSAStartup(MAKEWORD(2,2))`，配对 `WSACleanup`（两者都是**引用计数**） | 默认可用，无需启动 |
| 错误获取 | `WSAGetLastError()`（线程局部） | 全局 `errno`（含 `errno.h`） |
| 大小写约定 | 平台专有函数大写开头 / `WSA` 前缀 | 标准函数全小写 |

三条工程纪律（原文小窍门/注释）：

1. **头文件冲突**：同一编译单元同时含 `Windows.h` + `WinSock2.h` 会重复声明报错——先含 `WinSock2.h`，或先 `#define WIN32_LEAN_AND_MEAN`。
2. **错误码立即检查**：`WSAGetLastError`/`errno` 都会被下一次调用覆盖——返回 −1 后**马上**读，中间再调任何 socket 函数会掩盖真因。
3. **非标准函数隔离**：Winsock2 专有函数（大写/WSA 前缀）集中放开关层，跨平台路径只走标准函数——移植成本最低的分法。

### sockaddr 家族与字节序（§3.3）

```c
struct sockaddr     { uint16_t sa_family; char sa_data[14]; };   // 通用容器
struct sockaddr_in  { short sin_family; uint16_t sin_port;
                      struct in_addr sin_addr; char sin_zero[8]; }; // IPv4 专用
```

- API 诞生早于 C++ 多态，所以 `sockaddr_in` → `sockaddr` 是**手工强转**；`sin_zero` 填 0 凑齐 16 字节；Mac 平台额外有 `sa_len` 字段要设 `sizeof(sockaddr_in)`。
- 实例化套路：**先 `memset` 清零**（防"这个平台用、那个平台不用"的字段带垃圾值），端口/地址多字节数一律 `htons/htonl` 进、`ntohs/ntohl` 出——调试器里看到 `sin_port` 是字节交换后的十进制值**是正常的**。
- 主机序 = 网络序的平台上这些函数是空操作，优化编译器会把它优化掉——写不写都必须写。

### 类型安全封装模式（§3.3.1 / §3.4 / §3.5）

裸 `int`/`SOCKET` 的缺点：编译器接受 `socket(5 × 4)` 这种表达式——句柄没有类型。格雷泽的封装三板斧：

1. **类持有句柄**（`SocketAddress` 包 `sockaddr`、`UDPSocket`/`TCPSocket` 包 `SOCKET`）；
2. **`shared_ptr` typedef**（`UDPSocketPtr` / `SocketAddressPtr`）——生命周期跟着所有权走；
3. **工厂**（`SocketUtil::CreateUDPSocket(INET)` / `SocketAddressFactory` 从字符串构造）——平台分支关在工厂和开关方法里，业务代码只见类型。

跨平台开关就长在类方法内部（清单 3.8）：

```cpp
int UDPSocket::SetNonBlockingMode(bool inShouldBeNonBlocking)
{
#if _WIN32
    u_long arg = inShouldBeNonBlocking ? 1 : 0;
    int result = ioctlsocket(mSocket, FIONBIO, &arg);
#else
    int flags = fcntl(mSocket, F_GETFL, 0);
    flags = inShouldBeNonBlocking ?
                (flags | O_NONBLOCK):(flags & ~O_NONBLOCK);
    int result = fcntl(mSocket, F_SETFL, flags);
#endif

    if(result == SOCKET_ERROR)
    {
        SocketUtil::ReportError(L"UDPSocket::SetNonBlockingMode");
        return SocketUtil::GetLastError();
    }
    else
    {
        return NO_ERROR;
    }
}
```

注意 POSIX 侧的正确顺序：先 `F_GETFL` 取回现有标志、按位或上 `O_NONBLOCK`、再 `F_SETFL` 写回——**直接 `F_SETFL(O_NONBLOCK)` 会清掉别的标志位**。

### 非阻塞游戏循环与每帧上限（§3.6）

阻塞 I/O 对游戏是死刑（等一个客户端的 `recv` 卡住整个模拟），三条路：**多线程 / 非阻塞轮询 / select**。多线程路的账单：每连接一线程，扩展性差、数据汇入要加锁、收发同 socket 会互相阻塞——"有更简单的方法"。

非阻塞轮询的标准循环（清单 3.9）：

```cpp
void  DoGameLoop()
{
    UDPSocketPtr mySock = SocketUtil::CreateUDPSocket(INET);
    mySock->SetNonBlockingMode(true);

    while(gIsGameRunning)
    {
        char data[1500];
        SocketAddress socketAddress;

        int bytesReceived = mySock->ReceiveFrom(data, sizeof(data),
               socketAddress);
        if(bytesReceived> 0)
        {
            ProcessReceivedData(data, bytesReceived, socketAddress);
        }
        DoGameFrame();
    }
}
```

**每帧读取上限是本篇最值钱的一条纪律**：想要多读就循环读"直到读满上限或读空"。原文的理由——不限量的话，恶意客户端可以用海量**单字节数据报**让服务器把全部时间花在收包上，模拟被饿死。socket 数量大了轮询变低效 → `select`（§3.6.3），再往上就是 epoll/kqueue 的领域（游双系列）。

## 作者省略的前提

> [!note] 本节是补出来的，不在原文里。
> 每条句尾标来源：`（推演）` / `（见 §X.X）` / `（工程经验）`

| 省略了什么 | 补出来是什么 | 来源 |
|---|---|---|
| `int` fd 的深层好处 | 不只是类型不安全的借口——fd 能直接喂给 epoll/kqueue 统一等待，"socket 即文件描述符"是整个 IO 多路复用体系的入场券。Windows 的 `SOCKET` 也能进 select/WSAPoll，但"文件表下标"这层语义没了 | 见游双 5-2 系列 |
| `EAGAIN` 与 `EWOULDBLOCK` | POSIX 允许两值不同，Linux 上同值；Windows 对应 `WSAEWOULDBLOCK`。非阻塞循环必须把 −1+这两个码当**正常路径**而不是错误 | 工程经验 |
| 每帧上限与"读干净到 EAGAIN"的组合 | 两条纪律不矛盾：单次循环 = 读到 **min(上限, 读空)** 为止。只限不读干净 → 内核缓冲积压、延迟膨胀；只读干净不限量 → 洪泛饿死。合起来的正确形态见彭放 Reactor 规范 | 见 [[01-彭放-epoll-Reactor工程规范]] + §3.6.2 |
| 封装类用 `shared_ptr` 的理由 | 句柄本身是值语义（原文要求按值传），指针包装解决的是**生命周期与所有权**（谁负责 closesocket、回调期间不被关），不是值传递问题 | 推演 |
| 本项目为什么不写 Win32 分支 | `otf-server` 双环（WSL 宿主 + Linux 容器）都是 POSIX——`#if _WIN32` 分支保留在教材认知里，仓库代码不需要 | 工程经验 |

## 成立条件与失效边界

| 条件 | 满足则 | 不满足则 |
|---|---|---|
| 每帧处理量有限、连接少 | 非阻塞轮询最简单 | 连接多 → select 到达 fd 上限/轮询成本 O(n) → epoll（水平触发） |
| 只走标准函数 | 跨平台零成本 | 用了 WSA 专有功能 → 移植面扩大 |
| 收包上限 + 读干净组合 | 洪泛与积压两头都堵 | 只做其一 → 恶意客户端或延迟膨胀 |
| RAII 封装 + 工厂 | 句柄泄漏/双关不再可能 | 直接裸操作 fd → 异常路径泄漏 socket |

## 原文证据

> "限制每帧读取数据报数量很重要。如果不这样做的话，一个恶意的客户端可以发送大量的单字节数据报，发送的速度大于服务器处理的速度，严重阻碍服务器模拟游戏。"（§3.6.2）

> "在发生错误之后继续调用 socket 函数会因为第一个错误而造成第二个错误。这将改变 WSAGetLastError 的返回结果，掩盖问题的真正原因。"（§3.2）

## 本项目落点

| 教材结论 | 落到哪 | 怎么落 |
|---|---|---|
| 非阻塞 + 每帧上限 | `otf-server/src/net/`（tcp_transport 读循环） | LT 模式读干净到 EAGAIN、单次事件循环设包数上限——洪泛与积压双防 |
| 错误码立即检查 | net 层错误处理 | `read/write` 返回 −1 后立即取 `errno` 并分派（EAGAIN/ECONNRESET/…），不做任何中间调用 |
