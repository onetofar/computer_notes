## 二、伪链路层头部（回环专用）
### 数据：`02 00 00 00`
- **含义**：Windows Npcap 捕获回环（`127.0.0.1`）数据包时，添加的**自定义伪链路层头部**，并非标准以太网帧。
- **字段解析**：
  - `02 00`：地址族标识，值为 `AF_INET`（IPv4 协议）
  - `00 00`：保留字段，无实际含义
- **补充说明**：回环接口无物理以太网层，因此用该伪头部替代链路层帧，不影响上层协议解析。

## 三、IPv4 头部逐字段解析（字节偏移 4-23，共 20 字节）
IP 头原始数据：`45 00 00 2f af 84 40 00 40 11 8d 37 7f 00 00 01 7f 00 00 01`

| 字节偏移（IP头内）   | 字段名称                                 | 十六进制值   | 十进制/二进制解析                           | 协议含义                                                     |
| -------------------- | ---------------------------------------- | ------------ | ------------------------------------------- | ------------------------------------------------------------ |
| 0（总偏移4）         | 版本 + 头部长度（IHL）                   | `0x45`       | 高4位 `0x4`，低4位 `0x5`                    | 高4位 `0x4` → IPv4 协议；低4位 `0x5` → 头部长度（单位：32位/4字节），`5×4=20字节`（无选项字段，为标准IP头长度） |
| 1（总偏移5）         | 差分服务字段（DSCP/ECN）                 | `0x00`       | DSCP=0，ECN=0                               | DSCP `0x00` → 默认服务等级（CS0），无优先级标记；ECN `0x00` → 未使用显式拥塞通知（Not-ECT） |
| 2-3（总偏移6-7）     | 总长度（Total Length）                   | `0x002f`     | 十进制 `47`                                 | 整个IP数据报的总长度（IP头 + IP payload），此处为 `20（IP头） + 27（UDP数据报，含UDP头+数据）=47`，与值完全匹配 |
| 4-5（总偏移8-9）     | 标识（Identification）                   | `0xaf84`     | 十进制 `44932`                              | 内核为每个IP数据报分配的唯一标识，用于分片重组，每个包的标识通常不同 |
| 6-7（总偏移10-11）   | 标志 + 片偏移（Flags + Fragment Offset） | `0x4000`     | 标志位 `0x4`（二进制`010`），片偏移 `0x000` | 标志位 `0x4` → `DF=1`（不分片，Don't Fragment），`MF=0`（非后续分片）；片偏移 `0x000` → 无分片偏移，与不分片标志一致 |
| 8（总偏移12）        | 生存时间（TTL）                          | `0x40`       | 十进制 `64`                                 | IP包在网络中的最大跳数，Linux/Windows默认值为64，每经过一个路由器减1，减为0则丢弃 |
| 9（总偏移13）        | 协议（Protocol）                         | `0x11`       | 十进制 `17`                                 | IP payload的上层协议，`17`对应UDP协议，与抓包类型一致        |
| 10-11（总偏移14-15） | IP头部校验和                             | `0x8d37`     | -                                           | 仅对IP头部计算的校验和，验证IP头在传输中未损坏，此处已由内核正确计算 |
| 12-15（总偏移16-19） | 源IP地址                                 | `0x7f000001` | `127.0.0.1`                                 | 数据包发送方IP，为本地回环地址                               |
| 16-19（总偏移20-23） | 目的IP地址                               | `0x7f000001` | `127.0.0.1`                                 | 数据包接收方IP，与源IP相同，为本地回环通信                   |

## 四、UDP 头部逐字段解析（字节偏移 24-31，共 8 字节）
UDP 头原始数据：`b3 1e 23 28 00 1b 30 e3`

| 字节偏移（UDP头内） | 字段名称                       | 十六进制值 | 十进制解析 | 协议含义                                                     |
| ------------------- | ------------------------------ | ---------- | ---------- | ------------------------------------------------------------ |
| 0-1（总偏移24-25）  | 源端口号（Source Port）        | `0xb31e`   | `45854`    | 发送方的临时端口（ephemeral port），由操作系统随机分配，与Wireshark解析的`45854`一致 |
| 2-3（总偏移26-27）  | 目的端口号（Destination Port） | `0x2328`   | `9000`     | 接收方的服务端口，此处为自定义UDP服务的端口                  |
| 4-5（总偏移28-29）  | UDP长度（Length）              | `0x001b`   | `27`       | 整个UDP数据报的长度（UDP头 + UDP数据），`8（头） + 19（数据）=27`，与值完全匹配 |
| 6-7（总偏移30-31）  | UDP校验和（Checksum）          | `0x30e3`   | -          | 基于IP伪头部、UDP头、UDP数据计算的校验和，验证整个UDP数据报的完整性 |

### 关键状态说明
Wireshark 显示：`Checksum: 0x30e3 [correct]`，`Checksum Status: Good`
- 含义：Wireshark 已验证 UDP 校验和为有效，说明开启了 UDP 校验和验证功能，校验和计算正确，数据在传输中未损坏。

# 校验和如何计算?

我现在**严格按照你给的正确数据**，一步一步做 **UDP 校验和 反码求和**，纯计算、无脑套用，最后验证结果和你抓包的 `0x30E3` 完全一致！

## 第一步：锁定所有参与计算的字节（你写的全对）
先把这些打出来:

```c++
7F 00 00 01 7F 00 00 01  00 11  00 1B //虚拟头 包括: 源ip 目的ip 固定00 udp协议0x11 udp总长度
b3 1e 23 28 00 1b 00 00 //udp真实头部: 原始port 目的port 长度 校验和先是: 0x0000
48 65 6c 6c 6f 20 55 44 50 20 45 63 68 6f 31 31 31 31 21 00 //udp数据段: 需要补零到偶数字节,最后的00就是补的
```

按顺序拼接：
**伪首部(12) + UDP头(8,校验和清零) + 数据补零(20)**

```hex
// 1. 伪首部 (12字节)
7F 00 00 01 7F 00 00 01 00 11 00 1B
// 2. UDP头 (8字节，最后2字节清零)
B3 1E 23 28 00 1B 00 00
// 3. 数据补零 (20字节，19+1)
48 65 6C 6C 6F 20 55 44 50 20 45 63 68 6F 31 31 31 31 21 00
```

## 第二步：每 2 字节 = 1 组（16位，大端序）
```
分组1: 0x7F00    分组2: 0x0001    分组3: 0x7F00    分组4: 0x0001
分组5: 0x0011    分组6: 0x001B    分组7: 0xB31E    分组8: 0x2328
分组9: 0x001B    分组10:0x0000    分组11:0x4865    分组12:0x6C6C
分组13:0x6F20    分组14:0x5544    分组15:0x5020    分组16:0x4563
分组17:0x686F    分组18:0x3131    分组19:0x3131    分组20:0x2100
```

## 第三步：反码求和（核心：进位卷回低16位）
初始和 `sum = 0`，逐组相加，超 16 位就把进位加回去
```
sum = 0
1.  +7F00 → 7F00
2.  +0001 → 7F01
3.  +7F00 → FE01
4.  +0001 → FE02
5.  +0011 → FE13
6.  +001B → FE2E
7.  +B31E → 1B14C → 进位1 → B14C + 1 = B14D
8.  +2328 → D475
9.  +001B → D490
10. +0000 → D490
11. +4865 → 11CF5 → 进位1 → 1CF5 + 1 = 1CF6
12. +6C6C → 8963
13. +6F20 → F883
14. +5544 → 14DC7 → 进位1 → 4DC7 +1=4DC8
15. +5020 → 9DE8
16. +4563 → E34B
17. +686F → 14BB8 → 进位1 → 4BB8 +1=4BB9
18. +3131 → 7CEA
19. +3131 → AE1B
20. +2100 → CF1B
```

✅ **最终求和结果：`0xCF1B`**

## 第四步：对总和按 16 位取反 → 得到 UDP 校验和
公式：`0xFFFF - 求和结果 = 校验和`
```
0xFFFF - 0xCF1B = 0x30E3
```

抓包中的 UDP 校验和 = **`0x30E3`**
我们手动计算结果 = **`0x30E3`**

## 总结
1. 拼数据：**伪首部 + UDP头(清零) + 数据(补偶)**
2. 分16位组相加
3. 进位卷回
4. `0xFFFF - 总和 = 校验和`
5. 接收端全加 = `0xFFFF` → 正确
