### 各个字段内容
#### 版本字段：
- IPv4为`4`，IPv6为`6`；IPv4头部和IPv6头部**除版本字段位置相同外，其余结构完全不同**
#### **Internet头部长度（IHL）**：
- IPv4：保存头部中32位字的数量，4位字段限制头部最多为`15×32位=60字节`
- IPv6：**无此字段**，头部固定为`40字节`，无内嵌选项，扩展功能通过「扩展头」实现
#### DS(区分服务)+ECN(显示拥塞通知)=TOS(服务类型)：
- IPv4：用于数据报转发时的特殊处理
- IPv6：该字段改名为**「流量类（Traffic Class）」**，功能与IPv4的DS+ECN一致
#### **总长度字段**：
- IPv4：表示整个IP数据报（头部+数据）的总字节数，与IHL配合可定位数据部分起始位置
- IPv6：**无总长度字段**，改用「有效**载荷长度**（Payload Length）」字段，仅表示IPv6头之后的数据（含扩展头+上层数据）长度；IPv6基本头不支持分片，分片由扩展头实现，且支持`Jumbo Payload`扩展头实现最大4GB的超长载荷
#### 标识字段：
- IPv4：用于区分不同数据报的分片，发送主机每次发包会将内部计数器加1并写入该字段，避免分片混淆
- IPv6：**基本头无此字段**，分片相关标识/偏移字段由「分片扩展头」实现，且IPv6不支持中间路由器分片，仅源主机可处理分片
#### 分片偏移:
- **标志**（3 位）：保留位恒 0；**DF=1 禁止分片**，**MF=1 表示还有后续分片**，MF=0 为最后一片。
- 分片偏移（13 位）：标识分片在原数据报中的位置，**单位 8 字节**，接收端依此按序重组报文。
#### 生存期(TTL)：
- IPv4：设置数据报可经过的路由器数量上限，防止环路
- IPv6：改名为**「跳数限制（Hop Limit）」**，功能与TTL完全一致
#### 协议字段：
- IPv4：标识数据报有效载荷的协议类型（常用值：`6=TCP`、`17=UDP`）
- IPv6：改名为**「下一个头部（Next Header）」**，作用与IPv4协议字段类似，不仅可标识传输层协议（TCP/UDP/ICMPv6），还可标识后续扩展头类型
#### 头部校验和：
- IPv4：仅校验IP头部，不检查数据部分正确性
- IPv6：**无头部校验和字段**，由上层协议（如TCP/UDP）和链路层校验保证数据正确性，减少路由器处理开销
### DS ECN详解
DS 字段（区分服务）
**核心作用:DS 字段 = 给 IP 包打优先级标签，路由器按标签给转发待遇；普通网页默认 CS0；AF/EF 是 DSCP 定义的标准转发行为；DiffServ 是为了给多业务流量分级，解决尽力而为的拥塞问题。**
- 6 位，存储**DSCP（区分服务代码点）**，共 64 个可选值，默认值`0`（常规尽力而为流量）
- 核心作用：标记流量优先级，路由器根据 DSCP 值执行不同的转发策略（PHB，每跳行为）
- 常用 PHB 类型：
  - **CS（类别选择）**：兼容旧 TOS 优先级，CS0 = 默认，CS7 = 最高优先级（网络控制）
  - **AF（保证转发）**：格式`AFij`，i = 流量类别 (1-4)，j = 丢弃优先级 (1-3)，数值越大优先级越高
  - **EF（加速转发）**：低延迟、低抖动、低丢包，用于语音、视频等实时流量
**默认情况下，浏览器 / 操作系统发出的 HTTP/HTTPS 包，DSCP 值固定为`CS0（000000，十进制0）`**，也就是无特殊优先级的「尽力而为」流量。
  - 只有两种情况会变：
    1. 操作系统 / 应用手动配置了 QoS 策略（比如企业内网给办公网页设了优先级）
    2. 运营商 / 路由器做了 DSCP 重标记（比如把视频流量的 DSCP 改成 EF）
  - 你平时用 Chrome/Edge 刷网页，抓包看到的 DS 值几乎全是`0`，不用纠结。

ECN 字段（显式拥塞通知）

- 2 位，用于**提前标记网络拥塞**，避免直接丢包
- 工作流程：拥塞路由器标记 ECN 位 → 目的主机收到后通知发送方 → 发送方主动降速
- 比传统 “丢包触发降速” 更高效，TCP 协议原生支持

### IPv4 选项

- 位置：基本 IP 头（20 字节）之后，由 IHL 字段控制总长度，最多 40 字节，必须 32 位对齐
- 作用：提供可选的扩展功能（路由控制、诊断等）
- 现状：**绝大多数选项已废弃或极少使用**，大部分被企业防火墙过滤，会显著降低路由器转发效率
- 常见选项：源路由、记录路由、时间戳、安全标签（仅军事环境）

2. IPv6 扩展头（替代 IPv4 选项）

- 设计：**链式结构**，每个扩展头包含`Next Header`字段指向下一个头部，按需添加
- 优势：中间路由器仅处理必要的扩展头，不影响普通流量转发效率
- 常用扩展头：
  - 分片扩展头：实现 IPv6 分片功能（仅源主机处理）
  - 路由扩展头：指定数据包经过的路由器路径
  - 认证扩展头 (AH)：提供数据完整性和身份认证
  - 封装安全载荷扩展头 (ESP)：提供数据加密和认证

### 总长度字段以及IP数据关系：

65515 = 2^16 - 1; 理论能表面65515字节大小；
以太网帧数据报最大字节数为：1500byte

**IPv4 总长度（16 位）**：最大值是 `2^16 - 1 = 65535` 字节（IP 头 + IP 数据），这是协议定义的上限，不代表能一次发出去。

**以太网 MTU（最大传输单元）**：以太网帧的「数据部分（Payload）」最大是 1500 字节，这是链路层硬件的限制，决定了 IP 数据报的最大单次发送长度（IP 头 + IP 数据 ≤ 1500）。

#### 差距过大所以需要分片处理：

##### 1. 接收端：内核负责重组，网卡不参与

- 接收端的网卡收到以太网帧后，把 Payload（IP 分片）交给内核；
- 内核根据 IP 头中的`标识`（所有分片的标识相同，对应同一个原始 IP 数据报）、`分片偏移`和`MF标志位`，把所有分片按顺序重组，恢复成完整的原始 IP 数据报，再交给上层协议（TCP/UDP）。

##### 2. 中间路由器：只转发分片，不重组

IP 分片的重组只在**目的主机**完成，中间路由器（比如网关、骨干网路由器）只会转发每个分片，不会尝试把分片拼起来。

##### 3. 为什么 TCP 很少触发 IP 分片？

TCP 在三次握手时会协商`MSS（最大分段大小）`，MSS = MTU - IP 头长度 - TCP 头长度（比如 MTU=1500，IP 头 20，TCP 头 20 → MSS=1460）。

- TCP 会控制发送的数据部分不超过 MSS，这样「IP 头 + TCP 头 + TCP 数据」刚好等于 MTU，**完全避免 IP 分片**；
- 只有 UDP、ICMP 这类没有 MSS 控制的协议，才会触发 IP 分片。

# IP模块的工作流程(发生在网络层的故事)

## 过程
清楚边界信息:

🔹 **数据链路层**（网卡 + 驱动）**—— 只干 2 件事**

1. **收包**：把以太网帧拆封，取出里面的**IP 数据报**，**递交给网络层**
2. **发包**：把网络层处理完的 IP 数据报，封装成以太网帧，**发出去**→ 全程不看 IP 头、不判断、不计算、不转发

🔹 **网络层**（内核 IP 模块 + CPU）——**流程图全流程都在这里**从 `IP输入队列` → `头部校验` → `解析` → `本机判断` → `转发` → `路由` → `TTL-1` → `校验和更新` → `IP输出队列`**所有判断、所有逻辑、所有处理，全是网络层的工作**

🔹 **传输层**（TCP/UDP）—— 仅「目标 IP = 本机」时才介入就是流程图里 `按协议号分发上层` (教材图中的发送给本机数据包Yes)那一步，属于**网络层→传输层**的交付

------

IP模块是TCP/IP协议栈的「交通枢纽」，负责IP数据报的**接收、校验、路由转发、上层分发**，核心分为「输入处理」和「转发/输出」两大流程，路由表是它的核心**决策依据。**

------

### 1. 输入处理流程（数据报从链路层进来,从下往上）

- **步骤1：头部校验与解析**
  IP数据报进入`IP输入队列`后，首先做**IP头部校验和**校验，失败直接丢弃；校验通过后解析头部关键字段（目标IP、协议号、TTL、IP选项等）。
  
- **步骤2：IP选项特殊处理（源站选路）**

  - **IPv4：作为“选项 (Options)”字段出现**。它的标识是IP数据包头中“选项”字段里的**特定类型码 (Code)**，分为`0x89`（严格源路由，SSRR）和`0x83`（松散源路由，LSRR）。
  - **IPv6：作为“扩展报头 (Extension Header)”出现**。它的标识是紧跟在IPv6基本头部的“下一个头部 (Next Header)”字段，当值为 **`43`** 时，就代表紧跟着一个“路由扩展报头”（Routing Header）。

  如果头部包含源站选路选项（松散/严格源路由），直接跳过常规的本机判断，交给「数据报转发子模块」处理，按选项指定的路径转发（现在几乎被所有路由器禁用，安全风险极高）。

- **步骤3：本机判断与上层分发**
  解析目标IP地址，判断是否为**本机IP、广播/组播地址**：
  
  - ✅ 目标是本机：根据`协议号`字段（6=TCP、17=UDP、1=ICMP），将数据报分发给对应的上层协议（TCP/UDP/ICMP）。
  - ❌ 目标不是本机：交给「数据报转发子模块」，准备转发。

### 2. 转发/输出流程（非本机数据报处理）
- **步骤1：转发权限检查**
  转发子模块首先检查系统是否开启IP转发（主机默认关闭，**路由器**默认开启），未开启则直接丢弃数据报。
- **步骤2：下一跳路由计算**
  允许转发的情况下，根据目标IP地址查询`路由表`，计算下一跳路由（目标IP→下一跳IP+出接口）。
  - 路由表更新来源：动态路由协议（RIP/BGP）、静态配置（route命令）、ICMP重定向报文。
- **步骤3：TTL处理与头部重写**
  转发前TTL减1，若TTL=0则丢弃并发送ICMP超时错误；更新IP头部校验和，写入新的TTL和下一跳相关信息。
- **步骤4：排队与发送**
  处理后的数据报进入`IP输出队列`，等待网络驱动程序封装成链路层帧，发送到下一跳。

### 3. 路由表的更新与影响
- 动态路由协议（RIP/BGP）会根据网络拓扑变化自动更新路由表；
- 管理员通过`route`命令手动配置静态路由；
- 收到ICMP重定向报文时，会临时更新路由表，优化转发路径。

### 4. ICMP与IP模块的交互
- IP模块收到ICMP报文（如目的不可达、超时、重定向）时，会更新路由表或向上层报告错误；
- TCP/UDP发送数据报时，若遇到错误（如端口不可达），会触发IP模块发送ICMP错误报文。

## 主机过程和路由器差异

1. **路由器就是一台小型 Linux 主机**，有 CPU、有内核、有 TCP/IP 协议栈、有网卡。
2. **网卡只干链路层**，IP/TCP 一律由内核 + CPU 处理，**主机 / 路由器规则完全一样**。
3. 唯一区别：
   - 主机：默认 **关闭 IP 转发**（不帮别人捎包）
   - 路由器：默认 **开启 IP 转发**（专职帮别人捎包）
