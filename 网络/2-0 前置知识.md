## ICMPv4 前置知识整理
>**ICMPv4（Internet Control Message Protocol v4，互联网控制报文协议第 4 版）**
### 一、基础定位
**ICMPv4（Internet Control Message Protocol v4，互联网控制报文协议第4版）**
1. 层级：**IPv4网络层协议**，封装在 IPv4 报文内部（IPv4头部协议号 = `1`）
2. 本质：IPv4 的**配套辅助协议**，不传输业务数据，专门做**网络错误反馈、连通性探测、状态通知**
3. 与IP分片的关系：**ICMP报文本身也会被IP分片**，ICMP是IP的载荷，载荷超过链路MTU就触发IPv4分片
### 二、ICMPv4 核心报文类型（本案例用到2个）
| 类型值 | 类型名称                 | 作用                                                         | 案例对应                       |
|  | 
---

| 8      | 回显请求（Echo Request） | ping 命令发送，主动探测目标是否在线                          | 本案例发送方构造的就是该报文   |
| 0      | 回显应答（Echo Reply）   | 目标收到回显请求后回复                                       | 正常ping的返回包               |
| 11     | 超时（Time Exceeded）    | 分2种：<br>代码0：TTL耗尽（traceroute原理）<br>**代码1：分片重组超时（本案例）** | 接收方分片超时后回复的错误报文 |
| 3      | 目标不可达               | 端口、主机、网络不可达                                       | 网络不通时反馈                 |

### 三、ICMPv4 极简报文结构
```
【IPv4头部(20B)】 + 【ICMPv4头部 + 数据区】
ICMP头部：类型(1B) | 代码(1B) | 校验和(2B) | 可变数据区
```
- 错误类报文（如超时）：数据区必须携带**原出错IP报文头部+上层前8字节**，让发送方定位问题
- 回显请求/应答：数据区可自定义填充数据（ping包的负载）

### 四、IP分片 + ICMP 重组超时 核心规则（书本重点）
1. **分片重组计时器机制**
   接收方**只要收到任意一个IP分片**，立刻启动**重组超时计时器（标准默认20s）**；
   超时未集齐该报文所有分片 → 丢弃已缓存分片，回复 **ICMPv4 超时报文（类型11，代码1）** 通知发送方。

2. 为什么必须有计时器？（安全防御）
   攻击者可构造**残缺分片**：只发前2个分片、永远不发最后一片，让接收方无限缓存分片 → 耗尽内存/缓存，实现**DoS攻击（泪滴攻击 Teardrop）**；
   计时器就是为了定时清理缓存，抵御该攻击。

### 六、易混关键区分（必记）
1. ICMPv4 ≠ 传输层协议（TCP/UDP），是**网络层协议**；
2. ping 不是独立协议，只是**ICMPv4 回显请求/应答的应用**；
3. ICMP报文可以被分片，分片超时后，**错误反馈依旧走ICMPv4**；
4. 分片攻击的核心原理：利用IP重组机制，耗尽接收方缓存。
