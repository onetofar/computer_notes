# 第8章 深入学习组件式编程

> **小节地图**:§8.1 SystemManager / §8.2 allinone 工程 / §8.3 线程分类 / §8.4 IAwakeSystem 与线程对象池 / §8.5 主动销毁 / §8.6 时间堆 / §8.7 总结——全章精读。**双核:§8.4 对象池从全局变线程、§8.6 定时器从 if 变堆。**

## 8.1–8.2 SystemManager 与 allinone

`SystemManager` 统一管理全部 System 动作与实体注册,并持有一个 **DynamicObjectPoolCollector**(对象池集合,§8.4)——ECS 的「总线」。§8.2 的 allinone 工程把此前分散的 demo 收进一个可执行,验证框架自洽。

## 8.3 线程分类

线程不再是一个大类,按**职责分类**(网络线程/逻辑线程/…)。分类的收益在 §8.4 兑现:**线程内创建的对象不跨线程,对象池就可以不加锁**。

## 8.4 IAwakeSystem 与线程对象池

§5.5 的对象池是**全局单例**——多线程取放集合要加锁(`_freeLock`)。本章升级为**线程对象池**:

- **`DynamicObjectPoolCollector`**:每个 ECS 体系一份,`map<类型, IDynamicObjectPool*>` 集中管理所有类型的池;由 SystemManager 持有;
- 组件创建**全部走线程内对象池**,「以创建方式 new 组件」的操作被**消灭**;
- 线程内对象线程内用 → 锁消失;还附带一个指令**随时查看各线程的全部组件**(池的监控面,§5.5 第二动机的延伸);
- **`IAwakeSystem` 接口**:对象从池里取出后需要的一次性初始化动作,统一走 Awake 而不是各自构造——与 BackToPool(归还时自清,[[第5章 性能优化与对象池|第5章 §5.5]])对称:**取用 Awake、归还 Dispose,池不关心中间过程**。

> 📖 [[第5章 性能优化与对象池|第5章 §5.5]] → 本节的演化方向 = **锁的粒度从「全局集合」缩到「无」**,手段是所有权纪律(谁创建谁使用)而不是更细的锁。

## 8.5 主动销毁

对象生命周期不再只靠归还——提供**主动销毁路径**(Dispose 链),让「该死的对象」立刻可回收。与 BackToPool 的分工:归还 = 回池待复用;销毁 = 从池账本上摘除。框架要两条都支持,否则池只增不减。

## 8.6 时间堆:从「每帧 if」到「O(log n) 触发」

**动机是一个真实的卡死案例**:`HttpRequest` 发出去没有回应,登录流程**永久卡住**——Account 类没办法给客户端反馈。根因:**没有对请求做定时检查**;若开始就定「10s 超时,过期即失败(后到的回应也丢弃)」,问题不存在。类似地,RobotMgr 的定时打印长这样:

```cpp
if (_nextShowInfoTime > TimeTick) return;      // 每帧一次判断
_nextShowInfoTime = AddSeconds(TimeTick, 2);
ShowInfo();
```

每帧一次 if,框架里若有大量这种判断,**性能与优雅双输**。解法是时间堆:

- **二叉小顶堆**,按触发时间排序——最近要到期的永远在堆顶;
- 主循环每帧**只看堆顶**:没到点直接走,到了点弹出执行;插入/删除 O(log n);
- 全框架任意多的定时器,每帧的判断成本恒定 O(1)(看一眼堆顶)。

> 📖 [[第7章 延迟、抖动和可靠性|格雷泽第7章 §7.7]] 的模拟器、[[第8章 改进的延迟处理|第8章]] 的插值/超时,全都依赖「定时器存在且准」;游双系列的同主题:[[5-3 SIGALRM信号高性能定时器——时间轮]](时间轮 vs 最小堆的取舍)、[[5-3-升序链表定时器-linked_scheduled.hpp.md|升序链表定时器]](源码级)。**HttpRequest 超时案例的完整解法 = 定时器 + 「后到的回应也判失败」的语义**——这两条合起来才是「请求有期限」。

**改动地图**:把堆顶判断挪进遍历 = 退化回 O(N) if;定时器回调里做重活 = 阻塞整拍;超时语义允许「迟到的回应被接受」= 卡死案例复活。

## 章末判据

| 决策点 | 判据 |
|---|---|
| 对象池加锁吗 | 线程内用不加锁(所有权纪律);跨线程才付锁价 |
| 一次性初始化 | IAwakeSystem 统一走,构造函数只管不变量 |
| 定时器 | 有期限的异步操作**必须**挂定时器;数量多走堆,每帧只看堆顶 |
| 超时语义 | 后到的回应判失败,不许「迟到即有效」 |

一句话结论:**本章把第 6 章的 ECS 填进两块硬骨头——对象池的线程化(锁的消失)与定时器的堆化(判断的消失);两者共同的方法论:把「每帧人人检查」改成「结构只让该发生的事发生」。**
