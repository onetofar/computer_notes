# 书籍领域 —— 教材的三层结构

一本书进库不是「一篇笔记」，是**三层**。三层各有分工，混在一起会出两类问题：
一是把「我推演的东西」当成「原书写的东西」，二是查原书措辞时找不到出处。

| 层 | 目录 | 是什么 | 谁写 |
|---|---|---|---|
| **原文稿** | `教材原文/<书名>/` | 逐章**机械抽取**的正文，保留原书密度、代码清单与插图 | 脚本抽的，不加判断 |
| **讲义** | `教材讲义/<书名>/` | 把原文稿**彻底本地通俗化**：现象开场 → 白话解释 → 图解 → 实战锚点 | 人读的，带推演标注 |
| **精简** | `教材精简/<书名>/` | 知识点笔记：书里的机制**并进**库内已有笔记的某几节 | 按主题重组，不按章节 |

**三层是并列的，不是替代关系。** 查原书措辞读原文稿；想读懂读讲义；
要按主题串起来读精简。

---

## 三层的分工，说细一点

### 原文稿 = 底稿

从 epub / pdf **机械抽取**的正文，不做净化、不做改写。它的价值是**可回溯**：
讲义和精简里任何一句「书里就是这么说的」，都能指回它某一行。

抽取脚本在 [`markdown/_tools/`](../_tools/README.md)，踩过的坑（`<pre>` 代码被打散、
章节首页的迷你目录、插图图号不在 `<img alt>` 里）都记在那里。

### 讲义 = 写给人看的层

同样是教材内容，但**换一种讲法**。一篇讲义的骨架固定：

```text
第N章 讲义：<钩子标题>
  ├─ 这是什么 / 配套 / 实战锚点 / 诚实声明   （四行头部）
  ├─ 0. 开局
  ├─ N. §X.Y <英文小节名>                  （与原文小节一一对应）
  └─ N. 收尾：本章金句清单
```

**三条纪律**：

1. **自己加的类比必须标 `（推演）`** —— 书里没说的话不能混进原文转述。
   宁可标注「书里没写」，不可让读者去查然后发现对不上。
2. **不编造图号** —— 原书没编号的图（Pearson 把一部分图题存进 `<figcaption>`，
   另一批存成无障碍描述文字）就让它没编号。
3. **§号必须指向它真正覆盖的那一节** —— 见下面的「§-定位器的四种写法」。

### §-定位器的四种写法

讲义的一节不一定刚好等于原文的一节。四种写法各有用处，**但不能混用**：

| 情形 | 写法 | 例子 |
|---|---|---|
| 一节对一节（默认） | `§X.Y` | `§42.2 方案一：fsck` |
| 一节覆盖**连续**几节 | `§A.B–C.D` | `§39.2–39.4 文件系统接口` |
| 原文一节被讲义**拆成多节** | 两节**共用**同一个 §号 | `§44.3 讹误怎么办：校验和` + `§44.3 校验和放在哪：两种布局` |
| 一节覆盖**不连续**的几节 | `§X.Y / §Z.W`（每个号各自带 §） | `§39.9 / §39.13 删除文件与硬链接` |

⚠️ **区间只能用于连续的小节** —— 把不连续的小节写成一个区间
（如 `§39.9–39.13`）会让中间那几节看起来被重复覆盖，查它们的人会扑空。
**带 `§` 的并列写法不是区间**，别把它当区间读。

### 精简 = 按主题重组

按书**章节**组织的知识点笔记。特点是「一章一篇」，但内容是**书里的机制 + 库内已有笔记的落点**合起来的。
