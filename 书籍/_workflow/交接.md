## 1. 流水线是什么

```
epub/pdf  ──epub_to_chapters.py / pdf_to_chapters.py──▶  教材原文/  （锚点层 · 逐字 · 未经净化）
                                                          │
                          ┌───────────────────────────────┴──────────────────┐
                          ▼                                                  ▼
                    教材讲义/  （人读）                              教材精简/  （主题重组 + 行号锚点）
                    现象开场 · 白话 · 实战锚点 · 金句清单              机制 → 为什么重要 → 选型判据
                          │                                                  │
                          └──────────────────┬───────────────────────────────┘
                                             ▼
                                   MOC/教材/<书名>.md  目录表
                                   MOC/教材-MOC.md  书名节点一览
                                   markdown/书籍/README.md  书目表
```

**三层各自的职责**：

| 层 | 谁在读 | 硬要求 |
|---|---|---|
| 原文 | 机器（锚点校验器）+ 想核对细节的人 | **逐字**，一个标点都不能改 |
| 讲义 | 人 | 现象开场 → 白话 → **实战锚点**（挂到 `otf-server` 的真实代码）→ 金句清单 |
| 精简 | 「我只想快速想起这一章说了啥」的人 | 每条断言配**行号锚点** + 结尾**选型判据** |

### 4.3 取引文用 `quote.py`（**不要手抄**）

`markdown/书籍/_workflow/quote.py` —— 把「手抄引文串行」这个错误源从流程里拿掉了。

```bash
cd "C:\Users\wzy\iCloudDrive\iCloud~md~obsidian\onetofar_world\markdown\书籍"

# ① 先列真实标题编号（§ 号不许造，先跑这个）
python3 -I _workflow/quote.py heads "教材原文/Systems Performance/06-Chapter 6. CPUs.md"

# ② 找候选行
python3 -I _workflow/quote.py find "教材原文/Systems Performance/06-Chapter 6. CPUs.md" "<正则>"

# ③ 直接生成可粘贴的锚点表格行（引文从磁盘切片，逐字）

# ④ 字面核验（讲义金句逐条核）
python3 -I _workflow/quote.py grep "教材原文/Systems Performance/07-Chapter 7. Memory.md" "<英文原句>"
```

- `rows` 的 spec：`N`=整行；`N-M`=多行合并；`N:a-b`=第 N 行第 a..b 个字符（**用来切掉句中插进来的脚注号**）
- `rows` 会顺手警告「含竖线 / 以省略号结尾」—— 这两种会破表或破校验

## 5. 四条硬规矩（血泪换来的）

### 5.1 行号**一律**用 `quote.py` / `grep -n` 从磁盘取，**不要信 Read 工具显示的行号**

CIFS 上 Read 会把超长行**重新折行显示** ⇒ 「Read 里看到的行号」和「文件里的真实行号」**差 1–2 行**
⇒ **锚点全部对不上，而且不报错**。
引文跨行时用 `L<a>-<b>` 区间。

### 5.2 引文**逐字**，**不要手抄**

手抄实测会串行（把叙述用语 `worker_queue` 抄成代码里的 `work_queue`）。
**正确做法：用 `quote.py rows` 从磁盘切片，直接生成表格行**，一次全对。
另注：epub 抽取会在句中插脚注号 ⇒ **取脚注号之前的片段**，别「修顺」。

### 5.3 **落盘优先，校验后置**

先把完整文件 **Write 落盘**，再跑校验，再改。
**绝不要在写文件之前反复自我校验；不要写完先 trim 再落盘。**
⇒ 额度耗尽时，文件还在内存里就全丢了。

### 5.4 引文里**不能有** `|`、`<` `>`、`…`

- `|` → 破表格
- `<` `>` → Obsidian 当 HTML 标签吃掉，整句消失（CiA 附录D 满篇都是 `<chrono>` 这种）
- `…` 结尾 → 校验器按「尾部省略」处理，但规约不允许

## 6. Windows 侧的坑（本轮踩的）

| 坑 | 说明 |
|---|---|
| **Python stdout 是 GBK** | 中文输出到管道会变乱码，**看起来像文件编码坏了**（其实是显示问题，文件全是 UTF-8）。脚本里加 `sys.stdout.reconfigure(encoding="utf-8")` |
| **`python3 -c` 传中文会坏** | 命令行里的中文字面量被弄坏 ⇒ 匹配不到。要跑逻辑就 **写成 .py 文件再执行** |
| **`grep "中文"` 也会坏** | 模式串被弄坏 ⇒ 静默「无匹配」。查中文一律用 python 脚本 |
| **`-I` 会忽略 `PYTHONIOENCODING`** | `-I` = 隔离模式 = 忽略所有 `PYTHON*` 环境变量 ⇒ 靠环境变量治不了 stdout 编码，得进脚本改 |
| **文本模式写回会把 LF 变 CRLF** | `update_nodes.py` 写 MOC 时必须 `newline="\n"`，否则整个索引文件 diff 全红 |
| **heredoc 里的中文路径** | 一律改用相对路径 + `cd` 进目录，或用 python 脚本处理 |
| **后台 agent 会被中断** | 父会话一轮结束时，正在跑的子 agent 会被 **canceled**（文件可能落了一半）。⇒ **一轮里把 agent 跑完再退出**；中断后先看磁盘再重派 |

## 7. 其它坑

| 坑 | 说明 |
|---|---|
| **429 Token Plan 上限** | 是**共享池**上限。**并发 4–6 安全，10–13 会炸**。炸掉的 agent 可能已经把文件落盘了 —— **先看磁盘再重派** |
| **CIFS 陈旧缓存** | 写完必须用 Read **重读一遍**；`/mnt/kb` 上「改动没生效」先疑缓存 |
| **不要在 `/mnt/kb` 里跑 git** | 慢 + 锁问题。vault 的 gitdir 指向 `F:/BaiduSyncdisk/...`，**WSL 侧根本够不着** ⇒ **git 恢复不了 vault 文件**。提交在 **Windows 侧**做 |
| **讲义的金句不能有 `<` `>`** | Obsidian 会把尖括号当 HTML 标签吃掉 |
| **原文稿里的 § 编号不能造** | 先 `quote.py heads` 取真实编号。**原书自己会跳号**（SP §8.6 从 15 跳到 17）—— 照抄，别补造 |
| **SP 附录只有一级标题** | 定位器写 `§附录 A`，**不要**编 `§A.1` |
| **CiA 附录 D 有字母编号子节** | `§D.1`–`§D.7`、`§D.1.1` 等**真实存在**（与附录 B/C 不同） |
| **有些 epub 是试读本** | Packt Early Access 只有 1 章 —— 抽取结果会少章，别当成抽取 bug |
| **实战锚点的仓库在 Windows 上** | `F:\game_project\otf-server`（不是 `/home/xier/dev/game-project/otf-server/`） |
| **引用仓库代码不许加工** | 讲义里引 `文件:行号` 时，**代码块必须逐字等于仓库那一行** —— 不许加自己写的行尾注释；仓库的中文句号 `。` 不要写成 ASCII `.` |
