## 1. 你要做的事

- 输入：原文稿 `/mnt/kb/markdown/书籍/教材原文/<书名>/<原文稿文件名>.md`
- 输出：`/mnt/kb/markdown/书籍/教材精简/<书名>/<原文稿 basename 去数字前缀>.md`
- **一篇原文稿 = 一篇精简笔记。** 只写派给你的那一篇。

### 动手第一步：列真实标题编号

```bash
grep -n "^#\{1,5\} " "/mnt/kb/markdown/书籍/教材原文/<书名>/<原文稿文件名>.md"
```

把真实的 § 编号抄下来。**原文里没有的编号一律不许造**
（实测踩过：编了一个原文不存在的 `§11.3.3.1`）。

| 书 | §-定位器形式 |
|---|---|
| CiA 正文 | `§5.1`、`§5.1.2`（原文稿里是 `#### 5.1. …` 与 `##### 5.1.2. …`） |
| CiA 附录A | `§A.1`、`§A.4.2`（**字母编号**） |
| CiA 附录B/C/D | `§附录 B`（原文稿里是 `# Appendix B. …`，**只有一级标题，没有子节**） |
| SP | `§6.2.1`（原文稿里是 `#### 6.1 …`、`##### 6.2.1 …`） |
| SP 附录 | `§附录 A`（原文稿里是 `# Appendix A： …`，**只有一级标题**） |

### 动手第二步：抽锚点

- **12–20 条**，挑**承重的机制性句子**，不要挑铺垫和例子。
- 第 2 列：`<原文稿文件名>.md L<行号>` —— 文件名**照抄**（含 `附录A-` 这种前缀），
  行号用 `grep -n` 在**原文稿文件本身**上取，**不要手数**。
- ⚠️⚠️ **不要信 Read 工具显示的行号**（2026-11-02 实测踩坑）：
  CIFS 上 Read 会把超长行**重新折行显示**，于是「Read 里看到的行号」和
  「文件里的真实行号」会差 1–2 行 ⇒ 锚点全部对不上。
  ⇒ **行号一律用 `grep -n` / 脚本从磁盘取**；引文跨行时用 `L<a>-<b>` 区间。
- 第 3 列：**逐字**等于原文那一行（只允许空白差异）。
  - 不加 `**`、不改标点、不加注解。
  - 不能出现 `|`（会破表格），不能用 `…` 结尾。
  - 脚注号会插在句中（epub 副作用）⇒ **取脚注号之前的片段**，别「修顺」。
  - ` ’ ` ` “ ` 是 epub 排版产物，**照抄**。
- 引文**跨原文行断点**时不要硬凑一行 —— 挑单行可命中的句子。

### 动手第三步：写正文

- **中文讲**，引文**英文照抄**。
- 每节先给一段「这段在讲什么机制」，再给「它为什么重要 / 容易错在哪」。
- 自己的类比要标 **（推演）**。
- 代码用 ```cpp 围栏，**照抄原文**，不要自己改写。
- **精简层不写实战锚点**（那是讲义的事）。
- 结尾 `## 章末选型判据`：**几条可执行的判断**，不是复述小结。

## 2. 校验（落盘之后才做）

```bash
cd /mnt/kb && python3 -I markdown/_tools/kb_anchor_check.py "markdown/书籍/教材精简/<书名>/<输出文件名>.md"
```

- 必须**一条 ✗ 都没有**。有 ✗ 就按提示改。
- ⚠️ `kb_anchor_check.py` 与别人共用，**别改那个脚本**，改自己的笔记。
- 写完用 Read 工具**重读一遍**（CIFS 缓存会骗你），确认无乱码、无半截句子、frontmatter 闭合。
