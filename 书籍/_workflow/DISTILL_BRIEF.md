# 教材精简层写作规约（知识点笔记 · 必须带行号锚点）

## 0. 这层是什么

`markdown/书籍/教材精简/<书名>/<章名>.md` —— **知识点笔记**。
它不是原文的搬运，是**按主题重组**的「这一章到底说了哪些机制、我该怎么用」。
每一句「书里就是这么说的」都带**行号锚点**，读者能逐字回查。

> **三条层各管一件事**（见 `markdown/书籍/README.md`）：
> - **原文稿** = 事实底座（谁说了什么、代码长什么样）—— 机械抽取，未经净化
> - **讲义** = 解释层（写给人看，牺牲密度换理解）—— 你的同事读这个
> - **精简** = 知识层（主题重组 + **可复核的出处**）—— **索引/回查的人读这个**

## 3. 正文骨架

```markdown
# <章名>

> **小节地图**：<本篇覆盖哪些 §、哪些不立篇及理由、底层依赖指向哪篇>

## 0 · 原文锚点（逐条可回查）

下面每条给出「本篇小节 → 原文位置 → 该处原文逐字摘录」。摘录一字不改，
用 `kb_anchor_check.py` 可以把每条引文回查所在行；对不上就是这里错了。

| 本篇小节 | 原文位置 | 该处原文（逐字摘录） |
|---|---|---|
| §6.2.1 CPU Architecture | 06-Chapter 6. CPUs.md L97 | <该行原文，逐字> |

## <§号> <小节标题>
...

## 章末选型判据
...
```

## 4. 锚点怎么写（**必须严格**）

- **原文位置**列 = `<原文稿文件名>.md L<行号>`（**不带** `.md` 之外的路径；可写 `L12-34` 区间）。
  - 文件名**照抄**原文稿目录下的真实文件名（含数字前缀，如 `06-Chapter 6. CPUs.md`）。
  - 行号用 `grep -n` 在**原文稿文件本身**上取，**不要手数**。
- **第三列的引文必须逐字等于原文那一行**（允许 markdown 规范化：忽略空白差异）。
  - 校验器会把第三列的文本拿去在原文对应行里做**子串匹配**（去掉所有空白后比）。
  - ⇒ **引文里不要加 `**` 加粗、不要改标点、不要加 `（译）」之类的注解**。
  - 需要注解就另起一段写，别塞进引文列。
  - 引文里不能出现 `|`（会破表格），也不能用 `…` 结尾（校验器会去掉尾部省略号再比对）。
- 一篇 **12–20 条**锚点。挑**承重的机制性句子**，不要挑铺垫和例子。
- 校验器会检查**每一行**里的锚点 ⇒ 表格里的 `§` 列别写成 `.md L123` 的样子。
- ⚠️ **脚注号会插在句中**（epub 抽取的副作用，如 `noexcept(true) 9 ,`）。
  遇到这种行，**取脚注号之前的片段**作引文，别自己「修顺」——修了就对不上。
- ⚠️ 原文稿里 ` ’ ` ` “ ` 是 epub 的排版产物，**照抄**（校验器会归一化比对）。

## 4b. §-定位器按书不同（**别混用**）

| 书 | 定位器形式 | 注意 |
|---|---|---|
| EMC++ | `§Item N` / `§Case N` | **章号不叫 §5** —— 写「第5章」。`§Item 24` 才是定位器 |
| CiA | `§5.1` / `§5.1.2` | 原文稿里是 `#### 5.1. …` 与 `##### 5.1.2. …` |
| CiA 附录A | `§A.1` / `§A.4.2` | 原文稿里是 `#### A.1. …` 与 `##### A.4.2. …`（**字母编号**） |
| CiA 附录B/C/D | `§附录 B` | 原文稿里是 `# Appendix B. …`（**只有一级标题，没有子节**） |
| SP | `§6.2.1` | 原文稿里是 `#### 6.1 …`、`##### 6.2.1 …` |
| SP 附录 | `§附录 A` | 原文稿里是 `# Appendix A： …`（**只有一级标题**） |

- **动手前先 `grep -n "^#\{1,5\} " 原文稿` 把真实标题编号列出来**，照抄，别猜。

- **原文里没有的编号一律不许造**（实测踩过：讲义写了 `§11.3.3.1`，原文 11.3.3 下只有
  无编号的子标题 ⇒ 编造）。
- 讲义自己的编号（`### 8.0`）**不带 §**。

## 5. 正文怎么写

- **中文讲**，引文**英文照抄**（书是英文原版）。
- 每节先给一段「这段在讲什么机制」，再给「它为什么重要 / 容易错在哪」。
- 自己的类比要标 **（推演）**。
- 代码用 ```cpp 围栏，**照抄原文**，不要自己改写。
- **精简层不写实战锚点**（那是讲义的事）—— 但可以写「本机制在库里哪篇笔记里被用了」。
- 结尾 `## 章末选型判据`：**几条可执行的判断**（什么情况下用哪个 / 什么时候别用），
  不是复述小结。

## 6. 校验（每篇写完都要做）

> ⚠️⚠️ **落盘优先，校验后置**（2026-11-02 实测踩坑）：
> 有一批 agent 死在「反复校验 → trim → 改写」的路上，**额度耗尽时文件还在内存里，全丢了**。
> ⇒ **正确顺序：先 Write 落盘 → 再跑校验 → 再改**。
> **绝不要**在写文件之前反复自我校验；**也不要**写完先 trim 再落盘。

```bash
cd /mnt/kb && python3 -I markdown/_tools/kb_anchor_check.py "markdown/书籍/教材精简/<书名>/<章名>.md"
```

- 必须**一条 ✗ 都没有**。
- 有 ✗ 就按提示改（多半是行号错了或引文没逐字）。
- ⚠️ `kb_anchor_check.py` 与别的 agent **共用**，**别改那个脚本**，改自己的笔记。
- ⚠️ **新精简笔记不会被自动挂载** —— `MOC/教材/<书名>.md` 的目录表里要有它的行，
  否则 `kb_health.py` 会报「孤儿笔记」。写完确认那一行已在位。
- ⚠️ CIFS 上**写完必须 Read 一遍**再交付（缓存会骗你），确认无乱码、无半截句子。
