## 原理

### 问题：客户端判定 vs 服务器裁决的时间差

```
t0  客户端开火，屏幕上 Boss 面朝左（这是快照 A 与 B 插值出来的画面）
t0+½RTT  HitReport 到达服务器，此时服务器记录的 Boss 面朝右
         → 用"当前朝向"校验 IsExposed(头, 右) = 假 → 合法命中被丢弃
```

现象不是崩溃，是**"明明砍中了，服务器说没打中"**。
大部分时候是对的，偶发丢命中——**这类 bug 极难定位**，
因为复现需要刚好在转向的那半秒里出手。

### 最小实现：单快照回退

格雷泽 §8.4「服务器端回退」：命中判定不是"按现在算"，而是
**回退到客户端开火那一刻**去算。客户端在命中包里带：

- `snapshot_tick:u32` —— 当时正在**向哪个快照插值**
- `interp_t:u16` —— 插值进度，定点 [0,1000]（0=还在上一帧，1000=已到下一帧）

服务器保留最近 N 个 tick 的远端位姿，按 `(snapshot_tick, interp_t)`
**插值出那一刻的位姿**，再做 `IsExposed` 校验。

**为什么这两个字段就够了**：这是**单快照回退**，不是完整时间回滚。
需要回退的只有"我看见的远端长什么样"，而那个画面本来就是两个快照插值出来的——
客户端报出插值进度，服务器就能精确复现。

**玩家自己不需要回退**：玩家的位置由服务器按输入积分，服务器说了算。
**服务器要保存的状态因此只有"最近 200ms 的远端位姿"**，
而不是整个世界的历史。这是"最小实现"三个字的含义。

## 成立条件 / 失效边界

| 条件 | 说明 |
|---|---|
| 客户端与服务器对"画面是怎么来的"有**共同模型** | 同一套插值算法、同一组快照。模型不一致 = 回退算出的位姿与客户端看到的不一样 |
| 服务器保留的位姿窗口 **≥ 客户端可能的插值滞后** | 窗口太短 → 回退不到 → 退化成"用当前状态算" |
| 只有**远端实体**需要回退 | 自己的实体由服务器积分，天然一致 |
| 超出窗口的命中有降级路径 | 按当前位姿算，而不是丢弃——**丢弃会让弱网玩家完全打不动** |

## 明确拒绝的做法

| 做法 | 为什么拒绝 |
|---|---|
| 命中包只带 `client_tick`，服务器不回退 | `client_tick` 是**客户端自己的**时间轴，服务器没有对应的历史状态可查（除非也保存全历史） |
| 完整时间回滚重放 | 需要保存整个世界的历史 + 重放所有系统。本项目是单 Boss PvE，收益不抵成本 |
| 回退失败就丢弃命中 | 弱网玩家会"完全打不动"，从手感问题升级成不可玩 |
| 客户端上报"我打中的是哪个部位"就信 | 那是**上报权威状态**。回退校验是为了在信任之前先验证几何上确实打得到 |

## 易错点

- **`client_tick` 与 `snapshot_tick` 是两个不同的东西**。前者是"我什么时候出的手"，
  后者是"我当时在向哪张图插值"。**只有后者能定位到服务器的历史状态**。
- **回退的是"位姿"，不是"状态"**。只需要 Boss 的位置和朝向，
  不需要回退它的血量/仇恨/AI 计时器。**把回退范围放大会让成本翻好几倍**。
- **回退依赖共同模型**：客户端插值算法和服务器复现算法必须一致。
  客户端改了插值方式而服务器没跟上，回退会算出错误的位姿——
  **症状是"命中判定乱飞"**，且只在网络有延迟时出现。
