## 机制

### 会话骨架：主对等体与三种握手响应（§6.3 开头 / §6.3.1）

- P2P 下**没有代码分离**：所有对等体跑同一个可执行文件（对照姊妹篇 C/S 的三目标分离）。
- **主对等体（master peer）**只管两件事：向新对等体提供已知对等体的 IP 列表；**唯一地分配玩家 ID**（防两个对等体同时接纳新人的 ID 竞争）。它**不是**权威服务器——每个对等体都存全量状态，主断线游戏照样继续。命令行同 exe：`RoboCatRTS 45000 John`（主）/ `RoboCatRTS 127.0.0.1:45000 Jane`（成员，指定主地址只是连接更快）。
- `HELO` 的三种应答：`WLCM`（自己 ID + 主 ID + 现有人数 + **所有对等体的名字和 IP**）/ `NOJN`（已开局或满员）/ `NOMP`（你不是主，附主地址 → 重发）。收到 welcome 还没完——新对等体要向其他所有对等体发 `INTR`（介绍包），把自己的 ID+名字登记进每人的玩家表。
- **局域网地址陷阱**：主对等体把自己的局域网地址（192.x.x.x）发给了外网新对等体 → 连不上。解法阶梯：NAT 穿越 / **集中服务器（rendezvous server）**只做初始化地址交换 / 中央路由服务器（所有包经服务器转发，对等体互相不知道公网 IP——顺便防了对等体间的 DDoS）。
- 开始：主发 `STRT` → 全员 3 秒倒计时。计时器不补延迟，主总先开局——锁步下不影响同步，只是主可能空等；改进法：每个对等体从倒计时里减去自己到主的 **RTT/2**。

### 锁步节奏与命令语义（§6.3.2）

- 帧率锁定 30 FPS（Δt≈33ms = **子轮**），3 子轮 = 1 轮 = **100ms**，每秒 10 轮。轮/子轮长度按网络条件动态调整是帝国时代论文的课题，教学代码不调。
- **命令 ≠ 输入**：点选一只猫不影响状态 → 不是命令；右键移动/攻击影响状态 → 是命令。
- 第 x 轮的命令在第 **x+2** 轮执行：正常情况命令延迟高达 **200ms**，但延迟一致，RTS 不受影响。游戏从第 **−2** 轮开始，头 200ms 没有命令执行——这是锁步的固有属性，不是 bug。

命令是继承结构 + 工厂：

```cpp
class Command
{
public:
    enum ECommandType { CM_INVALID, CM_ATTACK, CM_MOVE };
    //given a buffer, will construct the appropriate command subclass
    static shared_ptr<Command> StaticReadAndCreate(
                               InputMemoryBitStream& inInputStream);
    virtual void Write(OutputMemoryBitStream& inOutputStream);
    virtual void ProcessCommand() = 0;
protected:
    virtual void Read(InputMemoryBitStream& inInputStream) = 0;
    ECommandType mCommandType;
    uint32_t mNetworkId;
    uint32_t mPlayerId;
};
```

`MoveCommand::StaticCreate` 在**发起端**验证（对象存在、是猫、`GetPlayerId() == 我的 ID`）；`ProcessCommand` 在**执行端**再验一遍（同样的三条件）——网络来的命令不盲执行，[[15-格雷泽-网络安全四层]] 的归属验证在这里落两道。

轮数据包的组装与推进：

```cpp
void NetworkManager::UpdateSendTurnPacket()
{
    mSubTurnNumber++;
    if (mSubTurnNumber == kSubTurnsPerTurn)
    {
        //create our turn data
        TurnData data(mPlayerId,
                      RandGen::sInstance->GetRandomUInt32(0, UINT32_MAX),
                      ComputeGlobalCRC(),
                      InputManager::sInstance->GetCommandList());

        OutputMemoryBitStream packet;
        packet.Write(kTurnCC);
        //we're sending data for 2 turns from now
        packet.Write(mTurnNumber + 2);
        packet.Write(mPlayerId);
        data.Write(packet);

        for (auto &iter: mPlayerToSocketMap)
            SendPacket(packet, iter.second);

        //save our turn data for turn + 2
        mTurnData[mTurnNumber + 2].emplace(mPlayerId, data);
        InputManager::sInstance->ClearCommandList();

        if (mTurnNumber >= 0)
            TryAdvanceTurn();
        else
        {   //a negative turn means there's no possible commands yet
            mTurnNumber++;
            mSubTurnNumber = 0;
        }
    }
}
```

```cpp
void NetworkManager::TryAdvanceTurn()
{
    //only advance the turn IF we received the data for everyone
    if (mTurnData[ mTurnNumber + 1 ].size() == mPlayerCount)
    {
        if (mState == NMS_Delay)
        {
            //throw away any input accrued during delay
            InputManager::sInstance->ClearCommandList();
            mState = NMS_Playing;
            //wait 100ms to give the slow peer a chance to catch up
            SDL_Delay(100);
        }

        mTurnNumber++;
        mSubTurnNumber = 0;

        if (CheckSync(mTurnData[mTurnNumber]))
        {
            //process all the moves for this turn
            for (auto& iter: mTurnData[mTurnNumber])
                iter.second.GetCommandList().ProcessCommands(iter.first);
        }
        else
        {
            //for simplicity, just end the game if it desyncs
            Engine::sInstance->SetShouldKeepRunning(false);
        }
    }
    else
    {   //don't have all player's turn data, we have to delay
        mState = NMS_Delay;
    }
}
```

- `mTurnData[轮号][玩家ID]` 双下标映射 → "轮 x 的数据是否**到齐**"是一次 `size() == mPlayerCount` 判断。
- 缺数据 → `NMS_Delay`：世界冻结、新到包重试推进；恢复时**丢掉延迟期间的本地输入**再等 100ms 给慢对等体追平。
- 丢包补救：延迟时定位缺谁 → 定向重传请求 → 几次不睬就放弃该对等体；后续轮包**捎带**旧轮数据兜底。

### 双校验：PRNG 心跳 + 全局 CRC（§6.3.3）

**PRNG 同步两个必要条件**：①全员相同种子（主对等体选好随 `STRT` 下发）；②每轮**调用次数、顺序、位置**完全一致——调用次数不同照样分叉。第三件事是 `rand()/srand()` 根本不可用：C 标准不规定算法，跨平台/编译器结果不同、熵不可信。解法 = C++11 `<random>` 的 MT19937（周期 2^19937）：

```cpp
class RandGen
{
public:
    static std::unique_ptr<RandGen> sInstance;
    static void StaticInit();
    void Seed(uint32_t inSeed);
    std::mt19937& GetGeneratorRef() {return mGenerator;}
    float GetRandomFloat();
    uint32_t GetRandomUInt32(uint32_t inMin, uint32_t inMax);
    int32_t GetRandomInt(int32_t inMin, int32_t inMax);
    Vector3 GetRandomVector(const Vector3& inMin, const Vector3& inMax);
private:
    std::mt19937 mGenerator;
    std::uniform_real_distribution<float> mFloatDistr;
};

uint32_t RandGen::GetRandomUInt32(uint32_t inMin, uint32_t inMax)
{
    std::uniform_int_distribution<uint32_t> dist(inMin, inMax);
    return dist(mGenerator);
}
```

- `random_device` 只拿来产**启动**种子，设备本身不当生成器。
- **PRNG 心跳**：每轮结束每人生成一个随机数随 `TurnData` 发出——`CheckSync` 逐轮比对，生成器分叉当场现形。
- 不影响游戏状态的随机（如模拟丢包）**另开一个生成器**——否则全员同刻模拟丢包。多生成器需要团队纪律：谁在哪儿必须用哪一个，要写清楚。

**状态 CRC**：每轮末对整个游戏状态算 CRC32（zlib `crc32`，已在依赖里）。`ComputeGlobalCRC` 按网络 ID **升序**遍历对象，各自 `WriteForCRC` 写入比特流再整体计算：

```cpp
uint32_t NetworkManager::ComputeGlobalCRC()
{
    OutputMemoryBitStream crcStream;

    uint32_t crc = crc32(0, Z_NULL, 0);
    for (auto& iter: mNetworkIdToGameObjectMap)
        iter.second->WriteForCRC(crcStream);

    crc = crc32 (crc, reinterpret_cast<const Bytef*>
                              (crcStream.GetBufferPtr()),
                              crcStream.GetByteLength());
    return crc;
}
```

- 不是每个变量都进 CRC：猫写入的是控制者 ID/网络 ID/位置/血量/状态/目标 ID；投掷冷却这类计时变量**不写**。
- CRC 可增量计算——理论上可以做一个"只算 CRC 不存缓冲"的流接口；教学代码为简洁复用 `OutputMemoryBitStream`。
- 浮点是另一半确定性风险：SIMD 指令与标量结果可能不同、IEEE 754 严格模式可被编译/运行时开关改变——确定性要管到硬件层。

## 成立条件与失效边界

| 条件 | 满足则 | 不满足则 |
|---|---|---|
| 确定性可控（同 PRNG 实现、同浮点策略、稳定遍历序） | 锁步成立，带宽 = 命令率 | 任一破 → CRC 心跳立刻报警，游戏只能退出或回滚重写 |
| 玩家少（4 人级） | 全连接 O(n²) 无所谓、轮数据到齐易判断 | 人数上去 → 全连接与"全员到齐才推进"同时崩 |
| 丢包率低 | 延迟态偶发，重传请求能兜住 | 高丢包 → 频繁冻结体验崩坏；这也正是动作游戏不用锁步的原因之一 |
| 命令影响状态、选择不产生命令 | 轮包带宽可控 | 输入粒度过粗（连续瞄准）→ RTS 形状不成立，转状态同步 |

## 原文证据

> "为了解决这个问题，《帝国时代》的工程师决定同步每个玩家的命令，而不是同步单元。"（§1.3；本篇是其实现展开）

> "如果当前是第 x 轮，并且已经收到第 x+1 轮的所有数据，那么 TryAdvanceTurn 将推进到第 x+1 轮。如果第 x+1 轮的有些数据丢了，那么网络管理器将进入延迟状态。"（§6.3.2）
