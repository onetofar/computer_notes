# G1(Garbage-First) 垃圾收集器 深度全解
## 🎯 G1 核心定位与前世今生
G1 是 HotSpot 虚拟机**面向服务端大堆**的全区域垃圾收集器，核心设计目标是**可预测的停顿时间+均衡吞吐量**，是 CMS 的官方替代者，彻底解决 CMS 内存碎片、并发模式失败等痛点。
- 别名：**垃圾优先收集器（Garbage-First）**
- 定位：JDK7u4 引入实验性支持，JDK8u40 稳定可用，JDK9 成为默认收集器
- 核心搭档：**自身独立完成全堆回收**，无需搭配新生代收集器，打破传统分代物理隔离
- 核心价值：首次实现**大堆下可控STW**，兼顾低延迟、无内存碎片、高吞吐，适配现代服务8G+大堆场景
## ⚙️ G1 完整工作流程（核心阶段）
### 🔹 初始标记（Initial Mark）
- 执行方式：**STW 单线程执行**，**借用Minor GC同步完成**，无额外独立停顿
- 核心任务：仅标记 **GC Roots 直接关联** 的对象，标记为灰色并入队
- 执行逻辑：
  - 枚举GC Roots（线程栈、寄存器、静态变量、JNI引用）
  - 仅处理直接引用对象，不递归扫描，速度极快
- 核心特点：
  - 停顿时间微秒级，几乎无感知
  - 开启SATB写前屏障，开始捕获并发期间的引用变更
- 关联三色标记：初始化灰色队列，启动三色标记流程
### 🔹 并发标记（Concurrent Mark）
- 执行方式：**与用户线程并发运行，无STW**
- 核心任务：遍历全堆对象图，递归标记所有存活对象，统计每个Region存活对象数量
- 执行逻辑：
  - 从灰色队列出发，扫描引用字段，白色→灰色→黑色
  - 触发**SATB写前屏障**，捕获所有即将被覆盖的旧引用，存入SATB队列
  - 并行扫描每个Region的RSet，处理跨Region引用
- 关联核心机制：
  - SATB写前屏障：保留GC初始快照，从源头杜绝漏标
  - RSet记忆集：精准定位跨Region引用，无需扫描全堆
- 核心特点：
  - 耗时较长但无停顿，与业务线程并行
  - 实时统计Region回收价值，为筛选回收做准备
### 🔹 最终标记（Final Mark）
- 执行方式：**STW 多线程执行**，停顿极短（毫秒级）
- 核心任务：处理SATB队列剩余对象，完成最终标记，修正并发标记误差
- 执行逻辑：
  1. 暂停用户线程，杜绝引用变更
  2. 必扫GC Roots，补全根引用变更
  3. **仅处理SATB队列中残留的旧引用**，无全堆扫描
  4. 完成所有存活对象标记，计算每个Region的回收收益
- 核心特点：
  - STW严格可控，远短于CMS Remark
  - 仅处理SATB队列，扫描范围固定、开销极低
### 🔹 筛选回收（Cleanup + Evacuation）
#### 	子步骤
```
   1. `**复制**：把 Region 里的存活对象复制到新 Region`
   2. `**记录转发地址**：在旧对象头记录「我被搬到新地址了」`
   3. `**更新所有引用**`
      - `扫描当前 Region 的引用`
      - `扫描 RSet 记录的跨 Region 引用`
      - `扫描 GC Roots 引用`
      - `**全部直接修改为新对象地址**`
   4. `**释放**：旧 Region 直接清空回收`
```
因为**用户线程是暂停的**，没有任何并发修改，所以引用更新**不会出错、不会遗漏、一步到位**。
- 执行方式：**STW 多线程并行执行**，核心回收阶段
- 核心任务：按**回收价值排序**，选择收益最高的Region执行回收，无全堆回收
- 执行逻辑：
  - 筛选：优先选择存活对象少、垃圾占比高的Region（垃圾优先）
  - 复制：将选中Region的存活对象，复制到空Region中
  - 清除：直接清空原Region，释放整块内存
  - 整理：复制过程天然完成内存整理，无碎片
- 核心特点：
  - 部分回收而非全堆回收，STW时长可控
  - 复制算法保证内存连续，彻底解决碎片问题
  - 多线程并行，回收效率极高
## 🛡️ G1 底层核心实现
### 🔹 SATB写前屏障（解决并发漏标，核心优于CMS）
```c++
// 全局SATB队列（集中存储漏标风险引用）
SATBQueue satb_global_queue;
// G1 SATB写前屏障（赋值操作执行前触发）
void g1_pre_write_barrier(oop* field, oop new_ref) {
    // 第一步：捕获即将被覆盖的旧引用（SATB核心）
    oop old_ref = *field;
    // 旧引用非空，加入SATB队列，作为临时GC Roots
    if (old_ref != nullptr) {
        satb_global_queue.push(old_ref);
    }
    // 第二步：执行真实的引用赋值操作
    *field = new_ref;
}
```
### 🔹 最终标记阶段SATB队列处理逻辑
```c++
void g1_final_mark_phase() {
    // 1. 极短STW暂停用户线程
    stop_all_user_threads();
    // 2. 必扫GC Roots
    scan_gc_roots();
    // 3. 仅处理SATB剩余队列（无全堆扫描，G1核心优势）
    while (!satb_global_queue.is_empty()) {
        oop obj = satb_global_queue.pop();
        // 以旧引用为根，递归标记白色对象
        mark_object(obj);
    }
    // 4. 统计Region存活数，计算回收价值
    calculate_region_live_data();
    // 5. 重置SATB队列，恢复用户线程
    satb_global_queue.clear();
    resume_all_user_threads();
}
```
### 🔹 RSet记忆集与跨Region引用处理
- 核心作用：**每个Region独立维护RSet**，记录其他Region对当前Region的引用
- 实现逻辑：
  - 写屏障拦截跨Region引用，实时更新RSet
  - 回收单个Region时，仅扫描RSet即可找到所有外部引用
  - 无需扫描全堆，大幅缩小扫描范围
- 对比CMS：RSet比卡表更精细，支持Region级精准回收，彻底摆脱分代限制
### 🔹 Region分区设计
- 堆内存被划分为**大小相等的Region**（1MB~32MB，2的幂次）
- 每个Region可动态扮演：Eden、Survivor、Old、Humongous（大对象）
- 无物理分代边界，逻辑分代，灵活调整各代区域大小
- 大对象直接存入Humongous Region，避免碎片，支持超大对象分配

## ✅ G1 核心优点
1. **可控的停顿时间**
   - 支持通过`-XX:MaxGCPauseMillis`设置目标停顿时间
   - 筛选回收只扫高价值Region，STW严格可控，打破大堆停顿不可控魔咒
2. **无内存碎片**
   - 回收阶段采用**复制算法**，存活对象规整复制，天然无碎片
   - 彻底解决CMS标记-清除的碎片痛点，杜绝大对象OOM
3. **全堆独立回收**
   - 无需搭配ParNew等新生代收集器，一体化设计，简化GC架构
   - 逻辑分代，动态调整Region角色，适配复杂对象生命周期
4. **SATB算法更优**
   - 写前屏障从源头保留快照，最终标记仅处理队列，无全堆重扫
   - STW更短、更稳定，远优于CMS增量更新
5. **大对象友好**
   - 专属Humongous Region存储大对象，避免大对象分配失败
   - 大堆（8G+）下性能远超CMS

## ❌ G1 核心缺点
1. **额外内存/CPU开销**
   - 需维护每个Region的RSet，内存占用高于CMS
   - SATB写屏障、RSet更新增加CPU开销，小堆下性能略逊于CMS
2. **浮动垃圾更多**
   - SATB快照机制会保留更多并发期间变垃圾的对象
   - 需预留更多内存空间，避免并发回收失败
3. **调优复杂度更高**
   - 涉及Region大小、停顿目标、混合回收阈值等参数
   - 新手调优难度高于CMS
4. **小堆优势不明显**
   - 堆内存<4G时，额外开销抵消低延迟优势，不如CMS/Parallel

## 🎯 G1 核心调优参数
- `-XX:+UseG1GC`：开启G1收集器（JDK9+默认）
- `-XX:MaxGCPauseMillis=200`：设置目标最大停顿时间（核心参数）
- `-XX:G1HeapRegionSize`：设置Region大小（1MB~32MB，2的幂次）
- `-XX:InitiatingHeapOccupancyPercent`：堆使用率达到阈值触发并发标记（默认45%）
- `-XX:G1MixedGCCountTarget`：混合回收执行次数，控制回收压力
- `-XX:ParallelGCThreads`：STW阶段并行GC线程数
- `-XX:ConcGCThreads`：并发标记阶段GC线程数

## 🎯 最终总结
1. G1是**面向大堆、可控停顿**的现代化全堆收集器，完美替代CMS
2. 核心设计：**Region分区+SATB写前屏障+RSet记忆集**，从架构上解决CMS缺陷
3. 流程极简：初始标记→并发标记→最终标记→筛选回收，两次短STW
4. 算法优势：**SATB优于增量更新**，复制算法杜绝碎片，筛选回收控制停顿
5. 核心Trade-off：用少量内存/CPU开销，换取**低延迟+无碎片+高吞吐**的均衡体验
6. 生产定位：JDK8+服务端首选，适配8G+大堆，互联网/金融核心业务标配
