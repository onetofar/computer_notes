# 第2章 信息的表示和处理
## 🧩 顶层核心【对应全书第2章 信息的表示和处理 总纲】
### 核心主线
- 计算机中所有信息（整数、浮点数、字符串、代码）的底层，都是二进制位的编码；所有程序的运算，本质都是二进制位的操作
### 核心价值
- 彻底理解Java基本类型的底层编码规则、运算陷阱、精度问题的根源，从底层规避开发中的数值类bug
### 核心前提
- 所有编码规则，都严格遵循IEEE 754浮点数标准、二进制补码整数标准，是跨平台、跨语言的通用底层规则
## 🧱 基础层：位、字节、整数编码【对应 2.1 信息存储 + 2.2 整数表示】

> **CSAPP 核心哲学**（原书 §2.1）："Information is Bits + Context"——计算机中所有信息（整数、浮点数、字符串、代码、指针）的底层都是一串二进制位，**相同位模式在不同上下文中含义完全不同**。例如，32位模式 `11000001110100000000000000000000` 在 `int` 上下文中表示 `-1,040,187,392`，在 `float` 上下文中表示 `-24.0`。这种上下文依赖性是所有类型转换、内存解读、安全漏洞的根源。

### 1. 基础单位定义
- 位（bit）：计算机最小存储单位，取值0/1
- 字节（Byte）：8位，内存最小可寻址单位（原书 §2.1：绝大多数系统的最小寻址单元）
- 字长（Word Size）：指针的标称大小，决定虚拟地址空间上限
  - 32位 → 4GB 虚拟地址空间（2³² bytes）
  - 64位 → 理论上 2⁶⁴ bytes（实际 x86-64 仅用低 48 位，即 256TB）
  - **C 语言关联**：`sizeof(void*)` 返回字长，`int32_t`/`int64_t` 提供固定宽度类型（原书 Figure 2.3）

### 2. 进制表示规则
- 二进制表示：4位二进制 = 1位十六进制，是底层编码的核心
- 十六进制表示
  - 标识：以 `0x` 或 `0X` 开头（C 语言标准）
  - 十进制→十六进制：反复除以 16，余数从低到高排列（原书 §2.1.1 示例：314156₁₀ → 0x4CB2C）
  - 十六进制→十进制：每位乘以 16 的对应幂次求和
  - **快速技巧**：记 A=10, C=12, F=15，B/D/E 可相对推算（B=11=A+1, D=13=C+1, E=14=F-1）

### 3. 无符号整数编码 B2U（原书 §2.2.2）※※※
- 原书核心公式（B2U = Binary to Unsigned）：
  ```
  B2U_w(x) = Σ(x_i · 2^i)    for i = 0 to w-1
  ```
- 每一位 x_i 的权重为 2^i，范围：0 ~ 2^w - 1
- **B2U 是双射（bijection）**：每个 w 位模式映射到唯一的无符号整数，且每个无符号整数对应唯一的 w 位模式
- C 语言对应：`unsigned char`(8), `unsigned short`(16), `unsigned int`(32), `unsigned long long`(64)

### 4. 补码编码 B2T（原书 §2.2.3）※※※
- 原书核心公式（B2T = Binary to Two's-Complement）：
  ```
  B2T_w(x) = -x_{w-1} · 2^{w-1} + Σ(x_i · 2^i)    for i = 0 to w-2
  ```
- **核心本质**：最高位（符号位）的权重是 **负的** -2^(w-1)，其余位权重为正。这就是 "two's-complement" 的数学本质。
- B2T 也是双射（bijection），每个 w 位模式映射到唯一的有符号整数
- 补码范围：-2^(w-1) ~ 2^(w-1) - 1，**正负不对称**（负数多一个）
- Java对应类型：byte(8位)、short(16位)、int(32位)、long(64位)，**Java所有整数默认都是补码编码，无原生无符号整数类型**

### 5. 有符号/无符号转换 T2U 与 U2T（原书 §2.2.4）※※※
- **关键事实**：C 语言中强制类型转换（casting）**不改变位模式**，只改变编译器对位模式的解释方式
- 原书公式：
  ```
  T2U_w(x) = x + 2^w    (当 x < 0)
  T2U_w(x) = x          (当 x ≥ 0)
  
  U2T_w(u) = u - 2^w    (当 u > TMax_w，即 u ≥ 2^{w-1})
  U2T_w(u) = u          (当 u ≤ TMax_w)
  ```
- **核心直觉**：补码为负时，T2U 将其映射到无符号范围的上半区（≥ 2^(w-1)）；补码为非负时，两种编码完全相同
- ⚠️ **C 语言陷阱**（原书 §2.2.5）：当有符号和无符号数出现在同一表达式中，C 隐式将**有符号转为无符号**，导致非直觉行为：
  ```c
  int a = -1;
  unsigned int b = 0;
  if (a < b)  // FALSE! -1 被转为 4294967295 > 0
      printf("-1 < 0");
  ```
  Java 规避了此问题（无无符号类型），但在 JNI/C 混合编程时需特别注意。

- 补码特殊值TMin：`-2ⁿ⁻¹`，是唯一绝对值大于自身正数最大值的数，`-TMin = TMin`（溢出导致），是Java中最隐蔽的数值bug之一
- 补码特殊值TMax：`2ⁿ⁻¹-1`，绝对值比TMin小1。对于int类型：`Integer.MIN_VALUE = -2147483648`，`Integer.MAX_VALUE = 2147483647`，`-Integer.MIN_VALUE` 仍为 `Integer.MIN_VALUE`（溢出），而非 `2147483648`
- 补码的非对称性导致取绝对值时要特别小心：
  ```java
  int x = Integer.MIN_VALUE;
  int absX = (x < 0) ? -x : x;  // 结果为 Integer.MIN_VALUE，仍是负数！
  // 正确做法：用 long 暂存或使用 Math.absExact（Java 15+）
### 3. 补码编码核心本质（CSAPP第二章灵魂）
- 核心定义：补码的最高位是**符号位/负权重位**，权重为 -2ⁿ⁻¹，其余位为正权重，权重为2ᵏ
- 计算规则：补码的十进制值 = 符号位负权重 + 其余位正权重之和
- 核心价值：是理解符号扩展、溢出、补码运算的唯一底层根基
- 补码特殊值TMin：`-2ⁿ⁻¹`，是唯一绝对值大于自身正数最大值的数，`-TMin = TMin`（溢出导致），是Java中最隐蔽的数值bug之一
- 补码特殊值TMax：`2ⁿ⁻¹-1`，绝对值比TMin小1。对于int类型：`Integer.MIN_VALUE = -2147483648`，`Integer.MAX_VALUE = 2147483647`，`-Integer.MIN_VALUE` 仍为 `Integer.MIN_VALUE`（溢出），而非 `2147483648`
- 补码的非对称性导致取绝对值时要特别小心：
  ```java
  int x = Integer.MIN_VALUE;
  int absX = (x < 0) ? -x : x;  // 结果为 Integer.MIN_VALUE，仍是负数！
  // 正确做法：用 long 暂存或使用 Math.absExact（Java 15+）
### 6. 符号扩展与零扩展（原书 §2.2.6）※※※
- **符号扩展（Sign Extension）**：将 w 位补码数转为 w+k 位补码数，保持数值不变
- 原书公式：对于 w 位模式的第 w 位（符号位），将其复制到所有新添的高 k 位
  ```
  B2T_{w+k}([x_{w-1},...,x_{w-1}, x_{w-1}, x_{w-2},...,x_0]) = B2T_w([x_{w-1},...,x_0])
  ```
- 数学证明核心（原书 §2.2.6）：两个符号位的权重差 `-2^{w+k-1} + 2^{w+k-2} + ... + 2^w = -2^w`，恰好等于原 w 位符号位权重之变化，所以数值不变
- C 语言隐式转换中 `char→int` 自动执行符号扩展；Java 中 `byte→int` 同样自动符号扩展

### 7. 截断（Truncation）（原书 §2.2.7）※※※
- 将 w 位有符号数截断为 k 位（k < w）：丢弃高位，取低位 k 位
- 原书公式：
  ```
  B2U_k([x_{k-1},...,x_0]) = B2U_w([x_{w-1},...,x_0]) mod 2^k
  B2T_k([x_{k-1},...,x_0]) = U2T_k( B2U_w(x) mod 2^k )
  ```
- 即：先把补码位模式当成无符号数对 2^k 取模，再转回补码
- Java 场景：`byte b = (byte) int_val` 等价于取 int 低 8 位再重新解释为补码

### 8. 位运算核心规则（原书 §2.1.7-2.1.9）
- 补码运算
  - 加法规则：模2ⁿ运算，自动溢出
  - 逆元计算：`-x = ~x + 1`（按位取反+1）
  - 核心特性：模运算下满足封闭性、交换律、结合律，可与位运算无缝结合
- **C 语言位级 vs 逻辑操作**（原书 §2.1.8，关键区分）：
  - `&` `|` `~` `^` → **位级操作**（bit-level）：逐位处理，结果是位向量
  - `&&` `||` `!` → **逻辑操作**（logical）：将非零视为 TRUE、零视为 FALSE，返回 0 或 1
  - ⚠️ 易混淆：`~0x00` → `0xFF`（位级取反），`!0x00` → `0x01`（逻辑非）
  - 逻辑操作的**提前求值特性**（early termination）：`p && *p++` 在 p 为 NULL 时安全（不会解引用）
- 核心位运算（Java开发高频）
  - 按位与`&`：位掩码、权限控制、取低位
  - 按位或`|`：置位、标志位合并
  - 按位非`~`：按位取反，补码逆元计算
  - 按位异或`^`：交换两个数、判断相等、校验位计算
  - 移位运算：`<<` 左移、`>>` 算术右移（保留符号位，补符号位）、`>>>` 逻辑右移（无符号，补0）
  - Java移位坑：移位位数超过类型位宽时，自动取模（int模32，long模64），`int << 32` 等价于 `int << 0`
- 实用位运算技巧（高频场景）
  - **判断奇偶**：`(x & 1) == 1`（比 `x % 2 != 0` 更快）
  - **清除最低位1**：`x & (x - 1)`（可用于统计二进制中1的个数）
  - **获取最低位1**：`x & -x`
  - **异或交换**（无需临时变量）：
    ```java
    a ^= b; b ^= a; a ^= b;  // 注意：a和b不能是同一变量
    ```
  - **位计数（popcount）**：`Integer.bitCount(x)`（底层调用CPU指令 `popcnt`，高效）
  - **取模为2的幂的余数**：`x & (m-1)`，其中m为2的幂，替代 `x % m`（更高效）
  - **Java 关联**：JIT 会将 `x % 8` 自动优化为 `x & 7`，但显式使用位运算可提升可读性（性能无差别）
### 5. 大小端（字节序，CSAPP核心必懂）
- 核心定义：多字节数据在内存中的存储顺序
- 大端序（Big Endian）：高位字节存在低地址，低位字节存在高地址，常用于网络协议、文件格式（又称网络字节序）
- 小端序（Little Endian）：低位字节存在低地址，高位字节存在高地址，x86/x86-64 CPU默认小端序
- Java关联认知：JVM默认大端序（网络字节序），开发中网络IO、二进制文件读写、JNI调用时，必须处理大小端转换，否则会出现数据错乱
- Java 中处理大小端的标准方式：
  - `ByteBuffer` 类：`ByteBuffer.allocate(4).order(ByteOrder.LITTLE_ENDIAN).putInt(0x12345678)`
  - `ByteOrder.nativeOrder()` 获取当前平台的字节序
  - 网络传输时，通常使用 `ByteOrder.BIG_ENDIAN` 并调用 `getInt()` / `putInt()`
  - 避免手动移位转换，容易出错
## ⚙️ 核心层：整数运算（溢出、截断、符号扩展）【对应 2.3 整数运算】

> 原书核心视角：整数运算本质是**模 2^w 运算**（w 位无符号加法）加上**补码解释**。所有溢出、截断现象都可以从模运算严格推导。

### 1. 无符号加法与溢出检测（原书 §2.3.1）※※※
- 原书公式：对于 0 ≤ x, y < 2^w
  ```
  x +^u_w y = x + y              当 x + y < 2^w       （正常）
  x +^u_w y = x + y - 2^w        当 2^w ≤ x + y < 2^{w+1}  （溢出）
  ```
- **溢出检测**：s = x + y（C 语言加法），溢出 ⇔ s < x（等价于 s < y）
- **阿贝尔群（Abelian Group）**：w 位无符号加法构成群 `(Z_{2^w}, +)`
  - 封闭性：任意两个 w 位数的和无符号和仍是 w 位数
  - 加法逆元：`-^u_w x = 2^w - x`（0 ≤ x < 2^w）

### 2. 补码加法与溢出检测（原书 §2.3.2）※※※
- 原书公式：对于 -2^{w-1} ≤ x, y ≤ 2^{w-1} - 1
  ```
  x +^t_w y = x + y - 2^w       当 x + y ≥ 2^{w-1}       （正溢出 → 变成负数）
  x +^t_w y = x + y             当 -2^{w-1} ≤ x+y < 2^{w-1}  （正常）
  x +^t_w y = x + y + 2^w       当 x + y < -2^{w-1}      （负溢出 → 变成正数）
  ```
- **溢出检测**（原书规则）：
  - 正溢出：x > 0, y > 0, 但 sum ≤ 0
  - 负溢出：x < 0, y < 0, 但 sum ≥ 0
- Java中场景：正溢出、负溢出都会静默处理，不会抛出异常
  - 典型场景：`Integer.MAX_VALUE + 1 = Integer.MIN_VALUE`
  - 典型场景：`Long.MAX_VALUE + 1 = Long.MIN_VALUE`
- Java 8+ 提供的溢出检测方法（推荐使用，避免隐蔽bug）：
  - `Math.addExact(int, int)`、`Math.subtractExact`、`Math.multiplyExact`、`Math.negateExact`、`Math.incrementExact`、`Math.decrementExact`
  - 发生溢出时抛出 `ArithmeticException`，便于捕获和处理
  - 性能开销极小，JIT 会内联优化，推荐在关键数值计算中使用

### 3. 补码取反（原书 §2.3.3）
- 对于 x ≠ TMin_w，有 `-^t_w x = -x`（算术取反）
- 对于 x = TMin_w，有 `-^t_w TMin_w = TMin_w`（溢出导致自身→自身，因为 TMin 的正值不在补码表示范围内）
- 两种计算方式：
  - `~x + 1`（按位取反后加1，对 TMin_w 也适用）
  - 从低位向高位：保持所有低位的 0 和最低位的 1 不变，其余高位取反

### 4. 乘法（原书 §2.3.4-2.3.5）※※
- **无符号乘法**：`x *^u_w y = (x · y) mod 2^w`（截取低 w 位）
- **补码乘法**：`x *^t_w y = U2T_w((x · y) mod 2^w)`
  - 原书关键结论：w 位补码乘法的低位结果与无符号乘法**完全相同**（位级等价性）
  - 这意味着同样的乘法硬件可以同时用于有符号和无符号乘法
- **乘以常数优化**（原书 §2.3.6）：编译器将 `x * 14` 优化为 `(x<<4) - (x<<1)`（=16x-2x），因为 shift+add 比乘法指令快
- **除以 2 的幂**（原书 §2.3.7）：
  - 无符号：逻辑右移 `x >> k` 实现 `⌊x / 2^k⌋`
  - 有符号：算术右移对正数正确，对负数需加 bias `(x + (1<<k) - 1) >> k` 才能实现向零舍入（C 语言标准要求）

### 5. 溢出
- 核心本质：运算结果超出了对应类型的补码表示范围，高位被丢弃，模2ⁿ运算后结果不符合预期
- 分类
  - 正溢出：结果超出正数最大值，变成负数
  - 负溢出：结果超出负数最小值，变成正数

### 6. 截断
- 核心本质：高位数据类型转为低位数据类型时，直接丢弃高位字节，仅保留低位字节，补码值重新计算
- 影响：截断后数值会发生变化，需注意精度丢失
- Java场景：`byte b = (byte) int` 自动执行截断，高位直接丢弃，符号位由新的最高位决定
- 截断时的符号位重新计算示例：
  ```java
  int i = 0xFFFF_FF81;  // 二进制：111...10000001
  byte b = (byte) i;     // 结果为 0x81（十进制-127），因为高位全部丢弃，符号位变为1
  ```
### 7. 符号扩展
- 核心本质：短数据类型扩展为长数据类型时，高位补符号位（补码的负权重位）
- 规则：保持数值不变，`byte → short → int → long` 自动执行符号扩展
- 底层逻辑：基于补码的负权重定义，补符号位不会改变原补码的十进制值
- 符号扩展与零扩展的区别：
  - 符号扩展（`>>` 右移或类型提升）：高位补符号位，保持数值不变
  - 零扩展（`>>>` 逻辑右移或转无符号）：高位补0，对于负数会变成很大的正数
  - Java 中 `int` 转 `long` 自动符号扩展，若需要零扩展：`int i = -1; long l = i & 0xFFFFFFFFL;`
### 4. 核心避坑
- 无符号数与补码数的混合运算：C语言中会隐式转换为无符号数，Java无无符号类型，需注意与C/C++交互时的转换坑
- 移位运算的溢出坑：左移超过类型位宽时，Java会自动取模（int模32，long模64），避免无效移位
- 负数的右移坑：
  ```java
  int n = -8;        // 11111111 11111111 11111111 11111000
  int a = n >> 2;    // 算术右移2位，结果 -2（11111111...11111110）
  int b = n >>> 2;   // 逻辑右移2位，结果 1073741822（正数）
  ```
  - 算术右移适合保留符号的除法（但不等价于除以2的幂，因向下取整）
  - 逻辑右移常用于无符号场景，如哈希计算
## 🔮 浮点数层：IEEE 754 标准与精度陷阱【对应 2.4 浮点数】
### 1. 二进制小数基础（原书 §2.4.1）
- 十进制小数：`d_m d_{m-1} ... d_1 d_0 . d_{-1} d_{-2} ... d_{-n}`，每位权重为 10 的对应幂次
- 二进制小数：`b_m ... b_0 . b_{-1} ... b_{-n}`，每位权重为 2 的对应幂次
  ```
  二进制 .1011₂ = 1·2^{-1} + 0·2^{-2} + 1·2^{-3} + 1·2^{-4}
                 = 0.5 + 0 + 0.125 + 0.0625 = 0.6875₁₀
  ```
- **根本限制**（原书 §2.4.1）：有限长度的二进制小数只能精确表示形如 `x/2^k` 的数。像 `0.1₁₀` = `0.0001100110011...₂`（无限循环），这就是 `0.1 + 0.2 ≠ 0.3` 的数学根源。

### 2. IEEE 浮点表示（原书 §2.4.2）※※※
- **V = (-1)^s × M × 2^E** 的三种情况：

| 情况 | 阶码 exp | 尾数 frac | E 的计算 | M 的计算 |
|------|---------|----------|---------|---------|
| **规格化数** | 非全0，非全1 | 任意 | `E = e - Bias`（e 为 exp 的无符号值） | `M = 1 + f`（隐含的 leading 1） |
| **非规格化数** | 全0 | 任意 | `E = 1 - Bias`（特殊设定） | `M = f`（无隐含 leading 1） |
| **特殊值** | 全1 | 取决于 f | — | — |

- **单精度 float（32位）**：1符号位S + 8阶码exp + 23尾数frac
  - Bias = 127（= 2⁷ - 1）
  - 规格化数 E 范围：-126 ~ +127
  - 非规格化数 E = -126（恒定）
- **双精度 double（64位）**：1+11+52，Bias = 1023（= 2¹⁰ - 1）
  - 规格化数 E 范围：-1022 ~ +1023
  - 非规格化数 E = -1022（恒定）

### 3. 为什么阶码用"移码（Biased）"而非补码？（原书隐含的设计原理）※※※
- **核心原因**：使用无符号比较电路即可比较浮点数大小
  - 最小非规格化数（exp=全0, frac=全0...001）的位模式恰好是最小正浮点数
  - 最大规格化数（exp=全1-1, frac=全1）的位模式恰好是最大有限浮点数
  - 若使用补码，负数 exp 的位模式会"看起来"比正数 exp 大，破坏比较硬件
- **特殊值编码**（原书 §2.4.2）：
  - exp=全0, frac=全0 → **±0**（s 决定符号，+0 和 -0 在某些上下文中相等）
  - exp=全0, frac≠全0 → **非规格化数**（gradual underflow）
  - exp=全1, frac=全0 → **±∞**（溢出、除以零的结果）
  - exp=全1, frac≠全0 → **NaN**（非数，如 sqrt(-1)、∞/∞），分 quiet NaN 和 signaling NaN

### 4. 关键数值（原书 Figure 2.32 整理）
| 描述 | float (32-bit) | double (64-bit) |
|------|---------------|-----------------|
| 最小正非规格化数（Δ） | 2^{-149} ≈ 1.4×10^{-45} | 2^{-1074} ≈ 4.9×10^{-324} |
| 最小正规格化数 | 2^{-126} ≈ 1.18×10^{-38} | 2^{-1022} ≈ 2.23×10^{-308} |
| 最大规格化数 | (2 - ε)·2^{127} ≈ 3.40×10^{38} | (2 - ε)·2^{1023} ≈ 1.79×10^{308} |
| 机器精度 ε（1 到下一个浮点数的间距） | 2^{-23} ≈ 1.19×10^{-7} | 2^{-52} ≈ 2.22×10^{-16} |
- `Math.ulp(x)` 返回 x 所在浮点值间距（Unit in the Last Place）

### 5. 非规格化数的设计价值：Gradual Underflow（原书 §2.4.2）
- **问题**：若无非规格化数，最小规格化数（如 float 的 2^{-126}）到 0 之间是"空白"，小于 2^{-126} 的值直接 flush 到 0（突然下溢）
- **解决**：非规格化数在 0 与最小规格化数之间，以**均匀间距**（float 间距 2^{-149}）填充，实现"渐进下溢"
- **代价**：非规格化数计算慢 10~100 倍（CPU 需微码辅助），高性能场景可用 `-XX:+FlushDenormalsToZero` 强制 flush
- 关键数值
  - 最小规格化数：float≈1.18e-38，double≈2.23e-308
  - 最大规格化数：float≈3.40e38，double≈1.79e308
  - 机器精度ε：float≈1.19e-7，double≈2.22e-16
- `Math.ulp(x)` 返回最小精度单位（Unit in the Last Place）
  - `Math.ulp(1.0f)` = 1.1920929E-7
  - 可用于构造合理的比较阈值
### 6. 舍入规则（原书 §2.4.4）※※※
- **IEEE 754 定义了 4 种舍入模式**：

| 舍入模式 | 规则 | 用途 |
|----------|------|------|
| **Round-to-even**（偶舍入）| 中间值（.5）舍入到最低有效位为偶数；非中间值舍入到最接近 | **默认模式**，消除统计偏差 |
| Round-toward-zero（向零舍入）| 截断小数部分 | C/Java `(int)` 强制转换 |
| Round-down（向下舍入）| 向 -∞ 方向舍入 | 区间算术下界 |
| Round-up（向上舍入）| 向 +∞ 方向舍入 | 区间算术上界 |

- **偶舍入示例**（十进制）：
  - 1.4 → 1（舍入到最接近值 1）
  - 1.5 → 2（.5 中间值，最低位 1→2 使最低位为偶数）
  - 2.5 → 2（.5 中间值，2 的 LSB 已是偶数）
  - 1.6 → 2
- **偶舍入示例**（二进制）：
  - `10.01100₂` → `10.0₂`（恰好 .5，向下取使 LSB=0）
  - `10.11100₂` → `11.0₂`（恰好 .5，向上取使 LSB=0）
  - `10.00011₂` → `10.0₂`（距离更近）
- Java 中 `Math.round()` 使用 "round half up"（.5 向正无穷入），非 IEEE 默认偶舍入。`BigDecimal` 可指定 `RoundingMode.HALF_EVEN`。
- 舍入误差：将舍入后的浮点数减原精确值，此误差称为**舍入误差**（rounding error）。在长计算链中，偶舍入倾向于使误差相互抵消，避免系统性累积偏差——这是偶舍入选为默认的根本原因。
- 浮点运算特性
  - 加法不满足结合律：`(a+b)+c ≠ a+(b+c)`
  - 乘法不满足分配律
  - 溢出→±∞，下溢→0或非规格化数
- 非规格化数（次正规数）的性能陷阱
  - 计算比规格化数慢 **10~100倍**
  - Java中可强制刷新为零：`-XX:+FlushDenormalsToZero`（仅高性能且精度不敏感场景）
- NaN的特殊性
  - `Float.NaN != Float.NaN` 永远为 true
  - 正确判断：`Float.isNaN(x)`
### 3. 整数与浮点数转换
- **int → float**：超过2²⁴的int值无法精确表示，出现舍入
- **int → double**：可精确表示所有32位int
- **long → float**：超过2²⁴无法精确
- **long → double**：超过2⁵³无法精确
- **float/double → 整数**：向零舍入，溢出时返回 `Integer.MAX_VALUE/MIN_VALUE`，不抛异常
- 安全转换示例：
  ```java
  double d = 1e20;
  int i = (int) d;  // 结果为 Integer.MAX_VALUE，无异常
  // 推荐使用 Math.toIntExact(long) 做溢出检测
  ```
### 4. Java开发高频坑点
- 浮点数相等判断：绝对不能用 `==`，用差值小于阈值（epsilon）
  ```java
  private static final double EPS = 1e-6;
  if (Math.abs(a - b) < EPS) { ... }
  ```
- 0.1无法精确表示的根源：无限循环二进制小数
- 避免循环累加小浮点数导致误差累积
- 金融计算必须用 `BigDecimal`，构造时使用字符串或 `BigDecimal.valueOf`
- 避免用浮点数做循环判断条件

## 🔗 拓展层【全章知识联动+Java底层映射】
1. **补码与JVM**：Java字节码中的 `iadd`、`isub` 等指令直接对应补码加减；溢出检查方法（`Math.addExact`）由JIT内联后生成条件跳转指令。
2. **浮点数与JVM**：`strictfp` 关键字强制严格遵循IEEE 754，防止平台扩展精度；`Math` 类中的 `sin`/`cos` 等调用底层CPU浮点指令。
3. **字节序与网络编程**：`ByteBuffer` 默认大端序，与网络协议一致；[[A Netty的演进|Netty]] 中的 `ByteBuf` 可配置字节序，底层直接映射到JNI内存操作。
4. **位运算与[[第3章 程序的机器级表示|第3章汇编]]**：所有位运算在x86-64下都有单条指令（`and`、`or`、`xor`、`shl`、`shr`、`sar`），JIT会直接生成；`Integer.bitCount` 映射到 `popcnt` 指令。
5. **溢出与[[第5章：优化程序性能|第5章性能]]**：编译器/ JIT 利用无符号溢出特性做循环归纳变量优化；手动溢出检测会引入额外分支，可能影响指令级并行。

## ❌ 避坑层【全章最易错、最致命要点速查】
1. **`-Integer.MIN_VALUE == Integer.MIN_VALUE`**（取绝对值陷阱）
2. **浮点数不能用 `==`**，必须用 epsilon
3. **移位位数取模**：`1 << 32` 等于 `1 << 0` = 1
4. **`>>` 与 `>>>` 的区别**：负数右移符号扩展 vs 零扩展
5. **`NaN != NaN`**，用 `isNaN()` 判断
6. **`BigDecimal` 必须用字符串构造**，且除法必须指定舍入模式
7. **网络/文件二进制IO必须显式处理字节序**（`ByteBuffer.order()`）
