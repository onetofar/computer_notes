## 📐 Unix I/O 核心模型（原书 §10.1-10.2）※※※
### 1. Unix I/O 统一世界观（原书 §10.1）
- **一切都是文件**（Everything is a file）：普通文件、目录、套接字、管道、设备——对内核来说都是字节序列
- 所有 I/O 操作通过以下统一接口完成：
  1. **打开文件**：`open()` → 返回文件描述符（fd，小非负整数）
  2. **改变文件偏移**：`lseek()` → 设置下次读写位置
  3. **读写文件**：`read()` / `write()` → 从当前偏移开始读写
  4. **关闭文件**：`close()` → 释放 fd 和相关内核数据结构

### 2. 文件类型速查（原书 §10.2）
| 类型 | 描述 | 特点 |
|------|------|------|
| 普通文件（regular） | 任意数据 | 文本文件以换行符 
 结尾 |
| 目录（directory） | 文件名→inode 的映射 | 由内核维护的"表格" |
| 套接字（socket） | 跨网络通信端点 | 不同于普通文件的读写语义 |
| 管道（pipe）| 进程间单向通信 | FIFO，有容量限制 |
| 符号链接（symlink）| 路径别名 | 通过 `readlink()` 读取目标 |
| 设备文件（device）| 物理设备映射 | 字符设备 vs 块设备 |

### 3. Robust I/O (Rio) 包（原书 §10.5）※※※
- **动机**：`read()`/`write()` 的不足值问题（short count）——请求读 100 字节可能只返回 40 字节
- Rio 提供两类函数：
  - **无缓冲的 Rio**：`rio_readn`/`rio_writen`——自动处理不足值，确保传输指定字节数
  - **带缓冲的 Rio**：`rio_readlineb`/`rio_readnb`——内部维护用户态缓冲区，支持按行读取
- 带缓冲 Rio 核心字段：
  ```c
  typedef struct {
      int rio_fd;                // 内部缓冲区对应的文件描述符
      int rio_cnt;               // 缓冲区中未读字节数
      char *rio_bufptr;          // 下一个未读字节的指针
      char rio_buf[RIO_BUFSIZE]; // 内部缓冲区
  } rio_t;
  ```
- Rio 缓冲原理：一次 `read()` 系统调用填满缓冲区（如 8192 字节），后续读取从缓冲区拷贝——**将系统调用开销分摊到多次读取**
- **Java关联**：`BufferedReader`/`BufferedInputStream` 的设计思想与 Rio 的带缓冲 I/O 完全一致

### 4. 文件共享机制（原书 §10.8）※※※
- 内核用三个数据结构管理打开的文件：
  1. **描述符表（Descriptor Table）**：每个进程独有，fd→文件表条目指针
  2. **文件表（File Table）**：全系统共享，每条包含文件位置（`pos`）、引用计数（`refcnt`）、v-node 指针
  3. **v-node 表（v-node Table）**：全系统共享，每条包含文件元数据（大小、权限、inode）
- **`fork()` 后的文件共享**：子进程复制父进程的描述符表（指向同一文件表条目）→ 父子共享文件偏移
- **`dup2(oldfd, newfd)`**：使 newfd 指向 oldfd 的文件表条目（用于 I/O 重定向）

## 🧱 基础层：Unix I/O核心概念与API【对应10.1~10.7】※※※
### 1. 一切皆文件：Unix I/O核心抽象
- 所有I/O设备（磁盘、终端、网络、管道）都抽象为文件
- 统一操作流程：`open` → `read`/`write` → `close`
- 基础API：`open`/`close`/`read`/`write`/`lseek`/`stat`
- **Java关联**：`FileInputStream`/`FileOutputStream`/`FileChannel`底层都调用这些系统调用
### 2. 三层核心数据结构（I/O的底层骨架）※※※
| 数据结构       | 存储位置     | 核心字段                                                     | 作用                     |
| ----------- | ------------ | ------------------------------------------------------------ | ------------------------ |
| **描述符表**   | 每个进程私有 | fd（0/stdin,1/stdout,2/stderr）→ 指向打开文件表项            | 进程级文件引用           |
| **打开文件表** | 内核全局共享 | 文件偏移量`offset`、引用计数`refcnt`、访问权限、指向v-node指针 | 记录一次`open`的会话状态 |
| **v-node表**   | 内核全局共享 | 文件元数据（`struct stat`：大小/权限/inode/类型）            | 描述文件本身属性         |
- **核心规则**：
  - 一个打开文件表项对应一次`open`调用
  - 多个fd可以指向同一个打开文件表项（`dup2`/`fork`）
  - 一个磁盘文件有唯一的v-node表项
### 3. 两类I/O模型
#### 3.1 无缓冲I/O（Unix原生）
- **特点**：直接调用系统调用，无用户态缓冲
- **不足值（short count）**：`read`/`write`返回的字节数可能小于请求值
- **触发场景**：
  - 读时遇到EOF
  - 从终端读（行缓冲，未满一行）
  - 从网络套接字读（数据包未完全到达）
  - 写时磁盘满或信号中断
- **磁盘文件例外**：除EOF外，通常不会产生不足值
#### 3.2 带缓冲I/O（用户态缓冲）
- **标准I/O（stdio）**：C标准库封装（`printf`/`scanf`/`fread`/`fwrite`），提供三种缓冲模式：
  - **全缓冲**：填满缓冲区才刷新（默认磁盘文件）
  - **行缓冲**：遇到换行符刷新（终端）
  - **无缓冲**：立即刷新（stderr）
- **RIO包（CSAPP健壮I/O）**：
  - **无缓冲RIO**：`rio_readn`/`rio_writen`——循环调用`read`/`write`直到传输完n字节
  - **带缓冲RIO**：`rio_t`结构体 + `rio_readinitb` + `rio_read` + `rio_readlineb` + `rio_readnb`
- **Java关联**：`BufferedInputStream`/`BufferedReader`提供类似缓冲机制，减少系统调用
### 4. 文件元数据与目录操作
#### 4.1 文件元数据（`stat`）
- 函数：`stat`/`fstat`/`lstat`
- `struct stat`核心成员：
  - `st_mode`：文件类型+权限（用`S_IS*`宏判断类型）
  - `st_size`：文件大小（字节）
  - `st_ino`：inode号
- **注意**：`S_ISREG`等宏是**预编译文本替换**，不是函数，可直接用于`if`
#### 4.2 目录操作
- `opendir`/`readdir`/`closedir`
- `DIR*`：目录流，类似文件描述符
- `readdir`：返回`struct dirent*`，`d_name`为文件名，`NULL`表示结束

## ⚙️ 原理层：文件共享与重定向【对应10.8~10.9】※※※

### 1. 打开文件表核心状态

#### 1.1 文件偏移量`offset`
- **存储位置**：仅在「打开文件表项」中，不在描述符表或v-node表
- **共享规则**：
  - 多个fd指向同一打开文件表项（`dup2`/`fork`）→ **共享offset，读写同步**
  - 多次`open`同一文件 → **独立打开文件表项，独立offset，互不影响**

#### 1.2 引用计数`refcnt`
- 含义：指向该打开文件表项的fd数量
- 变化规则：
  - 初始`open`：`refcnt=1`
  - `dup2`/`fork`：`refcnt+1`
  - `close(fd)`：`refcnt-1`，当`refcnt=0`时销毁打开文件表项

### 2. 描述符复制与文件共享

#### 2.1 `dup`/`dup2`函数
- 本质：让`newfd`指向`oldfd`对应的同一打开文件表项，`refcnt+1`
- 特性：若`newfd`已打开，先自动`close(newfd)`
- **典型用途**：I/O重定向（shell的`>`）

#### 2.2 `fork`后的文件共享
- 子进程继承父进程的描述符表，所有fd指向同一打开文件表项，`refcnt+1`
- 父子进程**共享offset**，读写同步

#### 2.3 两次`open`同一文件
- 两个独立打开文件表项，独立offset，`refcnt=1`

### 3. I/O重定向底层实现（shell `>` 的本质）

- **流程**：
  1. shell `fork`子进程
  2. 子进程`open`目标文件，获得fd=4
  3. 子进程调用`dup2(4, 1)`，将标准输出fd=1指向同一打开文件表项
  4. 子进程`close(4)`（可选，因`dup2`已增加`refcnt`）
  5. 子进程`exec`执行命令，所有输出（写fd=1）写入文件
- **Java关联**：`ProcessBuilder.redirectOutput(Redirect.to(new File("foo.txt")))`

### 4. 标准I/O与套接字的限制

#### 4.1 全双工流的读写切换限制
- **输出后输入**：必须调用`fflush`/`fseek`/`fsetpos`/`rewind`之一
  - 原因：写缓冲未刷出，内核offset与逻辑offset不同步
- **输入后输出**：必须调用`fseek`/`fsetpos`/`rewind`（`fflush`无效）
  - 原因：读缓冲预读了数据，内核offset已前进，`fflush`只刷新写缓冲

#### 4.2 套接字与标准I/O的矛盾
- 套接字**不支持`lseek`**（流式无边界，不可随机访问）
- 套接字与标准I/O混合使用时，读写切换限制更严格（不能`fseek`）
- **解决方案**：用`fdopen`打开两个独立流（一个读、一个写），避免切换

#### 4.3 Java关联
- Java的`Socket`输入/输出流是独立的，自动避免此问题
- `BufferedReader`/`PrintWriter`底层已处理缓冲

## 💡 思想层：Unix I/O的设计哲学

### 1. 一切皆文件——Unix最伟大的设计
- 统一抽象：普通文件、终端、套接字、管道都使用`open`/`read`/`write`/`close`
- **Java对应**：`Channel`接口统一了`FileChannel`、`SocketChannel`、`DatagramChannel`

### 2. 缓冲的本质——减少系统调用开销
- 系统调用（用户态↔内核态切换）开销大（微秒级）
- 通过用户态缓冲批量读写，大幅减少调用次数
- **Java对应**：`BufferedInputStream`、Netty的`ByteBuf`、Kafka的内存池

### 3. 三层表的隔离与解耦
- 描述符表（进程私有） + 打开文件表（会话状态） + v-node表（文件属性）
- 实现了进程间文件共享、重定向、fork继承的灵活机制

### 4. ✅ 新增：现代异步I/O模型
- **阻塞I/O**：`read`等待数据（传统）
- **非阻塞I/O**：轮询`read`立即返回
- **I/O多路复用**：`select`/`poll`/`epoll`，单线程监控多个fd
- **异步I/O**：`io_uring`（Linux 5.1+），内核完成读写后通知用户态，真正零拷贝
- **Java关联**：Java NIO的`Selector`基于`epoll`（Linux）或`kqueue`（BSD）；Netty 5.x实验性支持`io_uring`

## ❓ 灵魂拷问与高频易错点

### 1. 偏移量的位置（经典课后题）
- **Q**：两次`open`同一文件，分别`read`第一个字符，输出什么？
- **A**：两个独立打开文件表项，独立offset，都读到第一个字符（`c = f`）
- **Q**：`fork`后父子进程写文件，输出叠加还是覆盖？
- **A**：共享offset → 叠加（不会覆盖）

### 2. `refcnt`变化场景
- `open`：`refcnt=1`
- `dup2`/`fork`：`refcnt+1`
- `close`：`refcnt-1`，归零销毁

### 3. 不足值的易错点
- 磁盘文件读：只有EOF时不足值
- 终端/网络：随时可能不足值，必须循环处理
- **RIO包的价值**：自动处理不足值

### 4. 套接字的`lseek`非法
- 原因：流式无边界，无固定偏移量

### 5. 标准I/O读写切换的坑
- 输出后输入：必须`fflush`
- 输入后输出：必须`fseek`（不能用`fflush`）

### 6. 数组 vs 单个变量的`read`
- `char buf[2]; read(fd, buf, 2);` → 两次结果分别存在`buf[0]`和`buf[1]`
- `char c; read(fd, &c, 1);` 再调用一次 → 第二次读覆盖`c`

## 🛠️ 实践层：核心代码与最佳实践

### 1. RIO包核心实现（CSAPP）
```c
// 无缓冲RIO：保证读写n字节
ssize_t rio_readn(int fd, void *usrbuf, size_t n) {
    size_t nleft = n;
    ssize_t nread;
    char *bufp = usrbuf;
    while (nleft > 0) {
        if ((nread = read(fd, bufp, nleft)) < 0) {
            if (errno == EINTR) continue; // 被信号中断，重试
            return -1;
        } else if (nread == 0) break; // EOF
        nleft -= nread;
        bufp += nread;
    }
    return n - nleft;
}

// 带缓冲RIO结构体
#define RIO_BUFSIZE 8192
typedef struct {
    int rio_fd;
    int rio_cnt;
    char *rio_bufptr;
    char rio_buf[RIO_BUFSIZE];
} rio_t;

// 初始化
void rio_readinitb(rio_t *rp, int fd) {
    rp->rio_fd = fd;
    rp->rio_cnt = 0;
    rp->rio_bufptr = rp->rio_buf;
}

// 内部读函数（refill）
static ssize_t rio_read(rio_t *rp, char *usrbuf, size_t n) {
    int cnt;
    while (rp->rio_cnt <= 0) {
        rp->rio_cnt = read(rp->rio_fd, rp->rio_buf, sizeof(rp->rio_buf));
        if (rp->rio_cnt < 0) {
            if (errno != EINTR) return -1;
            continue;
        } else if (rp->rio_cnt == 0) return 0;
        rp->rio_bufptr = rp->rio_buf;
    }
    cnt = (n < rp->rio_cnt) ? n : rp->rio_cnt;
    memcpy(usrbuf, rp->rio_bufptr, cnt);
    rp->rio_bufptr += cnt;
    rp->rio_cnt -= cnt;
    return cnt;
}
```

### 2. `dup2`重定向示例
```c
int fd = open("foo.txt", O_WRONLY | O_CREAT | O_TRUNC, 0644);
dup2(fd, STDOUT_FILENO);
close(fd);
printf("This goes to foo.txt\n");
```

### 3. 生产级最佳实践
- **网络I/O**：必须使用带缓冲RIO或标准I/O，自动处理不足值
- **多进程写同一日志文件**：`open`时加`O_APPEND`标志，每次`write`前自动移动到文件末尾
- **套接字读写**：避免使用标准I/O的同一流进行读写切换，用两个独立流（`fdopen`两次）
- **文件句柄泄漏**：正确`close`所有fd，确保`refcnt`归零
- **性能调优**：大文件读写用`mmap`（零拷贝），小文件用带缓冲I/O

## 🔗 拓展层：现代I/O与Java底层映射

### 1. Linux I/O多路复用
- `select`：fd上限1024，每次遍历全部
- `poll`：无上限，仍要遍历
- `epoll`：事件驱动，只返回就绪fd，O(1)复杂度
- **Java NIO**：`Selector`底层在Linux上使用`epoll`（通过`EPollSelectorProvider`）

### 2. 零拷贝技术
- `sendfile`：内核态直接拷贝文件到socket（省去用户态缓冲）
- `mmap`：文件映射到内存，避免`read`/`write`拷贝
- `splice`/`tee`：管道零拷贝
- **Java**：`FileChannel.transferTo()`使用`sendfile`；`MappedByteBuffer`使用`mmap`

### 3. 异步I/O（io_uring）
- Linux 5.1+引入，解决`epoll`仍需系统调用提交读写的问题
- 提交队列（SQ）和完成队列（CQ）环形缓冲区，批量提交，真正异步
- **Java**：Project Loom的`java.net`新异步I/O可能基于`io_uring`

### 4. 文件锁与并发
- `fcntl`记录锁：支持整个文件或范围锁
- `flock`建议锁：协作式
- **Java**：`FileChannel.lock()`底层调用`fcntl`

## ❌ 避坑层【全章易错点速查】

1. **`read`/`write`可能返回不足值**，必须循环处理（用RIO包或自定义循环）
2. **套接字不支持`lseek`**，不可随机访问
3. **标准I/O读写切换**：输出→输入需`fflush`；输入→输出需`fseek`（`fflush`无效）
4. **两次`open`同一文件**，offset独立，不会互相覆盖
5. **`fork`后父子进程共享offset**，写文件会叠加
6. **`dup2`不会自动关闭`newfd`？** 会先`close(newfd)`（若已打开）
7. **`S_IS*`是宏**，不是函数，但可直接使用
8. **`close`后访问fd**（已关闭但未置-1）可能导致重用fd时误操作
9. **多进程写文件不加`O_APPEND`**，会覆盖对方数据
10. **使用标准I/O处理套接字**，注意读写切换限制，建议用`fdopen`分离流

## 📊 性能对照：系统调用与缓冲

| 操作                    | 开销（约）         | 说明                       |
| ----------------------- | ------------------ | -------------------------- |
| `read` 1字节            | ~1μs               | 系统调用+内核操作          |
| `read` 8192字节         | ~1μs               | 相同系统调用开销，批量数据 |
| `fgetc`（用户态缓冲）   | ~10ns              | 仅用户态内存拷贝           |
| `write` 1字节（无缓冲） | ~1μs               | 系统调用                   |
| `printf`（行缓冲）      | 遇到`\n`才系统调用 | 减少调用次数               |

**核心结论**：用户态缓冲可减少系统调用次数2~3个数量级。

- **句柄泄漏**：`lsof -p pid`查看进程打开的文件描述符
- **Socket stuck**：`strace -p pid`追踪系统调用
- **缓冲未刷新**：检查是否调用`flush()`（Java中`BufferedWriter`等）
- **多进程写日志乱码**：检查是否使用`O_APPEND`

### 4. 核心结论
- **理解Unix I/O三层结构**，就能理解文件共享、重定向、fork继承
- **掌握RIO包设计**，就能写出健壮的网络I/O代码
- **学习Java NIO/Netty**，本质是学习`epoll`+用户态缓冲
- **本章是网络编程、高并发I/O模型的基础**，与第11、12章深度联动
