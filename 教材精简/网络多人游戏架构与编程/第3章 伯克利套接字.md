## 3.1 创建 Socket

**伯克利套接字 API** 最初随 BSD 4.2 发布，提供了进程与 TCP/IP 各层通信的标准方法——此后被移植到每一个主流操作系统和语言，是名副其实的标准。创建：

```c
SOCKET socket(int af, int type, int protocol);
```

三个参数各是一张选择表：

| 参数 | 表 3.1–3.3 的关键取值 | 语义 |
|---|---|---|
| `af`（协议族） | `AF_INET`（IPv4）/ `AF_INET6` / `AF_UNSPEC` | 网络层协议。游戏主力 IPv4，IPv6 值得同时支持 |
| `type`（形式） | `SOCK_STREAM` / `SOCK_DGRAM` / `SOCK_RAW` / `SOCK_SEQPACKET` | STREAM=有状态连接、可靠有序（TCP）；DGRAM=离散报文、最少资源（UDP）；SEQPACKET=STREAM 但须整包读 |
| `protocol` | `IPPROTO_TCP` / `IPPROTO_UDP` / **0=默认** | 被复制进 IP 头的协议字段；0 让 OS 按类型选默认协议 |

惯用组合：`socket(AF_INET, SOCK_DGRAM, 0)` 一行创建 IPv4 UDP socket；`socket(AF_INET, SOCK_STREAM, 0)` 创建 TCP。

**关闭**：`closesocket(SOCKET)`。对 TCP socket,关闭前必须保证全部数据已确认——用 `shutdown(sock, how)` 先停半边：`SD_SEND` 停发（产生 **FIN** 包，数据发完才发，通知对端可安全关闭；对端回一个 FIN 作为响应）→ 收到对端 FIN 后才安全 `closesocket`。**半关闭是顺序，不是可选项**。

> **注释（raw socket）**：type 为 `SOCK_RAW` 且 protocol 为 0 时可以直接写 IP 层与传输层头部——Traceroute 就是这么设 TTL 的；**也是向头部字段塞非法值的唯一方法**（模糊测试服务器的工具，见 [[第10章 安全性|第10章]]）。因为允许非法头部值，多数 OS 只允许高权限程序创建 raw socket。

## 3.2 API 操作系统差异

| 维度 | Windows (Winsock2) | POSIX (Linux/Mac/PS) |
|---|---|---|
| socket 类型 | `SOCKET` = `UINT_PTR` 的 typedef（指向内核中保存 socket 状态的区域） | **`int`**——OS 打开文件/socket 列表的**下标**，可传给多数接受文件描述符的 OS 函数 |
| 头文件 | `WinSock2.h`；地址转换另含 `Ws2tcpip.h` | `sys/socket.h` + `netinet/in.h`（IPv4）+ `arpa/inet.h`（地址转换）+ `netdb.h`（名称解析） |
| 库初始化 | **必须** `WSAStartup(MAKEWORD(2,2))` 成功后才能调任何 Winsock2 函数；`WSACleanup` 关闭——**两者都引用计数，调用次数必须配对** | 默认可用，无需启动 |
| 错误获取 | `WSAGetLastError()`（**线程局部**） | 全局 `errno`（含 `errno.h`） |

三条纪律（原文给出理由）：

1. **头文件冲突**：同一编译单元同时含 `Windows.h` + `WinSock2.h` 会重复声明报错——先含 `WinSock2.h`,或在 Windows.h 前 `#define WIN32_LEAN_AND_MEAN`（预处理将 Windows.h 里的旧 Winsock 忽略）；
2. **错误码立即检查**：两平台的错误值都会被下一次调用覆盖——「在发生错误之后继续调用 socket 函数会因为第一个错误而造成第二个错误，掩盖问题的真正原因」。返回 −1 后**马上**读；
3. **非标准函数隔离**：Winsock2 专有函数以大写开头/WSA 前缀标记——把大写函数与跨平台函数分离，移植 POSIX 时成本最低。

补出的前提：**`int` fd 的深层好处**——fd 能直接喂给 epoll/kqueue 统一等待，「socket 即文件描述符」是整个 IO 多路复用体系的入场券；Windows 的 `SOCKET` 能进 select/WSAPoll 但没有「文件表下标」语义。而 `int` 的明显缺点是**零类型安全**——编译器接受 `socket(5 × 4)` 这种表达式（§3.3.1 封装就是为治它）。

## 3.3 socket 地址

每个网络层数据包要源/目的地址；封装传输层数据还要源/目的端口。API 用 `sockaddr` 传地址：

```c
struct sockaddr {
  uint16_t sa_family;   // 地址类型,须与 socket() 的 af 一致
  char    sa_data[14];  // 真正的地址,通用字节数组
};
```

`sa_data` 必须能装下**任何地址族**的地址格式，所以是哑字节数组。API 为常用族提供了专用类型——**因为 socket API 诞生时没有类与多态，专用类型必须手工强转回 `sockaddr`**：

```c
struct sockaddr_in {          // IPv4 专用
    short    sin_family;      // 与 sa_family 重叠,含义相同
    uint16_t sin_port;        // 16 位端口
    struct  in_addr sin_addr; // 4 字节 IPv4 地址
    char     sin_zero[8];     // 不使用!只为把 sockaddr_in 凑到与 sockaddr 同大,应填全 0
};
```

`in_addr` 跨平台有差异——多数平台的形态是一个 union，既可按 4 字节整数（`S_addr`）写，也可按四个字节（`S_un_b.s_b1..s_b4`）人类可读地写：

```c
struct in_addr { union {
    struct { uint8_t s_b1,s_b2,s_b3,s_b4; } S_un_b;
    struct { uint16_t s_w1,s_w2; } S_un_w;
    uint32_t S_addr;
} S_un; };
```

小窍门（原文）：实例化 BSD socket 结构体一律**先 `memset` 清零**——防止「这个平台用的字段在另一个平台不用」时带垃圾值。平台差异批注：Mac OS X 的 sockaddr 多一个 `sa_len` 字段，要设 `sizeof(sockaddr_in)`。

**字节序**：多字节字段赋值必须主机序→网络序（`htons` 16 位 / `htonl` 32 位），读出反向（`ntohs/ntohl`）。主机序=网络序的平台上这些函数是空操作，优化编译器会把它优化掉——**写不写都必须写**。调试器现象提醒：正确初始化的 `sin_port` 在调试器里显示的是**字节交换后的十进制值**——那是正常的，不是 bug。

清单 3.1 组合示范（65.254.248.180:80）：

```c
sockaddr_in myAddr;
memset(myAddr.sin_zero, 0, sizeof(myAddr.sin_zero));
myAddr.sin_family = AF_INET;
myAddr.sin_port = htons(80);
myAddr.sin_addr.S_un.S_un_b.s_b1 = 65;  // .s_b2=254; .s_b3=248; .s_b4=180;
```

### 3.3.1 类型安全

socket 库建立时几乎没考虑类型安全，应用层封装有双重价值：类型安全 + **把 socket API 从游戏代码中隔离**（将来换网络库只动一层）。清单 3.2 的 `SocketAddress`：

```cpp
class SocketAddress {
public:
    SocketAddress(uint32_t inAddress, uint16_t inPort)
    {
        GetAsSockAddrIn()->sin_family = AF_INET;
        GetAsSockAddrIn()->sin_addr.S_un.S_addr = htonl(inAddress);
        GetAsSockAddrIn()->sin_port = htons(inPort);
    }
    SocketAddress(const sockaddr& inSockAddr)   // 从网络 API 返回的 sockaddr 直接包进来
    { memcpy(&mSockAddr, &inSockAddr, sizeof(sockaddr)); }
    size_t GetSize() const { return sizeof(sockaddr); }
private:
    sockaddr mSockAddr;
    sockaddr_in* GetAsSockAddrIn() { return reinterpret_cast<sockaddr_in*>(&mSockAddr); }
};
typedef shared_ptr<SocketAddress> SocketAddressPtr;
```

两个构造函数各管一个方向：四字节地址+端口（自动设 `AF_INET`）；现成 sockaddr 的收包封装。`shared_ptr` typedef 让共享地址不必操心清理。**收包方向的构造函数是后续所有封装类的粘合剂**——socket 库只会给你裸 `sockaddr`，这一层负责把它变回类型安全的世界。

### 3.3.2 用字符串初始化 sockaddr

地址信息常来自配置文件/命令行字符串。两条路：

**纯 IP 字符串**——`inet_pton`（POSIX）/`InetPton`（Windows）：

```c
int inet_pton(int af, const char* src, void* dst);
// 成功返回 1,源字符串非法返回 0,系统错误返回 -1
sockaddr_in myAddr;
myAddr.sin_family = AF_INET;
myAddr.sin_port = htons(80);
InetPton(AF_INET, "65.254.248.180", &myAddr.sin_addr);
```

**域名**——`inet_pton` 不做域名查找，要 DNS 走 `getaddrinfo`：

```c
int getaddrinfo(const char *hostname, const char *servname,
                const addrinfo *hints, addrinfo **res);
```

- `servname` 可以是 "80" 也可以是服务名 "http"；
- `hints` 设定期望（地址族等），`nullptr` 表示全都要；
- `res` 指向新分配的 **addrinfo 链表**——一个域名可对应多个 IPv4/IPv6 地址，**遍历链表直到找到满足需求的 sockaddr**；`ai_next == nullptr` 是链表尾；
- 用完必须 `freeaddrinfo(res)`——它遍历整条链表释放所有节点。

**性能警告（原文）**：`getaddrinfo` 内部组装 DNS 包、发 UDP/TCP 给 DNS 服务器、等响应——毫秒到**秒级**，**没有内置异步**，会阻塞调用线程。要解析域名，放到**主线程之外的线程**里调（Windows 还可用 `GetAddrInfoEx` 免手工异步）。

清单 3.4 把这套封进 `SocketAddressFactory::CreateIPv4FromString`：按冒号拆 host:service（无冒号默认端口 "0"）、hint 限定 IPv4、遍历链表取第一个非空地址、构造 SocketAddressPtr、释放链表；**出错返回 nullptr**。原文的设计批注：**不用异常也能保证「非空指针即有效地址」**——把错误处理从构造函数挪到工厂。

### 3.3.3 绑定 socket

**绑定（binding）= 通知操作系统这个 socket 将使用特定地址+端口**：

```c
int bind(SOCKET sock, const sockaddr *address, int address_len);
```

`address` 与目的地址无关——它是**发送出去的数据包的源地址**（返回地址）。一台主机可有多个网络接口各配 IP，绑地址是在选接口；多人游戏通常不挑接口——**`sin_addr = INADDR_ANY` 绑定所有接口**。绑定成功返回 0，地址端口被占用返回 −1（可换端口重试，或**端口填 0 让库自动找空闲端口**）。

绑定的两个作用：①传入包的目的地址匹配时，OS 把包交给这个 socket；②为出站包的头部提供源地址+端口。

**自动绑定**：socket 发数据前必须绑定，未绑定时库**自动**绑一个可用端口。所以**手动 bind 的唯一理由是服务器要在公开地址+端口收包**；客户端完全不必绑——发第一个包时源地址源端口自动带上，服务器靠它回包。

## 3.4 UDP Socket

UDP 无状态无连接，**一台主机一对收发只需要一个 socket**。发送：

```c
int sendto(SOCKET sock, const char *buf, int len, int flags,
           const sockaddr *to, int tolen);
```

- `buf` 当成 `void*` 用（原文：它可以是任何能转成 `char*` 的类型）；
- **`len` 的硬约束**：UDP 包最大 65535（头部长度字段 16 位），但**链路层 MTU 才是真上限**——以太网 1500 里还要扣头部与封装。**游戏应避免发送大于 1300 字节的数据包**（防分片）——这个数字就是全书「1300 字节安全载荷」的出处；
- `to` 的地址族必须与 socket 一致；
- **返回值语义**：成功返回待发数据长度——**非零返回不代表发出去了，只代表进了发送队列**。

接收：

```c
int recvfrom(SOCKET sock, char *buf, int len, int flags,
             sockaddr *from, int *fromlen);
```

- 默认无数据时**阻塞**到数据报到达；
- `len` 是缓冲上限——超出部分**直接丢弃**（不报错），缓冲区要按最大包配；
- `flags` 里偶尔有用的 `MSG_PEEK`：偷看数据报但**不删**输入队列——下次可用更大缓冲重读；
- **`from` 参数的常见误用（原文点名）**：它是**输出**参数（写入发送者地址），**不能**用来过滤「只收特定地址的包」——数据报按序交付，每个包的 `from` 被覆盖为各自源地址；
- 成功返回复制进 `buf` 的字节数，错误返回 −1。

### 类型安全的 UDP Socket（清单 3.5/3.6）

```cpp
class UDPSocket {
public:
    ~UDPSocket();                    // 自动 closesocket——RAII 防 socket 泄漏
    int Bind(const SocketAddress& inToAddress);
    int SendTo(const void* inData, int inLen, const SocketAddress& inTo);
    int ReceiveFrom(void* inBuffer, int inLen, SocketAddress& outFrom);
private:
    friend class SocketUtil;         // 工厂才能构造
    UDPSocket(SOCKET inSocket) : mSocket(inSocket) {}
    SOCKET mSocket;
};
typedef shared_ptr<UDPSocket> UDPSocketPtr;
```

三个设计决策，每个都有理由：

1. **友元 + 私有构造**：UDPSocket 必须是 SocketAddress 的友元才能摸它私有的 `sockaddr`——封装外代码无法直接编辑 sockaddr，减少依赖防误用；构造私有 + `SocketUtil::CreateUDPSocket` 工厂（`socket(inFamily, SOCK_DGRAM, IPPROTO_UDP)` 成功才返回对象）——**杜绝「持无效 mSocket 的实例」存在**；
2. **析构即关闭**：RAII 把「忘了 closesocket」从纪律问题变成不可能；
3. **错误统一走 `SocketUtil`**：ReportError/GetLastError 隔离了「Windows 用 WSAGetLastError、POSIX 用 errno」的平台差异，且换错误处理行为只动一处。错误以**负数**返回（`-GetLastError()`）——调用方一个判负就够。

## 3.5 TCP Socket

TCP 可靠、有连接——**socket 本身存储连接状态**，所以**每条保持的 TCP 连接都需要一个单独的 socket**。这是 UDP 与 TCP 在 API 形状上的根本分岔。

### 服务器侧：listen + accept（不对称）

```c
int listen(SOCKET sock, int backlog);       // backlog=等待队列上限,超限丢弃;SOMAXCONN=默认值
SOCKET accept(SOCKET sock, sockaddr* addr, int* addrlen);
```

- **监听 socket 的职责只是「调度者」**：每收到 TCP 三次握手的第一个包就存下请求，直到进程 accept 并继续握手。它**不能**用来和远程主机收发数据——它没连接到任何主机；
- `accept` 成功时**创建并返回一个新 socket**——绑定在监听 socket 的同端口上。OS 靠「源地址+源端口」区分同端口上的多条连接、把包分给正确的 socket。新 socket 存着远程主机地址、负责全部重发跟踪，是**与该主机通信的唯一 socket**；
- `addr` 与 recvfrom 的 `from` 一样是输出参数——**不能筛选接受谁**；
- 默认无连接可接时 `accept` **阻塞**。

### 客户端侧：connect

```c
int connect(SOCKET sock, const sockaddr *addr, int addrlen);
```

发送初始 SYN 启动握手；默认阻塞到被接受或超时。**监听/连接是不对称的**：只有被动方需要监听 socket。

### 3.5.1 流语义的 send/recv

连接的 TCP socket 已存远程地址，收发函数**不再带地址参数**：

```c
int send(SOCKET sock, const char *buf, int len, int flags);
int recv(SOCKET sock, char *buf, int len, int flags);
```

`send` 的**流语义**（与 sendto 的包语义对照）：

- `buf` **不是数据包**——数据进 socket 输出缓冲区，库决定将来怎么切着发（开了 Nagle 会攒到 MSS，[[第7章 延迟、抖动和可靠性|第7章]] §7.4 的 `TCP_NODELAY` 就治它）；
- `len` 不必低于 MTU——缓冲区有空间就收；
- 返回值可能 **< len**（缓冲区只装得下一部分）；缓冲满则阻塞；**非零返回同样只代表入队**。

`recv` 的两个关键语义：

- **读多读少不可预测**——远端库按它认为合适的报文段切着发，单次 recv 得到的数量与远端 send 的信息无关；
- **返回 0 的双重含义**：`len` 非零时返回 0 = 对端发了 FIN（承诺不再有数据）；`len` 为零时返回 0 = 有数据可读——**多 socket 轮询时不占缓冲区探数据的简便手法**（探到后再用真缓冲区再 recv）。
- 默认无数据阻塞。

> **注释（原文）**：连接的 TCP socket 上用 `sendto/recvfrom` 合法——地址参数被忽略（容易困惑）。反过来，UDP socket 上也能 `connect`：把远端地址存进连接数据，此后可用 `send` 不带地址发、**且丢弃来自其他主机的数据报**——并不建立可靠连接，只是地址记账。

### 3.5.2 类型安全的 TCP Socket（清单 3.7）

```cpp
class TCPSocket {
public:
    ~TCPSocket();
    int  Connect(const SocketAddress& inAddress);
    int  Bind(const SocketAddress& inToAddress);
    int  Listen(int inBackLog = 32);
    shared_ptr<TCPSocket> Accept(SocketAddress& inFromAddress);
    int  Send(const void* inData, int inLen);
    int  Receive(void* inBuffer, int inLen);
private:
    friend class SocketUtil;
    TCPSocket(SOCKET inSocket) : mSocket(inSocket) {}
    SOCKET mSocket;
};
```

与 UDPSocket 同款骨架（友元/私有构造/RAII/负数错误），**TCP 特有的形状**：`Accept` 返回 `TCPSocketPtr`（新连接的 socket 同样被 RAII 管理）；`Send/Receive` 不带地址（用连接内存储的）。工厂侧补 `SocketUtil::CreateTCPSocket`（`socket(inFamily, SOCK_STREAM, IPPROTO_TCP)`）。

## 3.6 阻塞和非阻塞 I/O

阻塞 I/O 对游戏是死刑——等一个客户端的 `recv` 卡住整个模拟。三条路：

**① 多线程（§3.6.1）**：每连接一线程。账单：线程随连接数增长、扩展性差；数据汇入要加锁；同一 socket 的收发线程会互相阻塞。原文的态度：「有更简单的方法」。

**② 非阻塞轮询（§3.6.2）**：`SetNonBlockingMode(true)` 后的标准循环（清单 3.9，收包缓冲 1500 = 一个 MTU）：

```cpp
while(gIsGameRunning)
{
    char data[1500];
    SocketAddress socketAddress;
    int bytesReceived = mySock->ReceiveFrom(data, sizeof(data), socketAddress);
    if(bytesReceived > 0)
        ProcessReceivedData(data, bytesReceived, socketAddress);
    DoGameFrame();
}
```

非阻塞语义：无数据时返回 −1，错误码 **`EAGAIN`（POSIX，Linux 上与 EWOULDBLOCK 同值）/ `WSAEWOULDBLOCK`（Windows）——这是正常路径不是错误**。跨平台开关长在封装类里：

```cpp
#if _WIN32
    u_long arg = inShouldBeNonBlocking ? 1 : 0;
    int result = ioctlsocket(mSocket, FIONBIO, &arg);
#else
    int flags = fcntl(mSocket, F_GETFL, 0);          // 先取回现有标志!
    flags = inShouldBeNonBlocking ? (flags | O_NONBLOCK) : (flags & ~O_NONBLOCK);
    int result = fcntl(mSocket, F_SETFL, flags);     // 直接 SETFL(O_NONBLOCK) 会清掉别的标志
#endif
```

**每帧读取上限（§3.6.2 最值钱的一条）**：

> 「限制每帧读取数据报数量很重要。如果不这样做的话，一个恶意的客户端可以发送大量的单字节数据报，发送的速度大于服务器处理的速度，严重阻碍服务器模拟游戏。」

想要多读就循环读**到 min(上限, 读空)** 为止。socket 数量大了轮询变低效 → select。

**③ Select（§3.6.3）**：`select(nfds, readfds, writefds, exceptfds, timeout)` 把一批 fd 交给内核统一等待，返回后逐个检查 `FD_ISSET`。轮询到统一等待，是 IO 多路复用的第一级（上游：游双 [[5-2 IO复用相关技术]] / [[5-2-1 select poll epoll源码分析]]；本册工程化：[[2-2 epoll-Reactor工程纪律|彭放第2章]]）。

**表 3.4（SOL_SOCKET 级）**——游戏相关的六个：

| 选项 | 类型 | 作用与游戏含义 |
|---|---|---|
| `SO_RCVBUF` | int | 接收缓冲区大小。**TCP 带宽受接收窗口限制，而接收窗口不能比它大**——控制它直接影响带宽 |
| `SO_SNDBUF` | int | 发送缓冲区。可靠协议用它存「已发未确认」的数据；满了 `send/sendto` 阻塞 |
| `SO_REUSEADDR` | BOOL | **允许绑定已被占用的 IP:端口**——调试与嗅探程序有用；部分 OS 需要提权。重启服务不被 TIME_WAIT 挡住的前提（[[2-2 epoll-Reactor工程纪律|彭放第2章]]：设完必须查返回值） |
| `SO_KEEPALIVE` | BOOL | 连接协议专属。自动定期发保活包，未被确认则置错误态——**既探测死连接，也顺带刷新 NAT/防火墙表项**（否则可能超时）——与 [[第2章 互联网|第2章]] §2.8 的表项老化直接相关 |
| `SO_RCVTIMEO` / `SO_SNDTIMEO` | DWORD/timeval | 阻塞收/发的超时 |

**表 3.5（IPPROTO_TCP 级）**——只有一条但致命：

| 选项 | 类型 | 作用 |
|---|---|---|
| `TCP_NODELAY` | BOOL | 忽略 Nagle 算法。设 true 换「要求发送→真实发送」的延时降低，代价可能拥塞。**游戏必设**（Nagle 可延迟半秒，[[第7章 延迟、抖动和可靠性|第7章]] §7.4） |

## 章末判据

| 场景 | 动作 |
|---|---|
| 创建 socket | `AF_INET + SOCK_STREAM/DGRAM + 0`；TCP 关闭走 shutdown(SD_SEND)→FIN→等对端 FIN→closesocket |
| 结构体 | 先 memset 清零；多字节字段一律 htons/htonl 进、ntohs/ntohl 出；调试器里端口「看着不对」是正常现象 |
| 域名解析 | getaddrinfo 阻塞秒级——**主线程外调用**；用完 freeaddrinfo |
| 客户端 vs 服务器 | 客户端不 bind（自动绑）；服务器必须 bind 公开地址（INADDR_ANY） |
| UDP | 单 socket 收发；包 ≤1300B 防分片；recvfrom 的 from 不能当过滤器 |
| TCP | 每连接一个 socket；listen 只是调度者；send/recv 是流不是包；recv 返回 0 双义 |
| 防饿死 | 非阻塞 + 每帧读取上限（min(上限,读空)）；EAGAIN/WSAEWOULDBLOCK 是正常路径 |
| socket 选项 | TCP_NODELAY 必设；SO_REUSEADDR 设且查返回值；SO_KEEPALIVE 顺带保 NAT 表项 |

一句话结论：**本章是全书 API 层的地基——socket 三参数选协议形状，bind 决定「谁找得到你」，sendto/recvfrom 的包语义与 send/recv 的流语义分岔出 UDP 与 TCP 的全部使用方式，而类型安全封装（私有构造+工厂+RAII+负数错误）是把这些散装 C 函数驯化成可维护代码的标准姿势。**
