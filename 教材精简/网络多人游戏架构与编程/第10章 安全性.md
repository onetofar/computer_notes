## 网络安全四层 —— 从传输保密到服务器防护

> 原文锚点：第 10 章「安全性」§10.1–§10.4。
> 依赖：限知广播的前提是相关性裁剪（[[第5章 对象复制]] §3）；锁步全量模拟的作弊面见 [[第6章 网络拓扑和游戏案例]]。

### 0 四层防线总览

| 层 | 防什么 | 手段 | 性质 |
|---|---|---|---|
| §10.1 传输保密 | 偷看数据 | 加密（中间人）/ 限知广播（主机嗅探） | 防守 |
| §10.2 输入验证 | 非法操作 | 执行前验证动作合法性 | 防守 |
| §10.3 作弊检测 | 本机作弊软件 | 内存扫描 + 延迟封禁 | **主动** |
| §10.4 服务器防护 | 攻击服务器本身 | DDoS 预案 / 模糊测试 / 常时比较 | 防守 |

### 1 传输保密（§10.1）：两种嗅探，两种答案

**中间人攻击**（路由上的第三方读包）：判定要不要加密的判据是**数据值不值钱**——有微交易/登录账户（钱在后面）→ 必须加密登录与交易数据；只传复制数据 → 不加密无关紧要。要加密就用**公钥系统**（RSA）：客户端用服务器公钥加密登录凭证，只有服务器私钥能解。原文的工程纪律：**自己实现密码系统是资源浪费**，用 OpenSSL 这类经过验证的开源实现。

**主机嗅探**（玩家自己的机器读包）：加密只是**威慑不是防御**——可执行文件里一定藏着解密逻辑，逆向出密钥后密文形同裸奔。能做的是**提高破解成本**：定期换密钥与内存偏移、定期改包格式与顺序，让欺骗工具每次更新都要重新逆向。但底线要认：**永远无法阻止玩家在本机嗅探所有数据**。

真正的答案是**信息作弊**的反面——玩家嗅探是为了拿到不该知道的信息，那就**不把信息发给他**：隐身角色的位置更新干脆不发，客户端从数据包里就学不到。这就是**限知广播**：

> 假设发给每台主机的任何数据都会被作弊玩家检查 ⇒ 只发送与该主机相关的信息 ⇒ 作弊面最小。

这只有权威 C/S 才做得到（服务器按客户端裁剪复制集合，[[第5章 对象复制]] §3）；P2P 锁步全量模拟、人人持有全部状态，战争迷雾只是本机渲染开关——地图黑客（map hack）删掉它毫无技术难度，**且传输数据完全正常、对端无法察觉**。

### 2 输入验证（§10.2）：不信任任何网络操作

原则一句话：**游戏不应盲目执行来自网络数据包的操作**——开火前查有武器、有子弹、不在冷却，任一不满足就拒绝；移动命令必须应用到**该客户端自己的代理**上（C/S：ClientProxy 的归属校验，[[第6章 网络拓扑和游戏案例]]；P2P：命令的 `mPlayerId` 必须匹配被操控单元的主人，`StaticCreate` 与 `ProcessCommand` 双重验证，[[第6章 网络拓扑和游戏案例]]）。

**处置纪律比验证本身更微妙**：检测到非法输入**不要踢人**——无效输入可能是无辜的。原文的沉默例子：玩家 A 被沉默（不能施法），但「你被沉默了」的更新包还在路上，A 在收到前施法 = 非法但无恶意。正解是**保守地拒绝**，把踢人留给确凿的模式。

**反向验证的死角**：客户端无法验证服务器发来的数据（权威服务器持有全部真相，客户端只能信）。唯一安全的解是**不让玩家主持游戏**——开发者或云托管的服务器上这不成问题；玩家托管时想加对等验证（扔球动作同时广播给所有客户端做交叉核验）理论上可行，实际上有两个致命伤：客户端彼此未必可达（NAT/防火墙），且对等包**不保证先于**服务器包到达——等它 = 延迟状态更新，不等 = 回到起点。

### 3 软件作弊检测（§10.3）：主动出击

前三层都是被动的，作弊检测**主动扫描游戏机器**。能抓住的典型：嵌入进程/改写内存的作弊器、自动化 bot（MMO 挂机赚钱、FPS 自瞄）、**地图黑客**（传输层看不出来的那种——只有本机扫描能抓）。

两个工业实现的共同配方：

- **VAC**（Valve，Steamworks）：扫描游戏进程内存找已知作弊程序 + **纯服务器**——连接时与换图时核对客户端文件检验和，不匹配即踢（自定义外观文件进白名单）；
- **Warden**（暴雪）：同样扫内存上报服务器延迟封禁，独门优势是**运行时热更新检测逻辑**——补丁发布时不偷跑作弊的人，会在 Warden 悄悄更新后被抓。

两者共享的关键战术：**禁止波（ban wave）**——检测到作弊**不当场封**，攒名单择日一波带走。当场封 = 告诉作弊者「这条路死了」，帮他们调试；延迟封 = 让作弊程序继续扩散、一次抓出最大批量。以及一个持续军备的现实：**最好的检测平台也会被绕过**，检测系统必须不断更新。

### 4 保护服务器（§10.4）

| 威胁 | 防线 |
|---|---|
| **DDoS** | 洪水淹没连接/算力，让合法用户不可达。自有硬件 = 与 ISP 深度合作（难且贵）；云托管 = 内置分级防护、可购专项服务——**但不能假设云全包**，预案与演练仍要做 |
| **坏数据** | 畸形包让服务器崩溃，或借缓冲区溢出执行恶意代码。解法是**模糊测试**：向服务器灌海量非结构化数据（混入带合法签名的半结构化包效果更好），崩溃即修，迭代多轮 |
| **时序攻击** | 最隐蔽的一个，见下 |

**时序攻击**专门咬「逐字节比较凭证」的代码——包括最 innocuous 的提前返回优化：

```cpp
// 有洞：第一个字节就错 → 立刻返回 → 返回时间泄露「错在第几位」
for (int i = 0; i < 8; ++i)
    if (a[i] != b[i]) return false;

// 常时比较：逐位 XOR 归约，任何错误模式的耗时都相同
unsigned diff = 0;
for (int i = 0; i < 8; ++i) diff |= a[i] ^ b[i];
return diff == 0;
```

攻击者枚举 `b[0]` 的取值、测哪个让比较**耗时更长**，就能逐位确定完整凭证——攻击的是**时间侧信道**，不是算法本身。XOR 归约让「哪里错、错几处」在耗时上不可分辨。**任何协议哈希/签名校验都应该写在这个位置**——它防的不是普通作弊，是拿你的校验当 oracle 的逆向工程。

### 5 判据表

| 决策点 | 判据 |
|---|---|
| 加不加密 | 数据后面有没有钱（交易/账号）；有 → 公钥加密 + 成熟库 |
| 信息泄露 | 根治 = 限知广播（服务器别发）；加密只是提高逆向成本 |
| 非法输入 | 验证归属与前置条件；**拒绝但不踢**（区分恶意与乱序无辜） |
| 作弊检测 | 内存扫描 + 文件校验 + 禁止波；接受军备常态化 |
| 服务器防护 | DDoS 上云但保留预案；模糊测试常态化；比较凭证必用常时比较 |

一句话结论：**安全的总纲是「假设一切可见、验证一切到来」——发出去的数据（限知广播）、收进来的操作（输入验证）、机器上的进程（作弊检测）、服务器本身（DDoS/模糊测试/常时比较）四层各管一段；唯一治本的护城河是权威服务器的限知广播，其余全是提高攻击成本。**
