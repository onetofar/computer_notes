# 第1章 网络编程基础

> **小节地图**:§1.1 单机 vs 网络 / §1.2 IP 地址 / §1.3 TCP/IP / §1.4 阻塞式网络编程(含工程代码与服务端/客户端分析、系统差异、底层函数) / §1.5 非阻塞改造 / §1.6 总结——全章精读。
> 本章是彭放代码线的起点:先写一个阻塞式 echo,再亲手撞到阻塞的墙,引出第 2 章的 Select/Epoll。

## 1.1 单机游戏与网络游戏:同步与异步的分野

单机游戏的本质(图 1-1):**一个无限循环**,每帧三件事——检测输入 → 更新数据与画面 → 捕捉退出请求。循环越快响应越灵敏(原文的算术:一帧 0.5s 时,0.3s 与 0.6s 的两次输入分别在第 2、3 帧才被发现;一帧 0.1s 则几乎即时)。

**关键分野一句话**:单机**不需要异步**——所有操作像函数调用,必有立即返回值;数据在本地内存,读角色、进界面都不需要谁许可。网络游戏同样有循环,**只是多了网络层的处理**——而因为异步,逻辑复杂度陡增:收协议/发协议与主逻辑并行,登录要等对端返回才能进地图(图 1-2/1-3 的流程对比)。

> 这条分野就是全书的存在理由:**异步 = 「结果未到」成为常态 = 一切协议状态机、心跳、超时的根源**。[[第3章 线程、进程以及Actor模型|第3章 §3.4]] 的主循环骨架在本章已现形。

## 1.2 理解 IP 地址

- IP 地址的**本质是 32 位整数**,点分四段只是「每个字节用十进制显示、`.`分隔」的记忆法——所以每段不可能超过 255(一个字节而已);
- IP + 端口 = 一条确定且唯一的通信链路(HTTP 默认 80);
- 32 位不够用 → 128 位的 IPv6,旧 32 位即 IPv4。

## 1.3 理解 TCP/IP

**协议 = 有格式的数据**:A 机的字符串层层包装发到 B 机,B 机按约定格式逐层剥离。真实拓扑不是玩家 A → 玩家 B 的直连,而是**服务器中转模型**(客户端 ↔ 服务端 ↔ 客户端)。

**TCP vs UDP 的选型**,原文用游戏语境一句话定调:

> UDP 允许丢数据,TCP 不允许。看视频卡顿几秒没感觉,但**竞技游戏里少发一个技能可能输掉整场比赛**——游戏数据基于稳定性,本书讲 TCP/IP。

**洋葱模型**(图 1-6):应用层数据被 TCP 头、IP 头、以太网头**逐层包裹**,到达后逐层剥离。TCP/IP 四层(链路/网络/传输/应用)不完全匹配 OSI 七层,每层职责见表 1-1。

> 📖 与格雷泽的对照:[[第2章 互联网|格雷泽第2章 §2.2]] 的五层模型与「层是接口、协议是实现」;本节是同一件事的入门讲法。

## 1.4 阻塞式网络编程:逐 API 的 echo 工程

本章从 §1.4.1 起给出完整工程(服务端 + 客户端),§1.4.2/1.4.3 逐段分析。**API 全族**(§1.4.5 的底层函数说明,骨架):

| 阶段 | 函数 | 要点 |
|---|---|---|
| 建 | `WSAStartup`(Windows) / `socket(AF_INET, SOCK_STREAM, 0)` | Winsock 需显式启动;POSIX 默认可用 |
| 绑 | `bind(sock, sockaddr*, len)` | `sockaddr_in` 先 memset;端口/地址 `htons/htonl` |
| 听 | `listen(sock, backlog)` | 仅服务端;backlog = 等待队列上限 |
| 收连 | `accept(listen_sock, ...)` | **阻塞**到有连接;返回新 socket |
| 连 | `connect(sock, addr, len)` | 仅客户端;**阻塞**到握手完成 |
| 收发 | `send / recv` | 阻塞语义:缓冲满/空就睡 |
| 关 | `closesocket` | TCP 先 shutdown 发 FIN 再关 |

**系统差异**(§1.4.4,与 [[第3章 伯克利套接字|格雷泽第3章 §3.2]] 的速查表同源):`SOCKET` 是 `UINT_PTR` vs `int` 是文件表下标;`WSAStartup/WSACleanup` 引用计数配对;`WSAGetLastError` vs `errno`,**返回 −1 后立即读**(下一次调用覆盖错误码)。

**阻塞的墙在哪**(§1.4.6 小结的教训):echo 工程里 `accept`/`recv`/`send` 任何一个阻塞,整个服务端就停在那一步——单客户端能跑,第二个客户端连上后**谁先阻塞谁卡死全体**。这就是必须走向非阻塞的理由。

## 1.5 非阻塞改造

§1.5 把同一工程改成 `fcntl(O_NONBLOCK)`(Windows: `ioctlsocket(FIONBIO)`)后的轮询版:

- 全部 socket 设非阻塞,`accept/recv/send` 立即返回:没数据返回 −1 且 `errno == EAGAIN/EWOULDBLOCK`(**正常路径**,不是错误);
- 服务端主循环改为:**每帧把所有连接各 recv 一次**的轮询;客户端在 recv 之外照常跑逻辑帧;
- 代价当场可见:连接一多,每帧的空转 recv 就是 O(N) 系统调用浪费——**这正是引出 Select/Epoll 的钩子**(第 2 章)。

原文的改造纪律:非阻塞版本**业务行为与阻塞版完全一致**(同样的 echo),只换 IO 模式——变量隔离,先改 IO 再改逻辑。

> 📖 [[第3章 伯克利套接字|格雷泽第3章 §3.6]]:同一演化的教科书版(阻塞 → 多线程/非阻塞轮询/select 三条路);[[第2章 网络IO多路复用|彭放第2章]]:轮询 → epoll 的工程纪律。

## 1.6 总结

本章给全书画了三个底:①游戏 = 无限循环(每帧三件事);②网络游戏 = 循环 + 异步的网络层;③阻塞 IO 走不通,非阻塞轮询是过渡,IO 多路复用是终点(第 2 章)。

一句话结论:**先让「结果未到」成为一等公民,再谈怎么等——第 1 章负责立起这个意识,第 2 章负责解决它。**
