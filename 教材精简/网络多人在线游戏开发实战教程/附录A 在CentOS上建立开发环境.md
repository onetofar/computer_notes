# 附录A 在CentOS上建立开发环境

> **性质声明**:本附录是**操作手册**(安装器逐屏操作、MobaXterm 配置、编译环境搭建,2437 行里大头是截图转写)——本篇收骨架与要点;逐步操作用时回原文,或直接以现代环境(WSL2/容器)替代。

## 骨架清单

| 环节 | 内容 |
|---|---|
| CentOS 安装 | 存储分区设置(自定义挂载点)、最小化安装建议 |
| 远程终端 | MobaXterm:SSH 会话 + 鼠标/外观配置(Windows 侧的 X11 与终端) |
| 编译环境 | gcc/g++/make 工具链、gdb;书中版本较旧,以当代发行版包管理器为准 |
| 工程准备 | 书中各章 demo 的目录结构与编译方式(bin 目录 + 可执行 + 配置) |

## 用当代环境替代的映射

本书写作时的环境(CentOS 7 + 物理机/虚拟机)在今天的等价物:

| 书中 | 当代等价 | 理由 |
|---|---|---|
| CentOS 7 物理机/虚拟机 | **WSL2 + Linux 容器** | 双环构建([[00-项目领读|00-领读]] L8)——宿主快速迭代,容器保证环境一致 |
| MobaXterm 远程终端 | VS Code Remote-SSH / WSL 直连 | 编辑-调试一体化 |
| 手动 yum 装工具链 | Dockerfile 固化 | 环境可复现、可版本化 |

## 章末判据

| 决策点 | 判据 |
|---|---|
| 环境搭建的投入 | 一次投入固化成脚本/镜像;逐屏手装的操作不进知识库,进 README |
| 教材里的环境章 | 读「它要解决什么」(隔离/工具链/可复现),操作细节以当代方案替代 |

一句话结论:**环境章的永久价值只有一条——开发环境必须可复现;逐屏操作是它的时代残留,用容器化把「可复现」从文档责任变成机器责任。**
