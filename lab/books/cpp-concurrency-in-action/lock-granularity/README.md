# 锁粒度：同一份计数，三种并发策略

> 来源讲义：`C++ Concurrency in Action/Chapter 4. Synchronizing concurrent operations（讲义）.md`

## 对照关系

三个文件做的是**同一件事**（4 线程各加 20000 次），差别只在并发策略：

| 文件 | 策略 | 共享状态 | 锁开销 |
| --- | --- | --- | --- |
| `01-mutex-serial.cpp` | 一把大锁罩全局 | `sum` | 每次加法都抢同一把锁 |
| `02-sharded-no-lock.cpp` | 分片原子累加 | `shards[]` | 无锁，但仍有原子指令 |
| `03-striped-spinlock.cpp` | 分片自旋锁 | `shards[]` | 自旋 + 换出 |

跑起来对比三个 `耗时=... us` 就能看到粒度对并发的实际影响。

## 讨论点

1. `01` 的锁保护范围覆盖了整个累加区间，**临界区越大，串行化越严重**。
2. `02` 把可变状态切成互不相交的片，逻辑上退化成「每个线程只写自己的格子」，
   原子操作在这里只用于保证最终求和时能读到别的线程的写入。
3. `03` 用自旋锁替代阻塞锁：临界区短时自旋更快，长时自旋会烧 CPU。

## 跑法

```bash
bash tools/run_all.sh
```

三个文件都不含数据竞争，ASan/UBSan 干净退出是预期结果。
