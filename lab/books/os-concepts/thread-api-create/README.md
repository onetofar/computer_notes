# 线程 API: 同一个"造线程", POSIX 与 C++ 两套写法

对照问题: 造一个线程、把参数递进去、把结果拿回来, 两套 API 分别怎么做? 差别到底在哪?

| 文件 | 差异点 | 预期输出 |
| --- | --- | --- |
| [01-pthread-create.c](./01-pthread-create.c) | C + POSIX `pthread_create`, 多参数打包成结构体, `void*` 拆包, 结果写回调用者内存 | `[thread 0] base=1 iters=1000 result=1000` … `join 完成: 线程数=4 总和=10000 耗时=… ms` |
| [02-std-thread.cpp](./02-std-thread.cpp) | C++ `std::thread`, 同一份计算, lambda 按引用捕获任务 | 输出逐行与 `01` 完全一致(总和同为 10000), 只有耗时单位内部换算不同 |

两边的**结果值必须一致**(总和 10000) —— 这是对照的基准: API 不同, 语义相同。

## 教材原话

> **pthread_create / pthread_join** —— 造线程、收线程；


—— 《操作系统导论》第 27 章讲义 §27 开篇([[27-第27章 插叙：线程API]])

> C 没有泛型，pthread 要做到"任何函数都能当线程体、任何数据都能传进去"，只能用 `void*` 打天下。惯用法：**多个参数就打包成结构体**，线程函数里强转回来拆包：


—— 《操作系统导论》第 27 章讲义 §27.1「void* 不是玄学，是 C 的万用快递箱」

> ⚠️ 千万别返回指向线程栈的指针

> 线程返回 = 它的栈被回收。你返回的指针指向**一块已经释放的内存**——打印出来"可能碰巧是对的"，然后某天在生产环境变成灵异 bug。要返回值，用 `malloc` 放到堆上（图 27.2 的写法）。


—— 《操作系统导论》第 27 章讲义 §27.2「join 与那个致命的栈」

> 这背后是本章的一条通用规律：**每个线程有自己的栈**。栈上的东西天生线程私有；要跨线程共享，东西必须放堆或全局区。反过来的推论同样成立：只被一个线程用的数据放在栈上，天然安全——这是并发世界里少有的"免费午餐"。


—— 《操作系统导论》第 27 章讲义 §27.2

> 编译就一行：`gcc -o main main.c -Wall -pthread`（头文件 `pthread.h`，链接要 `-pthread`）。


—— 《操作系统导论》第 27 章讲义 §27.5–27.6

> **你写的只是代码，跑出来的顺序是调度程序写的。**


—— 《操作系统导论》第 26 章讲义 §26.1([[26-第26章 并发：介绍]])

## 讨论点

1. 两个文件里**结果都放在堆上**(C 是 `calloc` 出来的结构体, C++ 是 `std::vector`), 照着讲义那句"永远不要返回指向线程栈的指针"办。
2. `01` 用 `pthread_join(p, NULL)` 逐个收; `02` 用 `for (auto &th : ths) th.join();` 收——**join 是"同时派多个、然后逐个收"才有意义**, 单线程直接调用函数更省事。
3. 两个文件的"线程数=4 总和=10000"是同一件事的两种写法, 差异只在 API 表面。
