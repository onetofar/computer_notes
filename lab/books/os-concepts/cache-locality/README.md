# 局部性: 顺序访问 vs 跨步访问

> 对照问题: 同样的元素数、同样的求和, 只改访问顺序, 缓存与 TLB 的命中差多少?

| 文件 | 差异点 | 预期输出 |
| --- | --- | --- |
| [01-sequential.c](./01-sequential.c) | 顺序扫过 32MB 数组 | `顺序访问: 元素数=8388608 校验和=70368766459904 耗时=… ms` |
| [02-strided.c](./02-strided.c) | 1024 条流交错, 相邻访问相隔 4KB, 每次都换一页 | `跨步访问: 元素数=8388608 跨步=1024 int 校验和=70368766459904 耗时=… ms` |

两个文件的**校验和必须完全相同**——访问顺序不影响结果, 只影响时间。在本机实测: 顺序约 1.8ms, 跨步约 41ms(约 23 倍)。

> ⚠️ **口径说明**: 讲义第 41 章讲的是**磁盘局部性**(FFS 怎么摆数据), 不是 CPU 缓存。这一组实验是把讲义那条"相关放一起"的原理**搬到内存访问模式上**(这一步是推演, 不是原文结论); 原文提供的依据是下面引的那几句。

## 讨论点

1. 跨步取 4KB, 是为了让**每次访问都落到新的一页**: 缓存行用不上, TLB 也用不上, 两层都落空。
2. 数组 32MB 是刻意超过常见 L3 的量级, 否则"局部"根本看不出来。
3. 绝对耗时依机器而定(内存带宽、预取器、TLB 页大小都影响), **能对照的是比值和校验和相同这两件事**。
4. 讲义里 FFS 的"摊销"思路同样成立: **定位开销越贵, 就得一次搬越多数据**——局部性本质上是"把昂贵的代价摊薄"。
