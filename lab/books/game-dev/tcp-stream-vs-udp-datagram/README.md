# 一条消息的边界，由谁保证？TCP 字节流 vs UDP 数据报

> 来源讲义：`书籍/教材讲义/网络多人在线游戏开发实战教程/第1章 网络编程基础（讲义）.md` §1.3
> ＋ `第2章 网络IO多路复用（讲义）.md` §2.1.12

同样的 3 条消息（`AAA` / `BBBBB` / `CC`），
在 TCP 上是 10 个字节的连续流，在 UDP 上是 3 个各自独立的报文。
本主题用同一份数据跑三遍，看边界是怎么丢的、又怎么补回来的。

## 对照表

| 文件 | 差异点 | 预期输出 |
| --- | --- | --- |
| `01-tcp-byte-stream.cpp` | TCP 无协议头：客户端一次 `send` 发 10 字节（内含 3 条消息） | 服务端 `[server] recv#1 10 bytes: AAABBBBBCC`；`逻辑消息=3 收到字节=10 recv调用次数=1`——**收到的是字节，不是 3 条消息** |
| `02-tcp-length-header.cpp` | 同样 3 条消息，每条加 2 字节总长度头 | 服务端稳定切出 `切出第1条消息: AAA` / `第2条: BBBBB` / `第3条: CC`，末尾 `共切出 3 条消息`；客户端发出 16 字节（10 字节数据 + 3×2 字节头） |
| `03-udp-datagram.cpp` | UDP：一个消息一个数据报 | `recvfrom 第1个数据报 3 bytes: AAA` / `第2个 5 bytes: BBBBB` / `第3个 2 bytes: CC`——**边界天然保留** |

三份输出放在一起看：**TCP 把 3 条消息压成 10 个字节（边界要自己补），
UDP 把 3 条消息保持成 3 个报文（边界免费，代价是丢了就丢了）。**

## 教材原话

讲义 §1.3 给出本书的选型立场：

> - **TCP**：可靠、长连接，丢包自动重发、自动排序。游戏数据要稳定，所以本书全程用 TCP；
> - **UDP**：快但会丢，适合直播这类"卡几秒无感"的场景。竞技游戏里少发一个技能可能输掉整场，所以不能选它。

—— §1.3

讲义 §1.4 已经提醒过流没有边界：

> recv 的 buf 有长度上限，就算对方发了 2024 字节，你的 buf 只有 1024 就只收 1024。**收到的 1024 字节里可能混着 3 条协议，也可能只是某条协议的一半**——这就是后面要专门处理的粘包、拆包问题（第 2 章 §2.1 的缓冲区设计就是为了它）。

—— §1.4

第 2 章 §2.1.12 把这个现象命名为"粘包"，并给出解药：

> 网络上传的是**连绵不断的二进制**，不是一条条规整的消息：逻辑上发 5 条 10KB，实际可能一次收到 5KB、也可能 15KB——这就是**粘包**。怎么知道一条协议到齐了没有？答案：自己加**协议头**。本书的格式是：
>
> ```
> [ 总长度 2字节 | PacketHead | 协议体 ]
> ```

—— §2.1.12

> 读协议的流程是两次长度判断：
>
> 1. 缓冲区数据 ≥ 2 字节？→ 读出总长度（先读总长而不是先构造 PacketHead 实例，是个小优化：每帧判断时省掉对象构造，100 帧就省 100 个）；
> 2. 缓冲区数据 ≥ 总长度？→ 完整协议到了，整体取出；否则**继续等**——"取完一条后缓冲区还有剩"则必是下一条的开头。

—— §2.1.12

## 跑法

```bash
bash tools/run_all.sh

cd books/game-dev/tcp-stream-vs-udp-datagram
g++ -std=c++20 -O2 -Wall -Wextra -pthread 01-tcp-byte-stream.cpp   -o /tmp/01 && /tmp/01
g++ -std=c++20 -O2 -Wall -Wextra -pthread 02-tcp-length-header.cpp -o /tmp/02 && /tmp/02
g++ -std=c++20 -O2 -Wall -Wextra -pthread 03-udp-datagram.cpp      -o /tmp/03 && /tmp/03
```

**平台说明**：三个文件都走 POSIX socket（`127.0.0.1` 回环，端口临时分配），
非 Linux 平台只打印提示就退出。UDP 服务端按 `recvfrom` 拿到的来源地址 `sendto` 回去
（数据报 socket 没有"默认对端"），客户端与服务端都带 `SO_RCVTIMEO`，
进程有 `alarm(15)` 兜底，不会挂起。
