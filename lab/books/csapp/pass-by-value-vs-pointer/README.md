# 传参方式：传值与传指针，栈帧"按需付费"

> 来源讲义：`书籍/教材讲义/深入理解计算机系统/第3章 程序的机器级表示（讲义）.md` §3.7 / §3.7.1 / §3.7.3 / §3.7.4

机器层面支持过程调用要解决三件事：**传控制**、**传数据**、**分配/释放内存**。
第二件和第三件的代价，都能在"传值 vs 传指针"、以及"参数落在寄存器还是栈上"这两组对照里直接看见。

## 对照表

| 文件 | 差异点 | 预期输出 |
| --- | --- | --- |
| `01-pass-by-value.c` | 64KB 结构体**按值**传，调用者要先在栈上备好一份副本 | 栈帧相差约 64KB（实测 65592 字节）；CPU 时间比 `02` 高；`g_blob.scratch` 仍是 0 |
| `02-pass-by-pointer.c` | 同一个结构体**按指针**传，只传 8 字节地址 | 栈帧只差几十字节（实测 40 字节）；CPU 时间更低；`g_blob.scratch` 累加到 2000 |
| `03-stack-frame-position.c` | 6 个参数 vs 8 个参数：寄存器 vs 栈 | 第 7、8 个参数相隔 8 字节，且在调用者栈帧之上 |

两个文件做的是**同一份求和**（遍历 8192 个 double），校验和完全一致；
唯一的差别是那个 64KB 的结构体是**拷进去**的，还是**指进去**的。

栈帧字节数随 ABI 和编译器而变，上表的实测值取自 `gcc -O2` / x86-64（System V）环境。

## 教材原话

> 原书把这叫**极简主义策略**：**只实现每个具体过程真正需要的那部分机制**。所以你会看到有的函数有完整栈帧、有的函数一个字节的栈帧都不要——**过程调用不是「一律压栈」，而是「按需付费」。**

—— §3.7

> **只有需要栈帧的函数才有栈帧。** 如果所有局部变量都能塞进寄存器、而且函数不再调用别人（这种叫**叶子函数**），它连栈帧都省了。原书前面看的那些例子——`exchange`、`multstore`——一个栈帧都没有。

—— §3.7.1

> 最多 **6 个整型/指针参数**走 `%rdi`、`%rsi`、`%rdx`、`%rcx`、`%r8`、`%r9`，按参数表顺序分配。

—— §3.7.3

> 第 7 个及以后的参数**走栈**（每个都向上取整到 8 字节的倍数）。

—— §3.7.3

> 需要栈上局部存储的三种情况：
> 1. 寄存器不够装下所有局部数据。
> 2. 对局部变量取了地址（`&`），必须能生成它的地址。
> 3. 局部变量是数组或结构体，必须按数组/结构体方式访问。

—— §3.7.4

讲义 §3.7.3 里那个混合类型例子的注释，正好解释了 `03` 打印的 8 字节间距：

> 第 6 行 `movl 8(%rsp), %edx` **读了 4 字节**，但下一行 `addb` **只用低 1 字节**。因为参数是 `char`，但栈上按 8 字节对齐存。

—— §3.7.3

## 跑法

```bash
bash tools/run_all.sh

cd books/csapp/pass-by-value-vs-pointer
gcc -std=c11 -O2 -Wall -Wextra 01-pass-by-value.c   -o /tmp/01 && /tmp/01
gcc -std=c11 -O2 -Wall -Wextra 02-pass-by-pointer.c -o /tmp/02 && /tmp/02
gcc -std=c11 -O2 -Wall -Wextra 03-stack-frame-position.c -o /tmp/03 && /tmp/03
```

**看两个地方**：一是两个 CPU 时间（拷贝的代价），二是两个栈帧地址的差距（拷贝占了多少栈）。
