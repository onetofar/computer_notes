# 进程与线程：创建开销，以及共享变量要不要加锁

> 来源讲义：`书籍/教材讲义/深入理解计算机系统/第12章 并发编程（讲义）.md` §12.1 / §12.1.4 / §12.5 / §12.6

进程和线程都能"同时干两件事"，但代价差得很远；而一旦用线程改同一份内存，
就要回答"这个 `++` 到底算了几次"。

## 对照表

| 文件 | 差异点 | 预期输出 |
| --- | --- | --- |
| `01-fork-vs-thread.c` | 创建 20 个**子进程** vs 20 个 **pthread** | Linux 上 fork 明显更贵（几倍到几十倍）；Windows 上本文件只打印提示 |
| `02-atomic-counter.cpp` | 共享变量用 `std::atomic` 累加 | 计数**永远正确** = 4000000；无锁，但每次加法仍是一条原子指令 |
| `03-mutex-counter.cpp` | 共享变量用 `std::mutex` 保护 | 计数同样正确，但耗时明显高于原子版 |
| `04-racy-counter.cpp` | 共享变量只用 `volatile`（讲义的 badcnt.c） | 计数**小于**理论值，且每次运行都不一样 |

`02`、`03`、`04` 做的是**完全相同的事**（2 或 4 个线程各加一百万次），
差别只在共享变量怎么保护——三份输出可以直接横向对比。

## 教材原话

讲义 §12.1.4 把"进程很慢"拆成三笔账：

> 1. **创建**：`fork` 要复制一份页表、要为子进程分配 PID、要给它准备独立的地址空间。
>    Linux 的 `fork` 用写时复制（copy-on-write）把「真复制」推迟到子进程第一次写入时，但**页表本身还是得复制**。
> 2. **切换**：两个进程之间的上下文切换要换掉整个地址空间——TLB 要刷、寄存器组要换；
>    而线程之间只需要换寄存器和一个栈。
> 3. **通信**：进程之间传一句话，得显式走一次系统调用把数据搬进内核缓冲区，再搬出来；
>    同一个地址空间里两个线程传一句话，就是把几个字节 `memcpy` 一下。
>
> —— §12.1.4

讲义 §12.5 的 `badcnt.c`：

> `volatile long cnt = 0;`
>
> ```c
> void *thread(void *vargp) {
>     long i, niters = *((long *)vargp);
>     for (i = 0; i < niters; i++)
>         cnt++;
>     return NULL;
> }
> ```
>
> —— §12.5.1

> **每次答案都不一样。** 这是本章最值得盯住的现象——它意味着问题不在某一行代码，
> 而在线程执行的**交错顺序**。
>
> —— §12.5.1

> 关键就一条：**L、U、S 三步动了共享变量，H 和 T 没动。**
>
> —— §12.5.2

> **你无法预测操作系统会不会给你一个正确的交错。**
>
> —— §12.5.2

讲义 §12.6 的三个版本与它们的性能：

| 线程数 | 1 | 2 | 4 | 8 | 16 |
|---|---|---|---|---|---|
| `psum-mutex` | 68.00 | 432.00 | 719.00 | 552.00 | 599.00 |
| `psum-array` | 7.26 | 3.64 | 1.91 | 1.85 | 1.84 |
| `psum-local` | 1.06 | 0.54 | 0.28 | 0.29 | 0.30 |

> 原书对第一行的评价是「a nasty surprise」：**加锁版本单线程就已经极慢，并行之后更慢，而且核越多越慢。**
>
> —— §12.6.2

> 原因一句话：**同步操作相对于一次内存更新太贵了。**
>
> —— §12.6.2

> 原书给出的教训：**同步开销很贵，能免就免；免不掉的话，就用尽可能多的有用计算把它摊薄。**
>
> —— §12.6.2

## 跑法

```bash
bash tools/run_all.sh

cd books/csapp/thread-vs-process
g++ -std=c++20 -O2 -Wall -Wextra -pthread 02-atomic-counter.cpp -o /tmp/02 && /tmp/02
g++ -std=c++20 -O2 -Wall -Wextra -pthread 03-mutex-counter.cpp  -o /tmp/03 && /tmp/03
g++ -std=c++20 -O2 -Wall -Wextra -pthread 04-racy-counter.cpp   -o /tmp/04 && /tmp/04
```

**平台说明**：`01` 需要 POSIX 的 `fork`，在 Linux 上才有意义；
Windows 上它会打印一行提示就退出（不假装跑出数字）。

## 关于 `@ub: yes` 的取舍

本目录只有 `04` 是"故意的错误"，但它**没有**标 `@ub: yes`：

- `@ub: yes` 在这个仓库里的含义是"用 valgrind / ASan 能检出"（`tools/check_one.sh --ub` 会去找
  `Invalid read`、`AddressSanitizer` 这类输出）。
- 数据竞争**不是**内存错误：valgrind 和 ASan 都查不出来，要查得用 **ThreadSanitizer**。
- 标上它会让 `bash tools/run_all.sh --ub` 判成"没触发检测"，反而变成一个假失败。

`04` 的未定义行为在文件头用 `// @note:` 标了出来，读代码的人不会错过。
