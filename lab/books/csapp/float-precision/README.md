# 浮点精度：float 与 double，以及为什么浮点不能用 `==` 比较

> 来源讲义：`书籍/教材讲义/深入理解计算机系统/第2章 信息的表示与处理（讲义）.md` §2.4.4 / §2.4.5 / §2.4.6

浮点运算的结果是 **`Round(x ⊙ y)`**——先算精确结果，再舍入到目标格式。
所以"精度"不是一个模糊的形容词，而是**舍入规则 × 位宽**这两件确定的事。

## 教材原话

> C 提供 `float` 和 `double` 两种浮点类型。在支持 IEEE 的机器上，它们对应单精度和双精度，并且**采用就近偶数舍入**。
>
> —— §2.4.6

> IEEE 规定：任何算术运算 `x ⊙ y`（加、乘等）的结果都是 **`Round(x ⊙ y)`**——先算精确结果，再舍入到目标格式。
>
> —— §2.4.5

> **结合律不成立**：`x = (3.14 + 1e10) − 1e10` 得 `0.0`；`3.14 + (1e10 − 1e10)` 得 `3.14`
>
> —— §2.4.5

> 但这**换了一次结合方式，结果可能不同**。多数应用里差异小到无所谓，可编译器**无法知道用户愿意在效率和忠实之间做多少取舍**，
> 于是通常保守——不敢做任何可能影响功能性的浮点优化。
>
> —— §2.4.5

> **就近偶数（round-to-even）**是默认：找最近值……正好在中间时，选择**结果最低有效位是偶数**的那个方向。
> **为什么偏偏要"偶数"？** 如果一律向上舍，一组数据的平均值会**系统性偏高**；一律向下则系统性偏低。
> 就近偶数在大多数现实场景里**避免了这种统计偏差**——它大约一半向上、一半向下。
>
> —— §2.4.4

> 浮点加法**不满足结合律**。（§2.4.5）
>
> —— §5 收尾：本章金句清单
