# 整数溢出：有符号的"未定义"与无符号的"按定义回绕"

> 来源讲义：`书籍/教材讲义/深入理解计算机系统/第2章 信息的表示与处理（讲义）.md` §2.2.5 / §2.2.8 / §2.3

一个数字在机器里不是数学意义上的数，而是**有限位宽的位模式**，运算就是在这套位模式上定义的规则。
同一个"溢出"现象，在有符号数上叫**未定义行为**，在无符号数上叫**按定义取模回绕**——这四个文件就是把这两种语义摆在一起对照。

## 对照表

| 文件 | 差异点 | 预期输出 |
| --- | --- | --- |
| `01-signed-overflow.c` | 四个正数相乘，有符号溢出（未定义行为） | `product = -884901888`，位模式 `0xcb417800` |
| `02-unsigned-wrap.c` | 同一串位按无符号算，溢出是**有定义**的取模 | `UINT_MAX + 1 = 0`；`200*300*400*500 = 3410065408` |
| `03-signed-vs-unsigned-compare.c` | 混合有符号/无符号的比较，谁被隐式转换 | `-1 < 0U` 为假、`(unsigned)-1 > -2` 为真 |
| `04-unsigned-loop-underflow.c` | 循环边界 `i <= length - 1`，length 为 0 时下溢 | 越界读堆内存，需 valgrind/ASan 检出 |

`03` 里有两处故意写成"一边有符号一边无符号"的比较。gcc 的 `-Wsign-compare` 会在那里报警告，
而这正是讲义要讲的隐式转换本身，所以文件内用 `#pragma GCC diagnostic` 就地关掉了这一条
（其余警告照常生效，整个目录 `-Wall -Wextra` 零警告）。

讲义 §2.2.5 给出的求值表，本目录 `03-signed-vs-unsigned-compare.c` 逐条复现：

```
表达式                          类型      求值
-1 < 0                         有符号     1
-1 < 0U                        无符号     0        ← 反直觉
2147483647 > -2147483647-1      有符号     1
2147483647U > -2147483647-1    无符号     0        ← 反直觉
-1 > -2                        有符号     1
(unsigned)-1 > -2              无符号     1        ← 反直觉
```

讲义 §2.2.8 的例一（`04-unsigned-loop-underflow.c` 照抄的结构）：

```c
float sum_elements(float a[], unsigned length) {
    int i;
    float result = 0;
    for (i = 0; i <= length - 1; i++)   /* ← bug */
        result += a[i];
    return result;
}
```

> `length` 是 `unsigned`，`length - 1` 在 `length == 0` 时**下溢成 `UINT_MAX`**，循环条件 `i <= UINT_MAX` 永远成立 → 越界读、崩溃。正确写法是 `i < length`（把比较两端都留在无符号域内）

—— §2.2.8

> 隐式转成无符号的行为"发生在代码里没有任何显式痕迹的地方"，因此特别难查。（§2.2.8）

## 跑法

```bash
bash tools/run_all.sh          # 跳过 04 (标了 @ub: yes)
bash tools/run_all.sh --ub     # 连 04 一起跑, 期望 valgrind 报 Invalid read
```

单独看某个文件：

```bash
cd books/csapp/integer-overflow
gcc -std=c11 -O2 -Wall -Wextra 01-signed-overflow.c -o /tmp/01 && /tmp/01
```

`04-unsigned-loop-underflow.c` 的预期现象是**崩溃或检测器报错**，不是正常输出——
这正是"越界读、崩溃"这句话的现场。检测用 valgrind（免特权）或 ASan：
`KB_LAB_ASAN=1 bash tools/run_all.sh --ub`。

在**没有装检测器**的机器上直接跑这个文件，它会一路越界读下去，直到 20 秒超时被杀掉
——这也是预期现象。装了 valgrind（或 ASan）时，它会在**第一次越界读**上就停下并报错。
