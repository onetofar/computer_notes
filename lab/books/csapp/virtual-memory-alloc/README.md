# malloc 与 mmap：两种分配方式，两种地址

> 来源讲义：`书籍/教材讲义/深入理解计算机系统/第9章 虚拟内存（讲义）.md` §9.8.4 / §9.9 / §9.9.1 / §9.11.9

分配器（`malloc`）和用户级内存映射（`mmap`）都能给你一块内存，
但它们给的**地址长得完全不一样**——这不是实现细节，是两种不同的内存来源。

## 对照表

| 文件 | 差异点 | 预期输出 |
| --- | --- | --- |
| `01-malloc-address.c` | 从堆上分配 | 地址只保证 16 字节对齐；连续两次 `malloc` 紧挨着（同一块堆往前切） |
| `02-mmap-address.c` | 单独映射一片区域 | 地址**页对齐**（4096），且离堆很远；Linux 走 `mmap`，Windows 走 `VirtualAlloc` |
| `03-use-after-free.c` | `free` 之后再读 | 读到的是被覆盖的旧数据——**未定义行为**，需 valgrind/ASan 检出 |

`01` 与 `02` 是同一个问题的两面：**堆上的块是"切"出来的，映射出来的块是"划"出来的**。

## 教材原话

> `malloc` 返回一块**至少 `size` 字节**、且**对齐到足以装下任何类型对象**的内存。

—— §9.9.1

> - **32 位模式（`gcc -m32`）**：返回地址总是 8 的倍数；
> - **64 位模式（默认）**：返回地址总是 16 的倍数。

—— §9.9.1

> **`malloc` 不初始化返回的内存。** 要零初始化用 **`calloc`**（是 malloc 的薄封装，把内存清零）。

—— §9.9.1

> `malloc` 可以通过 `mmap`/`munmap`，也可以通过 **`sbrk`** 来分配/释放堆内存

—— §9.9

讲义 §9.8.4 给出的 `mmap` 签名与参数含义：

> - **`start`**：希望新区域从哪个地址开始。**这只是个建议**，通常传 NULL。

—— §9.8.4

> - **`flags`**：对象类型——**MAP_ANON**（匿名对象，页是 demand-zero）、**MAP_PRIVATE**（私有 COW 对象）、**MAP_SHARED**（共享对象）。

—— §9.8.4

> **删除之后再引用那块区域 → 段错误。**

—— §9.8.4

讲义 §9.11.9 讲的"引用已释放的堆块"，就是 `03` 的原型：

> **注意 `p2` 这个指针仍然指向那块已释放的内存**——应用有责任不再使用它，直到新的 `malloc` 重新初始化它。

—— §9.9.1（图 9.34 的说明）

> **取决于中间那些 malloc/free 的模式**，第 14 行读到的 `x[i]` 可能已经是**某个别的已分配堆块**的一部分，而且**已经被覆盖过了**。

—— §9.11.9

> **`ptr` 必须指向 malloc/calloc/realloc 得到的块的起点**，否则行为未定义。更糟的是 **`free` 没有返回值，所以出问题时应用完全收不到任何提示**

—— §9.9.1

## 跑法

```bash
bash tools/run_all.sh          # 跳过 03 (标了 @ub: yes)
bash tools/run_all.sh --ub     # 连 03 一起跑, 期望 valgrind 报 Invalid read

cd books/csapp/virtual-memory-alloc
gcc -std=c11 -O2 -Wall -Wextra 01-malloc-address.c -o /tmp/01 && /tmp/01
gcc -std=c11 -O2 -Wall -Wextra 02-mmap-address.c   -o /tmp/02 && /tmp/02
```

**平台说明**：`02` 在 Linux 上用 `mmap`，在 Windows 上用 `VirtualAlloc`——
两者给出的都是**页对齐**的新区域，所以"页对齐 + 远离堆"这个观察在两个平台上都成立。
