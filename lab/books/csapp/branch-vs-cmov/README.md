# 条件跳转 vs 条件传送：同一个 C 表达式，两种机器实现

> 来源讲义：`书籍/教材讲义/深入理解计算机系统/第3章 程序的机器级表示（讲义）.md` §3.6.5 / §3.6.6

`if (x < y)` 只有两种翻译方式：**跳过去**，或者**两个都算、按条件选一个**。
前者是控制流，后者是数据流——这个差别就是分支预测要付的钱的来源。

## 对照表

| 文件 | 差异点 | 预期输出 |
| --- | --- | --- |
| `01-absdiff-with-counters.c` | 两条路径各有 `volatile` 计数器的副作用 | `gcc -O2 -S` 里是条件跳转 `jge`，没有 `cmov` |
| `02-absdiff-plain.c` | 同样的 `absdiff`，路径上没有任何副作用 | `gcc -O2 -S` 里是条件传送 `cmov` |
| `03-inspect-asm.sh` | 把上面两个文件的汇编抓出来对照 | 一行表格：谁的 `cmov` 多、谁的条件跳转多 |

## 教材原话

讲义 §3.6.5 给的"用 goto 复刻机器控制流"的写法：

> 原书管这种用 `goto` 复刻机器控制流的 C 代码叫「**goto code**」——平时它是坏风格，但在这里它是**描述机器代码的合适语言**。
>
> —— §3.6.5

讲义 §3.6.5 的 `absdiff_se`（对应本目录 `01`）：

```
absdiff_se:
	cmpq	%rsi, %rdi	Compare x:y
	jge	.L2		If >= goto x_ge_y
	addq	$1,lt_cnt(%rip)	lt_cnt++
	movq	%rsi, %rax
	subq	%rdi, %rax	result = y - x
	ret
.L2:
	addq $1, ge_cnt(%rip)	ge_cnt++
	movq %rdi, %rax
	subq %rsi, %rax		result = x - y
	ret
```

讲义 §3.6.6 的 `absdiff`（对应本目录 `02`）：

```
absdiff:
	movq	%rsi, %rax
	subq	%rdi, %rax	rval = y-x
	movq	%rdi, %rdx
	subq	%rsi, %rdx	eval = x-y
	cmpq	%rsi, %rdi	Compare x:y
	cmovge	%rdx, %rax	If >=, rval = eval
	ret
```

> 还有第二种做法：**条件传送**（conditional move）。不是「跳过去」，而是**两个结果都算出来，然后按条件选一个**。
>
> —— §3.6.6

> **为什么这样更快？** 因为现代处理器是流水的（第 4 章），要保持流水线满载，就得**提前很久**知道下一条指令在哪。
> 遇到条件跳转，它得等条件算出来才知道走哪边——只能**猜**。猜对了没事，猜错了要把已经做的工作扔掉重来，
> 代价大约 **15~30 个时钟周期**。
>
> —— §3.6.6

> 原书在 Intel Haswell 上实测：条件跳转版在分支模式好预测时约 8 周期/次，模式随机时约 17.5 周期/次——
> **分支预测失败率 50% 时，平均多花 19 周期**（`T_MP = 2 × (17.5 − 8) = 19`）。
> 条件传送版**恒定 8 周期**，因为它的控制流跟数据无关，流水线永远不需要猜。
>
> —— §3.6.6

> 代价当然也有：条件传送**两个结果都算了**，如果一边算起来很贵就亏了。而且 `cmov` 只能用于「算式简单」的场景。
>
> —— §3.6.6

## 跑法

```bash
bash tools/run_all.sh

cd books/csapp/branch-vs-cmov
bash 03-inspect-asm.sh          # 直接看汇编对照表
```

`03-inspect-asm.sh` 会自己调 `gcc -O2 -S`（可用 `CC=gcc-12` 之类覆盖），把两个文件生成的汇编抓出来对照，
最后还会把关键指令贴出来。**这是本主题的核心证据** —— C 源码一个字没改，
差别只在于"路径上有没有副作用"，机器码就从"跳转"变成了"传送"。

两个 C 文件本身也能直接跑：它们只是把讲义里那两个函数调用二十万次，
顺便把分支计数打出来。运行结果在两个文件里是同一个 `total`，因为算的是同一件事。
